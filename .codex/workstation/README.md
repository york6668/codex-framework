# Codex 工作站

工作站承载用户委托 Codex 管理、或在授权任务中创建的开发资源，并提供云端配置与本机资源的统一发现入口。框架共享已确认的配置名称、来源、适用范围及发现与维护方法；凭据值、运行状态和业务数据由原有配置渠道或执行环境管理，不随框架复制。

配置与认证默认先使用已有的 Codex 云端配置，确认没有适用配置时，再检查本地已有 SSH、认证工具及配置。各仓库复用本入口，不另建变量、别名或逐仓凭据要求。

| 资源 | 已确认配置与发现线索 |
|---|---|
| Codex 云端 GitHub 配置 | 用户已确认个人保险库存在 `github`，类型为环境变量，适用范围为所有云端环境。沿用该名称；其内容是 Token、SSH 私钥还是其他配置尚未核验，不凭名称假定。 |
| 本地认证 | 云端没有适用配置时，核验当前设备已有 SSH、认证工具和连接配置；通过任务所需的目标操作判断可用性，不输出凭据值。 |
| 数据库与本地数据工具 | 从业务仓库、现有 Compose 标签和设备已有说明定位；`$HOME/docker/mi-local` 是可选线索。读取实际工具的 README，不假定资源已安装。 |
| Java 与 Maven | 仓库 Wrapper、`command -v mvn`、`java -version`、`JAVA_HOME`；macOS 可补充 `/usr/libexec/java_home -V`。依赖仓库读取当前 settings。 |
| 网络 | 操作系统的连接清单和当前路由；macOS 可用 `scutil --nc list`，Linux 使用现有网络管理工具。已有 VPN 不会随框架迁移。 |
| Git 工作区 | 当前仓库和 `git worktree list`；正常 IDEA 目录继续作为本地审核入口。云端使用该任务的检出目录。 |
| 新独立持久资源 | `${CODEX_HOME:-$HOME/.codex}/workstation/`；不为统一路径迁移现有资源。 |

个人保险库的“所有云端环境”是适用范围，只有环境请求的配置才会提供给任务；核对已有键的请求和提供情况，复用原值，不要求重新填写或创建另一个变量。见 [官方个人保险库说明](https://learn.chatgpt.com/docs/environments/cloud-environments#supply-personal-values)。

云端未配置、当前任务无法取得、取得后认证失败是不同事实。已有配置但任务取不到时，说明实际访问缺口；本地进程没有同名变量不能证明云端未配置，也不能据此要求用户重新配置。配置内容和实际访问能力以当次核验为准。

需要设备特有说明时可使用同目录的 `local.md`；若该文件存在，按当前任务需要读取其中的发现线索。该文件不在框架同步范围内。实际资源信息仍以当前可用配置、工具、进程、端口、标签和连接核验，不假定云端能直接读取本机文件或本机能直接读取个人保险库。

专业方法位于当前用户的 `$HOME/.agents/skills/york-workstation`，相关测试与数据方法按 Skill 入口引用读取。持久资源不会随框架更新或任务结束被删除、关闭或重新初始化。未知资源先辨识，服务管理权不等于其中业务数据的处置授权。
