# Codex 工作站

工作站承载用户委托 Codex 管理、或在授权任务中创建的开发资源，并提供云端配置与本机资源的统一发现入口。框架共享已确认的配置名称、来源、适用范围及发现与维护方法；凭据值、运行状态和业务数据由原有配置渠道或执行环境管理，不随框架复制。

配置与认证默认先使用已有的 Codex 云端配置或原生仓库连接；当前入口无法使用时，再检查本机已有 Git/SSH、认证工具及配置。两边均失败则说明实际访问缺口，标记待用户处理，不要求重新提供已配置的凭据。各仓库复用本入口，不另建变量、别名或逐仓凭据要求。

本入口随框架在环境准备时安装，位置以安装说明为准；平台运行时 `CODEX_HOME` 不一定是框架的安装位置。本机新建、恢复或清空任务时按 `york-codex-policy-maintenance/references/framework-sync.md` 检查版本，有变化才兼容应用，再读取已有规范。后续明确规范变更或用户要求时刷新，不为配置发现增加每轮拉取或实时同步。

| 本地认证 | 云端入口在当前任务不可用时，核验当前设备已有 Git/SSH、认证工具和连接配置；通过任务所需的目标操作判断可用性，不输出凭据值。 |

个人保险库的“所有云端环境”是适用范围，只有环境请求的配置才会提供给任务；核对已有键的请求和提供情况，复用原值，不要求重新填写或创建另一个变量。见 [官方个人保险库说明](https://learn.chatgpt.com/docs/environments/cloud-environments#supply-personal-values)。

云端未配置、当前任务无法取得、取得后认证失败是不同事实。已有配置但任务取不到时，说明实际访问缺口；本地进程没有同名变量不能证明云端未配置，也不能据此要求用户重新配置。配置内容和实际访问能力以当次核验为准。

需要本地与云端协作时，按 `york-workstation` 使用可用的原生任务接口发现、读取，并在用户授权下请求云端执行和回读结果。环境存在不代表本地已取得其文件、凭据或执行能力；这项交互按需进行，不承担规范的持续同步。

需要设备特有说明时可使用同目录的 `local.md`；若该文件存在，按当前任务需要读取其中的发现线索。该文件不在框架同步范围内。实际资源信息仍以当前可用配置、工具、进程、端口、标签和连接核验，不假定云端能直接读取本机文件或本机能直接读取个人保险库。

专业方法位于当前用户的 `$HOME/.agents/skills/york-workstation`，相关测试与数据方法按 Skill 入口引用读取。持久资源不会随框架更新或任务结束被删除、关闭或重新初始化。未知资源先辨识，服务管理权不等于其中业务数据的处置授权。
