# Codex 工作站

跨安装目录的方法以 `Skill名/references/...` 标识，按当前宿主的同名 Skill 发现入口定位，再读取该 Skill 内部的相对路径。全局规则从选定框架安装目录读取；不按固定父目录关系推定 Codex home 与 Skills 的位置。

执行节点是模型维护的可重建共享执行资源，以任务完成效率和有效资源利用为优先，承载用户委托 Codex 管理、或在授权任务中创建的工具、服务、实际数据与运行状态。必要停机、替换和停旧重建按实际依赖安排；需保留的内容、用户正常工作软件及外部系统仍按各自边界保护。共享框架由 GitHub `york6668/codex-framework` 持有、维护和发布；具体项目归属和私有来源从本节点既有映射发现；节点上的全局文档、Skills 和本入口都是部署副本。长期框架修订在所属项目检出中开发，发布后刷新节点副本；设备配置、历史记录、业务数据和凭据留在节点或原有配置渠道。

核心框架定义工作站环境与数据生命周期的职责、策略设置、默认行为和预期结果；各台 Mac 或其他节点的数据单元负责选择具体实现并执行。项目环境与配置中心由实际依赖、profile、启动覆盖及动态加载链识别，多环境时沿用当前任务明确选择或请用户确认。读取选定环境发布的服务配置与注册信息，将来源、连接、有效期和核验范围保存本地，再按任务需要准备数据。详见 环境发现与同步（`york-workstation/references/environment-sync.md`）。

上线 SQL 的关联核对、冲突处置、差异计算和验证由工作站在本地完成，再交付最终 SQL；线上执行必要的简单核验与最终写入。复用已有数据和工具，缺少输入时按需只读同步，Docker 是可选实现。发现源数据与目标环境不符时回到本地处理，不转交线上筛选或改写 SQL。详见 上线 SQL 的本地分析与交付（`york-local-data/references/data-sync.md#上线-sql-的本地分析与交付`）。

模型按业务依赖、复现价值、重建成本、源端可获得性和本地独有修改判断数据价值。配置与连接缓存默认有效期为 24 小时，核心数据按用途与恢复能力决定保留、刷新或清理，普通运行数据用途结束后默认直接清理。生效设置与执行结果留在节点，具体见 生命周期策略（`york-workstation/references/resource-lifecycle.md#数据价值与生命周期策略`） 和 按需同步方法（`york-local-data/references/data-sync.md`）。这一缓存期限不改变下述共享框架版本刷新规则。

本入口提供 Codex 云端配置与本机资源的发现方法，共享已确认的配置名称、来源和适用范围。GitHub 项目是框架来源，Codex 云端执行环境是另一执行位置；两者分别核验，访问 GitHub 不要求先启动或联系 Codex 云端任务。

配置与认证先按目标资源、身份用途和已有来源选择；内部维护先核对其既有受管会话或不透明提供方，外部业务或测试身份保持原用途、只读和入口限制，分流见认证与操作能力（`york-workstation/references/environment-sync.md#入口、认证与操作能力`）。GitHub/仓库访问先用已有 Codex 配置或原生仓库连接；当前入口无法使用时，再检查本机已有 Git/SSH、认证工具及配置。两边均失败则说明实际访问缺口，标记待用户处理，不要求重新提供已配置的凭据。各仓库复用本入口，不另建变量、别名或逐仓凭据要求。

上述原则同样约束生成或维护脚本、CI 和部署流程：不得将未确认存在的 secret 或变量写成强制依赖，再要求用户补配。已有流程因此失败时，先核对执行环境并修正认证路径；确需新增认证才说明必要权限及现有授权无法覆盖的依据，具体方法见 `york-workstation`。

Codex 原生连接、本机进程、Codex 云端执行环境和 GitHub Actions 的权限分别确认，不自动互相继承。只将认证失败归属于实际失败的操作和环境，不把可选 CI 缺口扩大为整个任务受阻，也不把其他路径验证通过当成 CI 成功。

本入口随框架在环境准备时安装，位置以安装说明为准；平台运行时 `CODEX_HOME` 不一定是框架的安装位置。本机新建、恢复或清空任务时按 `york-codex-policy-maintenance/references/framework-sync.md` 检查 GitHub 发布版本，补齐缺少内容、兼容更新变化，再读取规范并使用节点实际资源执行需求。后续只在明确已发布的变更、当前任务完成长期规范发布或用户要求时刷新，不为配置发现增加每轮拉取或实时同步。来源不可用时保留最后有效版本、节点数据和未发布修改，继续无依赖工作。

| 执行环境与项目来源 | 从当前任务实际可用环境和节点配置核对项目、仓库、分支及绑定；真实映射由工作站持有，框架只提供通用安装和使用方法。 |

使用原生配置提供方时，分别核对已有配置的适用范围、当前环境请求及实际提供情况，复用已有配置，不据某个节点的键名要求其他机器重复填写或新增变量。见 [官方个人保险库说明](https://learn.chatgpt.com/docs/environments/cloud-environments#supply-personal-values)。

Codex 云端未配置、当前任务无法取得、取得后认证失败是不同事实。已有配置但任务取不到时，说明实际访问缺口；本地进程没有同名变量不能证明 Codex 云端未配置，也不能据此要求用户重新配置。配置内容和实际访问能力以当次核验为准。

需要 执行节点 与 Codex 云端执行环境协作时，按 `york-workstation` 使用可用的原生任务接口发现、读取，并在用户授权下请求远端执行和回读结果。环境存在不代表本地已取得其文件、凭据或执行能力；这项交互按需进行，不承担规范的持续同步。

需要设备特有说明时可使用同目录的 `local.md`；若该文件存在，按当前任务需要读取其中的发现线索。该文件不在框架同步范围内，不能用来另建长期框架规范。部署副本上的框架差异按未发布修改保护并归回所属 GitHub 项目。实际资源信息仍以当前可用配置、工具、进程、端口、标签和连接核验，不假定 Codex 云端执行环境能直接读取本机文件或本机能直接读取个人保险库。

专业方法按当前宿主的 `york-workstation` Skill 发现入口定位，相关测试与数据方法按 Skill 内部引用读取。持久工具与服务不因框架更新或任务结束自动清除；按需停旧、替换和重建依资源角色及生命周期策略执行，跨任务保留不要求旧实例持续运行。未知资源先辨识，服务管理权不等于其中业务数据的处置授权。

工作站异常与可溯源性沿用原生任务/工具记录和节点已有状态，模型在相关任务入口核对新鲜度、身份、采用版本及资源实际退出；失效观察不视为正常。只读 `codex-framework workstation-check` 和完整判断边界见 `york-workstation/references/observability.md`。本入口不启用后台采集或通知。

已安装并获信任的 `SessionStart` Hook 可在任务启动或恢复时按需读取本节点的 `observation-sources.json` 并向模型注入有界摘要；摘要缺席时可只读运行 `codex-framework workstation-entry` 直读同一固定清单，清单缺失保持未知，不递归枚举工作站。节点状态值映射留在该文件，核心不带项目专用状态。Hook 缺席、未获信任或没有模型执行机会时不能声称已感知，任务空闲时不提供即时唤醒。

核心 0.3.1 的同一入口可读取节点明确选择的 `asset-facts-v1` 来源，保留独立的版本阶段、活动故障及局部历史诊断。共享源码的可选 `adapters/file-metadata/asset_facts.py` 只生成普通文件元数据，不随核心运行包自动安装或执行；节点选择文件、来源清单和观察输出继续由原节点维护。运行健康、实际加载和有限范围完成各需适用的真实证据，不能由版本字段或历史注记代签。

## 节点项目与配置发现

项目相关工作先按当前实际框架安装目录读取 `workstation/local.md` 的对应条目；路径相对该安装目录，不从另一机器的用户名、home 或 Skills 父目录猜测。该文件承载节点的真实项目归属、仓库与方法映射、具体地址和本机维护线索；具体维护及迁移由助手与工作站按原任务持久入口推进，核心不持有项目清单或节点实施细则。

文件不存在、为空或没有当前项目条目时，明确“当前节点未配置该项目映射”，核对原项目已获准的现有入口；仍无法确定时只保留依赖它的动作，继续其他工作，不把示例当默认配置。已有配置仍核来源和当前可用性；本文和节点文件均不扩大授权。

初始化、恢复或修正缺项时，由模型从当前有效用户要求、原项目规范和实际仓库/工具补齐所需映射：项目归属及仓库、开发基线的权威来源、专用方法入口、具体资源位置与操作来源。优先引用已有正文和配置，保护节点已有内容；无需统一目录、schema 或另建项目总表，日常任务也不重复初始化。项目基线不是交付目标授权，节点路径不是跨机器默认值。

对迁出共享框架的有效要求，先建立真实承接并从正常入口核对可发现、可执行，再退出框架中的专用副本。历史实现先审视当前必要性，可复用原项目/本机工具或删除失效机制，不为保留它强建参数化适配层。机器绑定留在既有配置，通用程序确需参数时由初始化解析实际值；模型参考文档不是运行时配置，缺变量或旧路径不能促使猜值、复制秘密或另建认证渠道。
