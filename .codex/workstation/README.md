# Codex 工作站

Mac mini 是具体的数据存储与执行节点，承载用户委托 Codex 管理、或在授权任务中创建的工具、服务、实际数据与运行状态。共享框架由 GitHub `york6668/codex-framework` 持有、维护和发布，BTC 专属方法归 `york6668/btc-core-strategy`；节点上的全局文档、Skills 和本入口都是部署副本。长期框架修订在所属项目检出中开发，发布后刷新节点副本；设备配置、历史记录、业务数据和凭据留在节点或原有配置渠道。

核心框架定义工作站环境与数据生命周期的职责、策略设置、默认行为和预期结果；各台 Mac 或其他节点的数据单元负责选择具体实现并执行。项目环境与配置中心由实际依赖、profile、启动覆盖及动态加载链识别，多环境时沿用当前任务明确选择或请用户确认。读取选定环境发布的服务配置与注册信息，将来源、连接、有效期和核验范围保存本地，再按任务需要准备数据。详见 [环境发现与同步](../../.agents/skills/york-workstation/references/environment-sync.md)。

上线 SQL 的关联核对、冲突处置、差异计算和验证由工作站在本地完成，再交付最终 SQL；线上执行必要的简单核验与最终写入。复用已有数据和工具，缺少输入时按需只读同步，Docker 是可选实现。发现源数据与目标环境不符时回到本地处理，不转交线上筛选或改写 SQL。详见 [上线 SQL 的本地分析与交付](../../.agents/skills/york-local-data/references/data-sync.md#上线-sql-的本地分析与交付)。

模型按业务依赖、复现价值、重建成本、源端可获得性和本地独有修改判断数据价值。配置与连接缓存默认有效期为 24 小时，核心数据按用途与恢复能力决定保留、刷新或清理，普通运行数据用途结束后默认直接清理。生效设置与执行结果留在节点，具体见 [生命周期策略](../../.agents/skills/york-workstation/references/resource-lifecycle.md#数据价值与生命周期策略) 和 [按需同步方法](../../.agents/skills/york-local-data/references/data-sync.md)。这一缓存期限不改变下述共享框架版本刷新规则。

本入口提供 Codex 云端配置与本机资源的发现方法，共享已确认的配置名称、来源和适用范围。GitHub 项目是框架来源，Codex 云端执行环境是另一执行位置；两者分别核验，访问 GitHub 不要求先启动或联系 Codex 云端任务。

配置与认证默认先使用已有的 Codex 云端配置或原生仓库连接；当前入口无法使用时，再检查本机已有 Git/SSH、认证工具及配置。两边均失败则说明实际访问缺口，标记待用户处理，不要求重新提供已配置的凭据。各仓库复用本入口，不另建变量、别名或逐仓凭据要求。

上述原则同样约束生成或维护脚本、CI 和部署流程：不得将未确认存在的 secret 或变量写成强制依赖，再要求用户补配。已有流程因此失败时，先核对执行环境并修正认证路径；确需新增认证才说明必要权限及现有授权无法覆盖的依据，具体方法见 `york-workstation`。

Codex 原生连接、本机进程、Codex 云端执行环境和 GitHub Actions 的权限分别确认，不自动互相继承。只将认证失败归属于实际失败的操作和环境，不把可选 CI 缺口扩大为整个任务受阻，也不把其他路径验证通过当成 CI 成功。

本入口随框架在环境准备时安装，位置以安装说明为准；平台运行时 `CODEX_HOME` 不一定是框架的安装位置。本机新建、恢复或清空任务时按 `york-codex-policy-maintenance/references/framework-sync.md` 检查 GitHub 发布版本，补齐缺少内容、兼容更新变化，再读取规范并使用节点实际资源执行需求。后续只在明确已发布的变更、当前任务完成长期规范发布或用户要求时刷新，不为配置发现增加每轮拉取或实时同步。来源不可用时保留最后有效版本、节点数据和未发布修改，继续无依赖工作。

个人保险库的“所有云端环境”是适用范围，只有环境请求的配置才会提供给任务；核对已有键的请求和提供情况，复用原值，不要求重新填写或创建另一个变量。见 [官方个人保险库说明](https://learn.chatgpt.com/docs/environments/cloud-environments#supply-personal-values)。

Codex 云端未配置、当前任务无法取得、取得后认证失败是不同事实。已有配置但任务取不到时，说明实际访问缺口；本地进程没有同名变量不能证明 Codex 云端未配置，也不能据此要求用户重新配置。配置内容和实际访问能力以当次核验为准。

需要 Mac mini 与 Codex 云端执行环境协作时，按 `york-workstation` 使用可用的原生任务接口发现、读取，并在用户授权下请求远端执行和回读结果。环境存在不代表本地已取得其文件、凭据或执行能力；这项交互按需进行，不承担规范的持续同步。

需要设备特有说明时可使用同目录的 `local.md`；若该文件存在，按当前任务需要读取其中的发现线索。该文件不在框架同步范围内，不能用来另建长期框架规范。部署副本上的框架差异按未发布修改保护并归回所属 GitHub 项目。实际资源信息仍以当前可用配置、工具、进程、端口、标签和连接核验，不假定 Codex 云端执行环境能直接读取本机文件或本机能直接读取个人保险库。

专业方法位于当前用户的 `$HOME/.agents/skills/york-workstation`，相关测试与数据方法按 Skill 入口引用读取。持久工具与服务不会随框架更新或任务结束被删除、关闭或重新初始化；其中数据按生命周期策略处理。未知资源先辨识，服务管理权不等于其中业务数据的处置授权。

工作站异常与可溯源性沿用原生任务/工具记录和节点已有状态，模型在相关任务入口核对新鲜度、身份、采用版本及资源实际退出；失效观察不视为正常。只读 `codex-framework workstation-check` 和完整判断边界见 `york-workstation/references/observability.md`。本入口不启用后台采集或通知。

现有 `SessionStart` Hook 在任务启动或恢复时按需读取本节点的 `observation-sources.json` 并向模型注入有界摘要；节点状态值映射留在该文件，核心不带项目专用状态。Hook 缺席、未获信任或没有模型执行机会时不能声称已感知，任务空闲时不提供即时唤醒。
