# 记忆使用方法

本说明及共享偏好、专业方法由 GitHub `york6668/codex-framework` 维护和发布；执行节点上的说明是部署副本。各节点独立保存历史记忆，记忆数据与方法源码分开管理。读取本地记忆不会将它上传到本仓。

- 优先遵循当前用户要求和现行 `AGENTS.md`。历史记忆用于找到已有决定、资料和线索，不把旧状态作为执行权限或业务事实。
- 当前问题依赖先前决定、项目约定或历史结果时，先从客户端提供的记忆摘要与索引定向查找，再按引用读取必要的来源。自包含的简单问题不必查记忆。
- 采用历史结论决定当前实施、兼容、数据处理或范围时，核对其主体、条件与时效；需要当前事实的判断回到现行代码、配置或实际结果。尚未核验的历史信息仅用于定位资料和待验证问题，标注来源与时效不使其成为决定依据。已确认且仍适用的契约直接复用，不因读取了历史就重复调查；查不到记录保持未知，不推定事情未发生。
- 优先使用客户端提供的记忆位置。默认发现入口为 `${CODEX_HOME:-$HOME/.codex}/memories`；不同版本可能使用其他目录，按客户端实际注入的信息处理。不存在记忆时继续当前工作，不创建虚假的历史或复制其他设备的数据。
- 原生记忆由客户端生成和管理；用户要求补充或纠正时，优先使用该客户端支持的入口。本机文件记忆允许的人工补充放在客户端指定的 notes 位置，不手工覆盖生成的索引与摘要。记忆中不保存凭据。
- Codex 云端执行环境可安装本 GitHub 项目的规则和 Skills。是否支持原生记忆、何时生成记忆，由目标客户端决定；安装本框架不代表该执行环境获得了其他节点的历史记忆。

可选配置在 [memory-settings.example.toml](memory-settings.example.toml)，不表示当前设备已经启用；同步工具仅分发这个文件，**不会改写 `config.toml` 或自动开启记忆**。在新设备上使用原生「个性化 → 记忆」或该客户端支持的配置入口，保留设备已有选择。

官方说明：[Memories](https://learn.chatgpt.com/docs/customization/memories)。
