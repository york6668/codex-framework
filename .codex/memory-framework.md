# 记忆使用方法

本说明及共享偏好、专业方法由 GitHub `york6668/codex-framework` 维护和发布；执行节点上的说明是部署副本。各节点独立保存历史记忆，记忆数据与方法源码分开管理。读取本地记忆不会将它上传到本仓。

## 依据、记忆与执行状态

有效用户要求、适用规范与已确认契约决定应完成什么及允许影响什么；记忆帮助找回相关上下文；执行状态说明当前依赖、在途效果和限制。内容被保存、压缩、摘要、重复引用或验证通过，不增加权威、适用范围或执行效力。这三个维度贯穿同一工作主线，不按存储位置或保存时长相互推导，也不建立第二套任务或规范平台。

会话和任务记忆承接本项工作的输入、判断、进度与结果，其内容可以跨多轮持久保存；长期记忆支持跨会话发现上下文，仍保留所属项目、来源和观察条件。长期记忆不等于长期规范，任务材料也不因跨轮保存成为公共材料。具体材料按项目用途、真实消费者、恢复需要和授权清理或归档；归档不扩大适用性。模型默认的长期价值判断只用于规范的保留、合并和删冗，不因“可能有用”将具体材料提升为持久线索、契约或后继义务。

## 形成、召回与纠正

- 从当前有效要求和职责选择必要上下文；依赖先前决定、项目约定或结果时，先复用客户端摘要和原项目入口，再按引用读取必要来源。简单自包含问题不查历史；不将旧任务、目录或轮次当作当前职责存在的前提。
- 摘要、结果整理、交接和人工记忆补充分别表达用户要求、已观察事实、模型解释与建议，保留来源、所属对象及影响判断的条件。重复转述不将模型解释升级为用户要求；假设、局部观察和验证结果不生成新的业务义务。已有引用及适用字段足够就复用，不给普通任务增加登记要求。
- 采用历史结论影响当前范围、实施、兼容或数据处置时，核对原依据是否仍适用；依赖当前事实的判断回到现行代码、配置或真实结果。资料不足时只定位待核问题，不先形成依赖或阻断。已有充分适用证据直接复用；查不到历史不推定事情未发生。
- 当前职责沿有效要求承接。旧任务身份只在定位证据、去重、在途效果、拒绝或 UNKNOWN 等真实需要中保留；完成、替代或归档的历史步骤退出活动入口。旧载体失效只限制依赖其中事实的动作，不消除职责，也不要求恢复旧任务才能工作。
- 用户纠正后修正原权威和依赖错误前提的活动结论。原始历史保持原观察，生成的记忆通过客户端支持的纠正入口处理；后续实际召回与决策分别验证，不将提交纠正或文件更新称为原生后台已完成合并。

## 原生能力与存储

- 优先使用客户端提供的记忆位置。默认发现入口为 `${CODEX_HOME:-$HOME/.codex}/memories`；不同版本可能使用其他目录，按客户端实际注入的信息处理。不存在记忆时继续当前工作，不创建虚假的历史或复制其他设备的数据。
- 原生记忆由客户端生成和管理；用户要求补充或纠正时，优先使用该客户端支持的入口。本机文件记忆允许的人工补充放在客户端指定的 notes 位置，不手工覆盖生成的索引与摘要。记忆中不保存凭据。
- 原生自动提取和合并属于宿主能力。只使用当前客户端实际支持的配置和入口；没有可验证的语义过滤接口时，不声称已在生成侧阻止某类内容。自动生成的记忆按上述来源与适用性使用，不能作为规范发布或任务状态的唯一渠道。
- Codex 云端执行环境可安装本 GitHub 项目的规则和 Skills。是否支持原生记忆、何时生成记忆，由目标客户端决定；安装本框架不代表该执行环境获得了其他节点的历史记忆。

可选配置在 [memory-settings.example.toml](memory-settings.example.toml)，不表示当前设备已经启用；同步工具仅分发这个文件，**不会改写 `config.toml` 或自动开启记忆**。在新设备上使用原生「个性化 → 记忆」或该客户端支持的配置入口，保留设备已有选择。

官方说明：[Memories](https://learn.chatgpt.com/docs/customization/memories) 将必要指导放在 `AGENTS.md` 或权威文档中，记忆作为回忆辅助。范围划分也可参考 [LangChain memory overview](https://docs.langchain.com/oss/python/concepts/memory)；参考其会话范围与跨会话记忆的区分，不引入该运行框架或新的存储平台。
