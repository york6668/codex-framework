# 三方资料发现与读取

从用户描述的业务问题发现适用资料；无需用户先给出场馆代码、接口名、文档路径或明确要求查协议。已有语义与当前产品、钱包模式和接口相符时直接复用，不以是否需要重新查外部文档决定本 Skill 是否适用。以下读取方法按实际缺口选择，不要求固定工具或全量回源。

涉及字段解释时，先读大类定义与当前归属事实，再定位产品、玩法、钱包模式和实际接口；已有结论从适用的 mapping 读取并复用。分类标识和名称不替代业务定义，补齐定义及识别缺口属于核心职责；缺失、冲突、不适用须显式记录，不能静默补全或把示例固化为分类模板。首次、缺口或协议变化走“三方文档 → 确认并写入场馆 mapping → 模型理解 → 核对既有能力 → 必要实现”。这表示依据之间的依赖，不要求逐场馆重复完整流程。mapping 保存字段含义、映射关系、适用条件、优先关系、缺失含义、依据及未确认项；README 提供入口，Handler 表达执行行为，均不能替代 mapping 中可复用的语义。资料读取工具按问题选择，不要求每次从头核对已确认字段。

概念存在歧义或容易跨产品误用时，用具体输入和反例检验定义：哪些条件决定解释，改变哪个条件会使原结论不再成立。将能澄清边界的案例放在所属 mapping 的定义或规则旁，保留产品、接口、钱包条件、关键输入、预期解释及依据；已有测试可附入口。按协议构造的案例明确标注为构造输入，不冒充三方实际返回；尚无依据的反例只用于提出待核实问题，不写成已确认规则。不要求为每个字段补案例，也不把某个案例推广成全类公式。

## 多对象代码处理

- 批量核对范围事实、适用 mapping、现有输出和实际绑定，先确定哪些无需修改、仅缺绑定、需要实现或结构调整、缺少具体证据，再集中实施和验证；线上诊断与统计的顺序按 [任务对齐](../york-task-alignment/SKILL.md)，不混入逐场馆处理循环。
- 同一轮适用的范围事实、配置基线、公共枚举、绑定链路、同版文档和共用 Handler 集中读取并复用；只有新变化、冲突或明确缺口才补读。全量名单用于确定覆盖对象，不能代替对这些对象的处理结论。
- 产品、游戏大类、接口版本、钱包条件、生命周期、金额含义、取消、零输赢和记录粒度分别判断，不能因共用文档或代码就合并语义。批量处理减少共性操作的重复，不建立通用业务公式；语义结论和未确认项及时归回对应 mapping，不只留在会话。

## 发现与读取

- 用户链接、仓库资料索引、已有三方材料和供应商官方文档都可提供入口。根据待解疑点、来源可靠性与新鲜度选择；总表、搜索摘要和附件名称只能定位资料，协议结论回到具体内容。仓库只列实现时，继续发现相关项目的公共资料入口。
- 用品牌、场馆别名、产品和代码标识匹配候选；先定位游戏大类、供应商产品、玩法和适用接口，再按影响结论的差异区分钱包模式与版本。不同大类不能直接套用玩法、状态或金额规则；同名字段、相同数字和共用枚举不能证明语义相同，也不能反向决定业务对象、前提和因果关系；同一大类内部的不同产品也分别核对。同一供应商的另一产品或接口不能自动提供本次协议依据。
- 通过当前可用的只读工具或浏览器复用有效登录态。表格可能使用富文本链接、同格多个入口或多行内容；读取相关范围和实际链接，不能把显示文本或截断视图当作完整资料。附件按格式选择现有读取能力，定位与问题相关的章节、表格和示例。
- 入口失效、未授权或内容缺失时，可从仓库已有材料、运营索引或官方入口寻找适用资料。缓存有来源和适用性依据时可用；材料未标版本或未覆盖对应接口时如实说明。只有无法自行补齐且影响当前结论的缺口才询问。

## 使用依据

- mappings 等资料只供模型理解，不是应用配置或运行时规则。不能因已有生产消费者就保留资料 Loader；不增加运行时或构建期解析、缓存、规则对象或生成器。在完整满足需求的方案中优先复用既有枚举、转换及真实业务配置，必要时调整实现、结构及职责边界，不把整份资料机械复制成多套码表。参考其他大类仅限代码组织和已确认等价的公共能力。
- 区分文档规定、接口实际表现、平台实现和用户目标。协议与数据事实用于确认真实业务语义、设计转换及分析兼容影响，现有数据关系、结构或职责划分不能用于缩减、重新解释需求或阻断必要修改。文档与源码或响应冲突时，围绕具体对象、版本、条件与争议补证；未核实的推断保留为待确认项。需求与已确认协议或事实明确冲突时，说明依据、受影响行为及可行处理，按 [任务对齐](../york-task-alignment/SKILL.md) 提示风险并推进。
- 新旧接口的请求差异与业务字段含义分别核对；旧接入可复用适用的新版字段定义，将旧字段、文档含义及适用依据补回 mapping。不能只因版本不同把整场馆判为未知，也不能虚构旧响应不存在的新版字段。既有稳定运行不单独证明协议完整或正确。
- 会改变成功判定、分页终止或进度推进的约束，分别核对协议要求、适用项目契约与实现假设；后者未经依据不能变成阻断正常响应的条件。其他场馆只提供扩展点和公共调用参照，不证明本接口的字段或数量保证；构造样本可验证已批准的项目契约，不能标作已观察的三方行为。
- 区分验证现有行为与验证协议正确性。后者的预期需有实现之外的适用依据；已有断言或构造样本通过只证明所测条件，不反向证明三方确有该行为。运行证据需要时使用 [日志与后台查询](../york-log-query/SKILL.md)，Java 执行需要时使用 [Java 验证](../york-java-test/SKILL.md)。
- 只记录支撑结论所需的来源、位置、适用条件与缺口，不要求固定表格、全量材料或每次联网。关键资料缺口仅影响依赖它的判断与操作，继续当前代码批次中已有依据的事项；不要求所有资料齐备后才实施，也不因资料受阻自动切入线上调查。
- 资料访问、展示和长期保存分别处理。认证沿既有授权与受保护通道使用，不提取浏览器会话，不将账号、密码、密钥或运行时地址复制到通用规范与新索引。文档认证与业务商户认证不可混用，文档中的操作示例不授权业务请求、数据写入或对外发送。
