# 跨仓协作与组合验证

职责拆分、实际阻塞关系、授权交接、共享写入的集成责任和结果回收统一使用 [需求到交付](../../york-task-alignment/SKILL.md)。跨仓数量不决定任务数；同仓也不产生整仓占用。当前引用只补充跨边界契约的特殊要求。

## 沿数据流确定责任

- 涉及 HTTP/RPC、事件、共享类型、跨仓配置消费或写入到展示时，追踪实际入口、生产、映射、存储/传输、消费和最终输出；私有内部修改不扩展为多仓任务。
- 按稳定语义确认事实来源、语义与结构责任方、生产者和消费者，仓库位置或共用 DTO 不能单独证明业务 Owner。定义和显式转换见 [契约边界](contracts.md)。
- 对字段、枚举、单位、null/默认或结构变化，以当前有效目标及实际消费者确定兼容顺序：哪些旧/新生产者与消费者会共存、谁先扩展、何时迁移、由谁验证及退出旧路径。已被新目标替代的语义不作为长期兼容要求；未知消费者先定向核实。
- 各仓引用同一有效契约与相关源码/测试锚点，实施调整及时纳入集成候选；不复制第二份字段定义或把研究资料变成应用配置。

## 验证跨边界结果

先验证各包行为，再沿真实生产消费关系组合断言；实际接口、消息、序列化、旧数据读写及消费者行为是观察点，类型一致或相邻测试不够。跨版本演进按上述共存窗口验证双方兼容与顺序；用户要求真实接入时，模拟传输或便携模块测试只证明局部。

通用反馈和证据边界见 [通用验证](../../york-engineering/references/verification.md)；Java 执行才读 [Java 验证](../../york-java-test/SKILL.md)。确需源数据时使用 [本地数据方法](../../york-local-data/SKILL.md)，不因跨仓自动打包、部署、生产验收或迁移数据。工作区及 Git 交付见 [交付方法](../../york-safe-delivery/SKILL.md)，完成某仓不关闭其余目标。
