# 业务可诊断性与语义说明

## 日志语义

处理异常、状态转换、映射、外部调用、异步、重试或补偿时，检查现有信息能否关联本次处理的阶段、选择原因和结果，实际存在缺口才补充。

使用项目真实关联标识和字段，按需记录阶段、原因码、关键状态、外部结果、耗时及异常链；不要假定共同 traceId，也不为日志修改业务接口。状态修复、回填和映射需要能关联对象、最小前后状态、所用规则与结果，避免从最终值反推原因。

日志诊断价值与业务载荷的字段契约分别判断。新增日志不自动记录全对象、密码、私钥、token 或支付凭据；高频成功路径避免重复高等级逐条输出，不为记日志新增数据库查询、远程调用或显著序列化开销。按实际需要聚合或采样，并用定向断言、可控复现或代码走查检验其关联和判因能力。

读取已有原始日志使用 [日志查询](../../york-log-query/SKILL.md)；内部证据读取与新增采集、聊天展示、长期保存分别处理。

## 契约注释

协议缩写、单位、null/默认、异名映射、兼容理由，以及跨线程或资源约束无法由命名和类型表达时，在承担语义的类型、接口或转换处说明。行为改变时修正失真说明，不批量清理无关历史注释。

语言沿仓库惯例，协议字段与错误码保留原文。严格 JSON 不改为 JSONC；说明放类型、Javadoc 或相邻契约文档。日志和注释验证只覆盖本次改变与未解决的语义缺口，不要求专门收据。
