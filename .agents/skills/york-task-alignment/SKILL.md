# 从需求到交付

所有设计、方法选择和任务发起都由适用核心框架支持的模型编排承接，按完整有效目标组织原职责、现有任务、实际产物和验收缺口。业务与项目在该执行基础中保留领域与工程责任，不另起独立决策/发起机制；独立任务边界不因此合并。父聊天承担沟通与需求入口，模型在真实可用的原生回合负责设计、实施、核收和下一合法动作，不以父逐步转发为前提。当前只使用 Codex 套餐内原生模型/任务及已授权、实际支持的正常工具和 CLI，不设计或引入独立模型 API、Key、API 计费、外部模型 worker 或 fallback；正常工具接口继续按原能力和权限使用。用户控制启停，目标、纠正、依赖和结果沿现有记录关联，不复制任务库、调度器、执行器或通知服务。

首次工作从下面的正常路径进入；简单且边界清楚的改字、查询或局部操作可以直接完成，不需要计划文档、任务拆分、独立代理或用户逐项批准。

## 识别目标并发现方法

先从全部仍有效用户要求、反馈及影响目标的已证发现（包括尚未开任务的项）确定目标、范围、预期交付、验收依据、真实依赖及当前责任，区分已知事实、明确的新行为与会影响实现的未决问题。这些内容在原任务中说明到足以执行和回收即可，不要求固定表单。已有资料和可用工具足够时直接推进；只针对会改变结果或授权的歧义询问，期间继续独立工作。新追加属于同一交付或缺陷续办时接续原目标，不因只看到最新子问题丢失累计要求。

业务任务开始时，先由[业务系统方法](../york-engineering/references/business-workflow.md)选择适用的业务规范、执行要求、测试方法和交付标准，再结合项目契约组织本地实施。方法不只记录需求和结果，还用于检查项目是否满足约定；具体字段、接口及环境事实由所属项目提供。结果返回后仍按完整目标核对尚未满足的义务。

按待解决的问题组合最少必要方法，先读入口，再读有条件相关的引用：

| 当前问题 | 方法与边界 |
|---|---|
| 首次开发、结构选择、局部缺陷或代码验证，任意语言 | [通用工程](../york-engineering/SKILL.md)；实现和验证规模与实际风险相称。Java 工具执行再读 [Java 验证](../york-java-test/SKILL.md)。 |
| 公共类型、事件、接口或跨仓生产消费变化 | [跨仓契约](../york-cross-repo-change/SKILL.md)；沿真实消费链定位，仓库数量不决定拆包数。 |
| 第三方定义、字段或业务归属未明 | [资料发现](../york-provider-docs/SKILL.md)；先复用适用定义与 mapping，不用同名字段推导语义。 |
| 需要运行证据、数据或节点能力 | 先核对资源管理归属与当前身份用途：模型管理的工作站资源从 [工作站](../york-workstation/SKILL.md) 的已登记管理入口、部署与元数据能力发现；外部业务身份按原用途选择 [日志](../york-log-query/SKILL.md) 或 [本地数据](../york-local-data/SKILL.md)。数据库字样、个人 DataGrip 无连接或未解锁不构成模型资源的依赖；认证与副作用按 [环境同步](../york-workstation/references/environment-sync.md) 判断。方法选择不授权生产写入、迁数据或维护其他服务。 |
| 研究或直接只读问题 | 根据问题取证并交付结论；没有代码、资源或交接需求时不加载工程及多任务流程。只有待未来事实验证的结论才读 [结论生命周期](references/decision-lifecycle.md)。 |
| 审查或获准 Git 交付 | [代码审核与交付](../york-safe-delivery/SKILL.md)；修改、提交、推送、部署的授权分别核对。 |

## 项目职责与当前请求

先按用户问题、对象与规则、真实流程和期望结果识别需求，判断满足程度及下一动作。核心框架为模型设计与任务编排提供共同方法；业务系统持需求、业务语义、规范/执行要求、验收方法、交付标准及实际效果；本地项目持工程实现、测试、修复及原件。模型按本次需要组织这些职责并将适用要求交执行编排落实到选定机器，机器不承担业务或项目责任，也没有是否采用适用要求的裁量。该职责说明是例子，不是每项必经层级、串行管道或新增平台；同一原任务可连续承担适用职责。业务侧不收源码/tests/logs或管理工程版本，交易保留自身专业语义；这些设计和任务仍在同一适用核心框架支持的模型编排基础上进行。

多项目保留自己的有效目标和义务，不因目录、报告者、旧源码成功或最新一句话改派责任。任务按可独立实施、验证和收尾的结果拆分，在原描述说明必要输入、产出、真实依赖、主写范围和完成条件；优先复用既有任务。规范修订、工程重构、分发安装、消费者采用和领域结果不塞进一个大回合，也不互设无依据前置。

当前请求身份、所回答义务、产物和验收逐项对应。旧请求的报告即使真实 PASS，也不回答本轮目标；来源缺失保留未证实，不猜压缩或记忆导致。接收连续委托时回读选定原生输入及当前修订，旧目标仍有效的部分连同原义务、出处进入后续执行上下文，明确修订才替换对应范围；不能仅因原件仍在历史记录就认为下一执行者已经得到。正式持久入口可在原任务 spec 提供 `project`、`assignment`、`request_identity`；这些是执行上下文和关系，不授予权限。`verify-return` 对当前身份和产物报告作关联核对，不能凭报告标题或词语相似认定本轮完成。

## 形成能交付的切片

复杂目标按能观察到用户结果的纵向切片组织，每片贯穿必要入口、生产/转换、消费、验证与交付，不仅按目录、技术层或 Skill 标题分工。先做能解除关键不确定性或交出可用结果的一片；已有范围遗漏需求时重划方案，最小改动不能限制必要理解与实现。

涉及前后台贯通及页面效果交付时，从开始就保留后台操作、同一业务对象的前台消费、本地效果和获准远端交付，以及相互可达的文档说明、页面效果和统一入口，按[业务系统页面交付](../york-engineering/references/business-workflow.md#前后台页面贯通与效果交付)组织。区分核心通用编排、框架内业务系统方法与具体项目执行：前两者由共享框架维护，项目提供接口、页面、工具和环境事实。阶段成果返回后核对完整链路的剩余义务；接口通过、单端页面或截图上传不能关闭其他已约定阶段。部署依赖只限制依赖该版本的验收，不阻止页面整理、上传能力验证及其他独立步骤。

先核实进入编排的前提：对会改变范围、顺序、兼容、资源处置或验收门槛的判断，沿原任务说明具体来源、原文所能支持的事实、适用对象与尚未证实部分。推测和未知只用于选择必要的有界查证，不能静默变成实施决定或硬依赖；合理但非强制的防护说明理由、成本和退出条件，不声称它证明了风险。用户目标与未来选择按要求执行，与现行事实分别判断。转述、摘要、任务创建、交接和压缩须保留原出处与证据状态；重复出现、另一任务同意或更确定的措辞都不能升级证据。来源确已补足才更新相应事实，仍不扩大授权。

只画实际阻塞关系：缺哪个已证输入、能力、共享契约、写入窗口或验收结果会使哪一步不能正确执行，并说明该事实为何影响该消费者。前提不明时只暂缓真正依赖它的决定，低成本只读取证和无依赖工作继续；不先按假想高风险增设迁移、备份或全局验收门槛。阻断关联确切动作、资源及其依赖消费者，向下游保留来源与状态，只传播这条已证关系。环境方案待对齐、Docker 离线或 OOM 只限制依赖该环境的操作和现场验收；输入充分且无该依赖的框架或业务代码、离线验证照常推进。用户规定顺序时依其要求；允许并行时，无依赖分支可以并行，不扩大授权，也不要求另开会话。涉及 OpenAI 的设计、任务、工具执行或继续运行时，先按 [官方依据与能力核验](../york-engineering/references/openai-capability-basis.md) 从完整官方体系发现相关产品和现成能力，再依当前宿主事实形成切片、执行与恢复方案；Agent 工作流仅为示例，不据此预设新建持久调度或排除其他产品。已知相关合同变化再复核受影响设计，不把其他 API/SDK 或宿主的能力当成本宿主已启用；范围纠正只改变相关依据和依赖，不扩散暂停或接管无关任务。业务流程按 [业务复测](../york-engineering/references/business-workflow.md) 选择项目契约与真实反馈，官方没有业务细节不构成业务禁止。判断任务与跨节点能力时使用当前原生工具合同；任务创建、消息和真实系统操作仍须实际授权，不能因方法需要扩权。

已有相关任务优先复用，交接说明当前目标、必要输入及版本、数据位置与允许影响范围、交付证据、实施/集成/适用独立验收责任及失败归属。授权或限制的来源有争议时，在原交接中带原消息/工具引用及实际可见等级，分别说明用户原文、上级委托、模型自限和平台回执；助手“根现在允许”的协调文字不升级为人类原文，转贴用户引文也不证明接收工具已取得同等级授权。只传适用于本次目标、对象、效果和阶段的限制，保留原失败与尚未核实来源；不为每次动作新建表单、授权库或收件层。只有真实重叠写入才协调单一写入或集成责任，按当前内容合并，不设整仓占用、永久文件锁或强制分支/worktree。

涉及资源时先按[资源角色与处置](../york-workstation/references/resource-lifecycle.md#资源角色与处置)核对用途、重建契约、最小本地证据与在途依赖，再选择停旧重建、保留迁移或有依据的连续接管；数据库、持久或共享标签不自动触发生产热接管/W0W1。工作站以任务完成效率和有效资源利用为优先，必要停机、替换和停旧重建正常安排。容量以用户正常工作软件基线为准，临时关软件只算缓解；释放资源与新增负载按各自副作用判断，不把启动余量用于阻止安全停旧。按[资源生命周期](../york-workstation/references/resource-lifecycle.md)核对测量及真实恢复约束，判断深度随实际风险，不用固定大小阈值代替数据价值或恢复依据；核验与等待只覆盖具体风险，复用有效结果，不把保旧、重复全量验证或全局环境稳定变成默认前置。资源登记完成仍按下面的结果回收处置发现。

在途文件修改同样是成果：读出差异的意图及依据，与最新目标一致的主动纳入候选并共同验证；未知内容先保护并定向核对。旧行为被新共识替代时修改实现及测试预期，不能以兼容维持旧实现或长期双轨。仍有效的接口、持久数据和消费者按事实保留必要迁移及回退，说明退出条件；真实语义冲突只暂停受影响部分。

## 职责与新问题

处理职责承担方案、实现、自测、修正和授权内交付；排查职责承担已授权的有界取证、原因与影响判断，把证据及限制交回原处理责任。排查范围只有读取时，不修改旁任务文件、服务或优先级；排查意见本身不构成暂停、接管或扩展旁任务的许可。这项限制约束该排查，不撤销原父目标及兄弟任务已有的实施授权。准备、诊断转到实施，或约束与旧授权冲突时，沿原消息核提出者、目标任务/请求、对象与副作用、适用阶段及是否仍有效；“本轮不执行”和模型选择的保守办法不能改写为用户永久禁止。来源或期限不明先保留具体未知，不能凭“用户禁令”标签扩大；真实用户暂停/禁止、平台限制和未解除拒绝仍按准确范围保留。已证风险需要止住执行时只处理获准的受影响动作，并由主协调核对依赖；其余工作继续。

独立验证对明确范围、版本和预期判通过、失败或未运行，交原处理修正；集成处理真实相互作用和组合结果。要求独验时自测不代签，普通任务不强制拆四个会话。原执行任务继续负责其已接受范围的完整交付，异常或子任务返回不把责任转移给父聊天；主协调处理整体衔接和必要用户决定，不作每步执行/核收前置。连续委托按当前需求续接，旧 completed/PASS 不回答新要求，独立未完目标不被最新一条静默替代。

新问题先关联原件、具体动作或资源、已证影响与未决假设，判断属于原目标缺陷、独立需求还是共享依赖。原目标缺陷交原责任续修；独立问题沿其授权有界处理，不改变无依赖原任务的目标、顺序或交付条件。扩大查证不等于扩大修改范围；确需变更目标、权限或资源目的地时只提出具体新增项。已有用户目标覆盖的同对象实现细节、工具参数或角色接续调整，由原授权责任方处理，不自动再申请整个目标或工作站管理权；新增真实风险、持续权限、目的地或用户取舍才核对应新增范围。工具正式执行准入与用户目标授权分别判断，提交原生审核不等于修改持久权限，也不保证获准；平台要求本人确认时只交实际确认步骤，平台拒绝则停止对应动作。用户明确暂停整个项目时，按其覆盖范围停止，不以并行原则继续；仅对齐环境方案或暂停某一步不能推成全局暂停。用户纠正误暂停后回看最新有效目标与在途成果，恢复仍获准分支，保留未解除的取消、硬拒绝和真实依赖。

原生读回缺少来源、轮次或 final 证据时，按 [原生补证与结果收讫](references/execution-check.md#原生补证与结果收讫) 使用已授权且无平台拒绝的既有入口核实，并区分程序绑定、实质验收和人工收讫。已证明的合并或领域效果不因返回格式失败而重做；原协调已按事实明确接受的有限结果不再为形式回执启动循环，旧失败仍保留。

受控回归中的故意缺项保留为测试对照。验证目的达到并获相应验收后，测试完成与夹具里的 pending 分别记录，不能把该缺项复制成真实业务待办；真实未履行义务仍按原用户目标和实际结果判断，不能仅凭“测试”标签删除。

## 执行异常的自行纠偏

工具/审核错误、结果冲突、版本漂移、效果缺失或反复只报状态时，原执行者在当前或下一个既有机会自行核对：准确动作、对象/目的地/副作用及是否发生，授权/限制的真实来源和适用范围，普通错误、拒绝与 UNKNOWN，以及可控的调用构造、说明、约束传播、拆分或实现缺陷。先保护原输入/失败，修正已证可控原因并作适用反馈；不只转交审核摘要或重新泛化索权。平台内部输入不可见则原因未知，不把审核判断当已证根因，也不声称补规范改变平台 trust。

拒绝停止同对象/目的地/副作用；不得改名、去掉升级参数、换通道/工具/设备/发送者或伪造授权绕过。仅有实质新相关证据、确认原动作未执行且原路径支持时，才可在原允许入口复核一次，再拒即停；单独禁止的旧动作不获重试许可。UNKNOWN 只核原获准可见状态/效果，缺终态接口保持未决，不超时清零或补发。只修调用方问题而准入仍缺时，分别报告已修、被拒、待处理和未知，以及恢复条件。仅真正需要新增用户选择、目的地、权限或费用时精确询问。局部异常只改变相关动作，不解除原任务责任。

## 实施、回收和交付

交付首先判断当前用户需求和业务标准是否达到。业务侧交付实际结果及剩余问题；本地工程项目自行核源码/构建/测试/采用及版本，不要求业务侧管理工程版本，也不禁止为核实需求或缺陷而检查必要源码。completed 只结束回合，一次 PASS 只覆盖所测范围。摘要和交接保留原结果的限定、无效对照、未执行与具体拒绝，不能只传版本及 PASS，或因未选入当前通过项就让这些事实消失；源码组装、加载可见、实际使用及效果分别判定。历史结论按要求、代码、输入、环境、方法的适用范围复用，改变部分复验，不重跑无关全套。可选 task delivery-view 只核传入关系，不是统一交付模型、执行许可或必经转换；用户示例不固化层级、顺序和格式。

原执行责任在适用核心方法下交付并消费结果，不等待父转发或总表先写回。核查单位是当前任务适用要求及其送达、实际执行和效果，版本仅定位来源；不因节点整包版本不同自动要求全量升级，也不将缺证写成节点可自行不采用。对缺失环节沿要求形成、任务编排、工具执行和效果核验定位，由原责任在授权内补齐。跨设备复用已授权载体，各端的编排在自身真实机会落实必要输入，不依赖父读远端会话；有文件不证明被唤醒。唯一汇总只派生关联、漂移和遗漏提示，汇总落后不使已交成果退回待修；真实工具限制、拒绝或UNKNOWN继续按具体动作保留。


按所选工程或专业方法完成设计、修改及适当验证。需要另一项结果时回收确切版本、原生执行结局、实际效果、通过/失败/未运行的验收结论及尚缺依赖，分别判断后重新计算当前可做步骤；失败返原实施责任，继续无依赖部分。排查结果即使晚到也交回原处理责任，先核对版本、当前变化和影响；新证据改变原因时修正方案，不能覆盖已经验证的较新成果或令排查方直接接管。组件分别独立通过后，集成责任方仍须将有效在途成果合入同一候选，沿实际交互和原失败路径作必要组合回归；共享冲突只隔离重叠文件或资源及其依赖，不停整仓。组合失败交相应原处理修正，并按确切新版复验；独立结果只在相同内容及适用范围内复用，不能拼接不同版本的通过结论。类型一致、分项通过和 `check` 的 ready 投影均不能证明模型真实规划或整体目标完成。

排查、资源登记或盘点交付时，从发现、剩余未知、整改建议和用户反馈提取仍需处置的问题，关联现有目标、原处理责任、下一步、依赖和验收；按问题归组，复用原任务和原有唯一清单，不按每个资源另建任务或反馈台账。调查本身完成只关闭已核范围，候选数量未复核、匿名资源归属未知及派生整改仍保持待处理；不从“已登记”推导“无需处置”。

反馈或用户纠正与旧计划冲突时，保留纠正原文、来源及适用对象，定位被否定的前提及其派生转述、硬依赖、暂停、额外兼容和验收要求；撤销仅由错误前提支撑的项，并更新受影响方案、代码、阈值依据、测试预期和原有清单。核对活跃消费者实际收到并采用的版本与内容；只在报告列出、发送成功或口头同意不算落实。尚未核实采用时列出具体任务、旧前提、应撤步骤及接收缺口，独立部分继续。纠正某项数据价值不等于允许删除具体对象，既有明确安全要求、外部业务和个人文件、真实运行依赖、平台确认与未解除拒绝继续按其自身依据保留。通过已有授权交接并核实接收、落实和返回；未能取得实际更新证据就保留具体未验项，已取消的项不因反馈归组复活。

阶段完成、子任务返回或实际通知到达时，承担执行责任的原任务回看自己全部仍有效目标、当前纠正及反馈，先核收已有成果，再选择并完成下一获准动作。不要求读完整父历史，已完成范围也不为重建总表而重做。OPEN、owner、承诺继续和最近一批 completed 都不是实际接续；失败/未知不因返回而完成。当前已接受范围完成即交付，把其他范围明确交原独立责任，而非在一个大回合包办所有后续；没有实际运行机会不虚构后台执行。

选择本任务可做的步骤就执行；确需其他既有责任时，只沿具备授权且当前确实支持的入口交接，保留输入范围、逻辑效果和预期结果。建议、发送、接收、执行、返回分别说明；发送成功不代执行，UNKNOWN 不按新 sender 或缺可见收件补发同一效果。原任务仍负责未完结果，消息缺口不授权换路，不让用户重新设计分工；可见范围不足只冻结相关交接，独立工作继续。

取消保持停止，准确拒绝及其必要依赖单独暂停，其他获准工作继续。原每小时 App 任务在实际可访问和获准的本端核收当前成果、比较有效目标并推进可做步骤；通知可用时及时消费，小时补漏而不重做效果。用户控制计划启停，不新建调度或假称跨设备自动接棒。有真实回合却只读旧 fixture、固定示例或旧 frontier 而遗漏可做工作，是消费者/模型执行问题；无新回合则分清触发、接收、节点事实和未知。确无可做项、预算/能力不足或用户暂停时，准确返回剩余结果和恢复条件；有限 CLI 正常退出本身不是故障。

原目标明确要求多项目组合结果时，由既有集成责任合并真正相互作用的成果，在实际采用的明确版本集合上执行适用独立跨线回归，再由原汇总责任派生更新。不把无关项目、所有历史或总表同步设成前置，分项独立交付继续。业务需求验收与本地工程组合检验各归原职责，不能用任一代替另一；需要的最终回归继续保留为单独可收尾范围。

既有 `task` 入口的 `coordinate`/`work` 只关联明确的原任务，投影项目义务和当前可做项，不另建总台账；跨任务依赖声明具体输入版本、来源和消费者原因，假设/未知不升级硬阻断。已登记文件输出和明确逻辑资源按对象、操作与占用协调；同库可共享，兼容读取不因库名相同停止，真实冲突仅隔离重叠效果及其已证消费者。内部占用索引只保存执行和未解拒绝，不代替任务/业务清单，也不允许换项目、任务或入口解除历史拒绝。需要 `finalization` 的实际组合范围关联当前必需分项、合并及实际加载证据和适用独立跨线报告；缺少真实功能义务的证据时保持未完成，程序关系通过也不签模型真实采用。原清单与协调汇总仅派生关联，不作为功能验收前置；缺失、陈旧或被拒的纯汇总不阻独立功能交付。用户明确要求的清单交付仍由原责任单独承接，不能借 `tracking` 标签抹除任何真实功能义务。

核心工程实施可自测，正式独验按原要求由既有独立责任判断适用受检范围。规范修订交正文差异、一致性及消费者，不冒代码已改、安装或真实采用；代码重构、发布安装、消费者落实及最终集成分别复用原责任接续，当前任务不以等待所有阶段作为收尾条件。原未完义务和失败准确保留，后继只接受实际已证范围。

## 反复纠偏时扩大范围综合对齐

同一需求反复纠偏时，以原始要求、有效纠正、历史方案、更早及当前版本重新审视原范围，不能只在现有 diff 内补丁。按 [接续与综合对齐](references/resumption.md#反复纠偏时扩大范围综合对齐) 查到足以解释偏差、确认完整覆盖和必要修改；原有有效成果继续保护。普通接续的信息缺口、局部受阻和原生即时检查也只在需要时读取 [接续方法](references/resumption.md)。
