# 从需求到交付

主会话对完整有效目标负责。用户只需提出要解决的问题，方法选择、必要理解、设计、实施验证和后续接续由模型承担。首次工作从下面的正常路径进入；简单且边界清楚的改字、查询或局部操作可以直接完成，不需要计划文档、任务拆分、独立代理或用户逐项批准。

## 识别目标并发现方法

先从全部仍有效用户要求、反馈及影响目标的已证发现（包括尚未开任务的项）确定目标、范围、预期交付、验收依据、真实依赖及当前责任，区分已知事实、明确的新行为与会影响实现的未决问题。这些内容在原任务中说明到足以执行和回收即可，不要求固定表单。已有资料和可用工具足够时直接推进；只针对会改变结果或授权的歧义询问，期间继续独立工作。新追加属于同一交付或缺陷续办时接续原目标，不因只看到最新子问题丢失累计要求。

按待解决的问题组合最少必要方法，先读入口，再读有条件相关的引用：

| 当前问题 | 方法与边界 |
|---|---|
| 首次开发、结构选择、局部缺陷或代码验证，任意语言 | [通用工程](../york-engineering/SKILL.md)；实现和验证规模与实际风险相称。Java 工具执行再读 [Java 验证](../york-java-test/SKILL.md)。 |
| 公共类型、事件、接口或跨仓生产消费变化 | [跨仓契约](../york-cross-repo-change/SKILL.md)；沿真实消费链定位，仓库数量不决定拆包数。 |
| 第三方定义、字段或业务归属未明 | [资料发现](../york-provider-docs/SKILL.md)；先复用适用定义与 mapping，不用同名字段推导语义。 |
| 需要运行证据、数据或节点能力 | 先核对资源管理归属与当前身份用途：模型管理的工作站资源从 [工作站](../york-workstation/SKILL.md) 的已登记管理入口、部署与元数据能力发现；外部业务身份按原用途选择 [日志](../york-log-query/SKILL.md) 或 [本地数据](../york-local-data/SKILL.md)。数据库字样、个人 DataGrip 无连接或未解锁不构成模型资源的依赖；认证与副作用按 [环境同步](../york-workstation/references/environment-sync.md) 判断。方法选择不授权生产写入、迁数据或维护其他服务。 |
| 研究或直接只读问题 | 根据问题取证并交付结论；没有代码、资源或交接需求时不加载工程及多任务流程。只有待未来事实验证的结论才读 [结论生命周期](references/decision-lifecycle.md)。 |
| 审查或获准 Git 交付 | [代码审核与交付](../york-safe-delivery/SKILL.md)；修改、提交、推送、部署的授权分别核对。 |

## 形成能交付的切片

复杂目标按能观察到用户结果的纵向切片组织，每片贯穿必要入口、生产/转换、消费、验证与交付，不仅按目录、技术层或 Skill 标题分工。先做能解除关键不确定性或交出可用结果的一片；已有范围遗漏需求时重划方案，最小改动不能限制必要理解与实现。

先核实进入编排的前提：对会改变范围、顺序、兼容、资源处置或验收门槛的判断，沿原任务说明具体来源、原文所能支持的事实、适用对象与尚未证实部分。推测和未知只用于选择必要的有界查证，不能静默变成实施决定或硬依赖；合理但非强制的防护说明理由、成本和退出条件，不声称它证明了风险。用户目标与未来选择按要求执行，与现行事实分别判断。转述、摘要、任务创建、交接和压缩须保留原出处与证据状态；重复出现、另一任务同意或更确定的措辞都不能升级证据。来源确已补足才更新相应事实，仍不扩大授权。

只画实际阻塞关系：缺哪个已证输入、能力、共享契约、写入窗口或验收结果会使哪一步不能正确执行，并说明该事实为何影响该消费者。前提不明时只暂缓真正依赖它的决定，低成本只读取证和无依赖工作继续；不先按假想高风险增设迁移、备份或全局验收门槛。阻断关联确切动作、资源及其依赖消费者，向下游保留来源与状态，只传播这条已证关系。环境方案待对齐、Docker 离线或 OOM 只限制依赖该环境的操作和现场验收；输入充分且无该依赖的框架或业务代码、离线验证照常推进。用户规定顺序时依其要求；允许并行时，无依赖分支可以并行，不扩大授权，也不要求另开会话。涉及 OpenAI 的设计、任务、工具执行或继续运行时，先按 [官方依据与能力核验](../york-engineering/references/openai-capability-basis.md) 从完整官方体系发现相关产品和现成能力，再依当前宿主事实形成切片、执行与恢复方案；Agent 工作流仅为示例，不据此预设新建持久调度或排除其他产品。已知相关合同变化再复核受影响设计，不把其他 API/SDK 或宿主的能力当成本宿主已启用；范围纠正只改变相关依据和依赖，不扩散暂停或接管无关任务。业务流程按 [业务复测](../york-engineering/references/business-workflow.md) 选择项目契约与真实反馈，官方没有业务细节不构成业务禁止。判断任务与跨节点能力时使用当前原生工具合同；任务创建、消息和真实系统操作仍须实际授权，不能因方法需要扩权。

已有相关任务优先复用，交接说明当前目标、必要输入及版本、数据位置与允许影响范围、交付证据、实施/集成/适用独立验收责任及失败归属。只有真实重叠写入才协调单一写入或集成责任，按当前内容合并，不设整仓占用、永久文件锁或强制分支/worktree。

涉及资源时先按[资源角色与处置](../york-workstation/references/resource-lifecycle.md#资源角色与处置)核对用途、重建契约、最小本地证据与在途依赖，再选择停旧重建、保留迁移或有依据的连续接管；数据库、持久或共享标签不自动触发生产热接管/W0W1。工作站以任务完成效率和有效资源利用为优先，必要停机、替换和停旧重建正常安排。容量以用户正常工作软件基线为准，临时关软件只算缓解；释放资源与新增负载按各自副作用判断，不把启动余量用于阻止安全停旧。按[资源生命周期](../york-workstation/references/resource-lifecycle.md)核对测量及真实恢复约束，判断深度随实际风险，不用固定大小阈值代替数据价值或恢复依据；核验与等待只覆盖具体风险，复用有效结果，不把保旧、重复全量验证或全局环境稳定变成默认前置。资源登记完成仍按下面的结果回收处置发现。

在途文件修改同样是成果：读出差异的意图及依据，与最新目标一致的主动纳入候选并共同验证；未知内容先保护并定向核对。旧行为被新共识替代时修改实现及测试预期，不能以兼容维持旧实现或长期双轨。仍有效的接口、持久数据和消费者按事实保留必要迁移及回退，说明退出条件；真实语义冲突只暂停受影响部分。

## 职责与新问题

处理职责承担方案、实现、自测、修正和授权内交付；排查职责承担已授权的有界取证、原因与影响判断，把证据及限制交回原处理责任。排查范围只有读取时，不修改旁任务文件、服务或优先级；排查意见本身不构成暂停、接管或扩展旁任务的许可。已证风险需要止住执行时只处理获准的受影响动作，并由主协调核对依赖；其余工作继续。

独立验证职责对固定版本、输入、环境和验收依据判断通过、失败或未运行，保留失败并交回原处理修正；集成职责合并各项有效成果、处理实际冲突并验证组合结果。职责可以由现有任务按范围承担，简单任务不强制拆成四个会话；要求独立验证时，处理者的自测仍不能代签。主协调始终承担完整目标、职责衔接、交接接收和结果回收。 接收委托及返回结果前，核对本次选定原生输入、对象与冻结版本、实际执行结果和引用报告逐项对应；累计整体目标与这次有限交付分别判断。同线程连续委托、旧完成回合或旧 PASS 不替代当前对象，已执行的当前失败或未运行须如实返回。多个仍有效对象分别保留，明确修订才替代对应旧输入；不能默认最新一条取消其他待办。

新问题先关联原件、具体动作或资源、已证影响与未决假设，判断属于原目标缺陷、独立需求还是共享依赖。原目标缺陷交原责任续修；独立问题沿其授权有界处理，不改变无依赖原任务的目标、顺序或交付条件。扩大查证不等于扩大修改范围；确需变更目标、权限或资源目的地时只提出具体新增项。用户明确暂停整个项目时，按其覆盖范围停止，不以并行原则继续；仅对齐环境方案或暂停某一步不能推成全局暂停。用户纠正误暂停后回看最新有效目标与在途成果，恢复仍获准分支，保留未解除的取消、硬拒绝和真实依赖。

原生读回缺少来源、轮次或 final 证据时，按 [原生补证与结果收讫](references/execution-check.md#原生补证与结果收讫) 使用已授权且无平台拒绝的既有入口核实，并区分程序绑定、实质验收和人工收讫。已证明的合并或领域效果不因返回格式失败而重做；原协调已按事实明确接受的有限结果不再为形式回执启动循环，旧失败仍保留。

受控回归中的故意缺项保留为测试对照。验证目的达到并获相应验收后，测试完成与夹具里的 pending 分别记录，不能把该缺项复制成真实业务待办；真实未履行义务仍按原用户目标和实际结果判断，不能仅凭“测试”标签删除。

## 实施、回收和交付

按所选工程或专业方法完成设计、修改及适当验证。需要另一项结果时回收确切版本、原生执行结局、实际效果、通过/失败/未运行的验收结论及尚缺依赖，分别判断后重新计算当前可做步骤；失败返原实施责任，继续无依赖部分。排查结果即使晚到也交回原处理责任，先核对版本、当前变化和影响；新证据改变原因时修正方案，不能覆盖已经验证的较新成果或令排查方直接接管。组件分别独立通过后，集成责任方仍须将有效在途成果合入同一候选，沿实际交互和原失败路径作必要组合回归；共享冲突只隔离重叠文件或资源及其依赖，不停整仓。组合失败交相应原处理修正，并按确切新版复验；独立结果只在相同内容及适用范围内复用，不能拼接不同版本的通过结论。类型一致、分项通过和 `check` 的 ready 投影均不能证明模型真实规划或整体目标完成。

排查、资源登记或盘点交付时，从发现、剩余未知、整改建议和用户反馈提取仍需处置的问题，关联现有目标、原处理责任、下一步、依赖和验收；按问题归组，复用原任务和原有唯一清单，不按每个资源另建任务或反馈台账。调查本身完成只关闭已核范围，候选数量未复核、匿名资源归属未知及派生整改仍保持待处理；不从“已登记”推导“无需处置”。

反馈或用户纠正与旧计划冲突时，保留纠正原文、来源及适用对象，定位被否定的前提及其派生转述、硬依赖、暂停、额外兼容和验收要求；撤销仅由错误前提支撑的项，并更新受影响方案、代码、阈值依据、测试预期和原有清单。核对活跃消费者实际收到并采用的版本与内容；只在报告列出、发送成功或口头同意不算落实。尚未核实采用时列出具体任务、旧前提、应撤步骤及接收缺口，独立部分继续。纠正某项数据价值不等于允许删除具体对象，既有明确安全要求、外部业务和个人文件、真实运行依赖、平台确认与未解除拒绝继续按其自身依据保留。通过已有授权交接并核实接收、落实和返回；未能取得实际更新证据就保留具体未验项，已取消的项不因反馈归组复活。

阶段完成、子任务返回、清单合并或收到完成/断连通知时，每个实际可执行的主会话轮次都回看全部仍有效父目标、最新纠正、衍生待办及反馈，判明已满足、未满足或缺证据；只关闭已验范围，核对原任务是否已有同项在途或结果待回收，再从实际依赖与现有授权中选择并落实下一可执行步骤。重复通知复用已核事实，不重做已完成效果，也不只反复查状态。最近一批完成、没有在途任务、清单中的 OPEN、owner、下一交付或承诺继续均不能代替该步实际行动。失败或未知仍待处置，不因返回而完成；没有实际新轮次时不虚构自动唤醒或后台执行。

选择本任务可做的步骤就执行；确需其他任务时，由具备消息授权的责任方交接固定输入、范围、版本与预期返回，并回读目标任务实际接收或执行响应。分别说明建议、已发送、已接收、执行中和已返回；发送超时或结果未知先核对原动作与目标原件，不重复发送，发送成功也不等于实际接收。确认接收只转交该步执行，完整目标和结果回收责任仍由原协调方承担；接收未确认时发送方保留协调责任；不能合法派发的子任务将具体发送缺口交回有授权的协调方，并继续自身可做的准备，不能让用户重新设计分工。原生消息工具的直接人类授权要求仍适用，另一任务的转交本身不产生该授权；已有适用直接授权继续复用。

取消或撤回的项保持停止，不重派或换入口；硬拒绝及其依赖单独暂停，其他独立获准工作继续。缺入口或消息失败只限制相应动作；尚未查证的管理能力与个人 GUI 缺席不能写成全局阻断。错误依赖被纠正后，原责任在本轮实际恢复获准步骤，再回收结果。确无可执行项时列明原生阻断、未确认交接及恢复条件；没有实际执行机会或接收证据不称后台持续跟踪。沿用原任务消息和唯一清单，不建第二台账、定时器或额外模型调用。主协调仅在整体验收达到当前获准完成条件、用户明确暂停其覆盖范围，或所有剩余项均有具体阻断且无获准独立步骤时停止主动推进。子任务可以交付有限结果，但整体目标和待回收责任不随子项返回解除；接收、执行及有限结果返回后仍须再次回看并落实剩余下一步，单次交接不能验收连续接续。未发生的真实接续分支当轮判未运行，不以静态测试或文件安装签整体采用。

核心框架实施可做开发自测，正式回归由已有独立任务按固定候选、输入、环境和当前目标判定；失败保留并返实施，对确切新版复验，实施者不自签。对应范围通过后按既有授权及时发布、核对安装并刷新当前使用的规则；发布版本、安装文件、任务读取和真实采用分别取证。集成责任把结果、未验项和下一步回收至原有唯一清单，主协调据此继续完整目标；没有合并、组合复测、真实采用或剩余目标的证据时保留相应缺口，不将分项通过写成整体完成。

## 反复纠偏时扩大范围综合对齐

同一需求反复纠偏时，以原始要求、有效纠正、历史方案、更早及当前版本重新审视原范围，不能只在现有 diff 内补丁。按 [接续与综合对齐](references/resumption.md#反复纠偏时扩大范围综合对齐) 查到足以解释偏差、确认完整覆盖和必要修改；原有有效成果继续保护。普通接续的信息缺口、局部受阻和原生即时检查也只在需要时读取 [接续方法](references/resumption.md)。
