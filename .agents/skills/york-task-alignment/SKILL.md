# 任务对齐与纠偏

追加要求和状态询问默认接续当前工作。保留仍有效的目标、已完成修改和用户决定，明确取消的内容不再恢复。

接续时先从适用规范和业务资料复用长期结论，结合当前用户要求确定本轮范围。资料中的历史“本期不做”不构成长期限制，当前实现未覆盖也不等于已批准目标取消。只有当前资料不足以还原关键决定或存在冲突时，再定向回读相关任务；结果摘要不能代替影响当前判断的用户纠偏，也不要求每个新任务重读全部历史。

- 根据任务需要使用对话、已有方案或简短工作笔记。已有 `work_id` 和正文可以沿用；不强制创建 UUID、唯一文件、固定字段或状态机。
- 记录只用于找到目标、关键决定、代码位置与尚未完成的事项。不设资源绑定、当前写入者、版本签名、交接批准或审核目录占用。
- 记录缺失或陈旧时，结合用户要求和当前代码继续工作；必要信息可以边工作边补充，不让记录修复成为业务前置。
- 实现范围以当前有效需求及其业务对象、条件、顺序和预期行为确定。在完整保留所需含义、信息、行为和验收标准的方案中优先复用、少改；现有能力不足时，需求必需的字段新增、结构调整和主链修改属于实现范围，无需用户先指定技术方案。数据关系、现有结构、职责划分和既有实现用于判断实现方式与影响，不能反向定义、缩减或重新解释需求，也不能据此阻断必要修改；仍需排除无关重构。
- 需求与已确认契约或数据事实明确冲突时，说明具体依据、冲突点、受影响行为及解决方案。有完整满足需求且在授权内的实现方式，提示风险后继续推进；确需改变需求结果、验收标准或超出授权时，只询问该项取舍并暂缓依赖它的操作，继续不依赖它的工作。未经核实的推断只用于提出待验证问题和选择必要验证，不能决定实施方案、兼容措施、数据处理、额外比较或范围；标注不确定性不豁免这一限制。先复用足够且适用的依据，确有事实缺口再核对源码、配置、实际数据或本地隔离结果；无法核实只暂缓依赖它的决定，不把猜测交给用户选择成“事实”，也不阻断整个任务。用户明确的新目标或设计选择规定未来行为，与现行行为是否已被证实分别判断。
- 用户纠偏后，从修正后的理解继续落实，撤销依赖错误或未核实前提的决定，同步修正受影响的方案、代码、文档和测试预期，保留其他有效要求与累计成果。用户指出的缺陷不默认构成穷尽清单；沿受影响目标核对生产者、条件传递、消费者、失败处理及最终结果，纠正共同的错误前提，不扩展为无关重构或未经授权的现场操作。配置未启用不等于能力缺失，按当前有效目标的启用条件判断实现与验证缺口。
- 同一请求包含代码处理与线上问题时，分别明确需要交付的修改、诊断或统计结论，按用户顺序处理，未指定时优先代码；独立目标不等于并行任务，也不需要另建对话。代码确需线上事实时，只读取能决定当前修改的必要输入，取得后回到当前代码批次，不顺带追查同步、部署或完整现场链路。
- 多对象代码工作先区分可复用的共性步骤和必须分别判断的业务差异，再组织资料核对、能力与绑定判断、实施及验证批次。每批形成实际处理结论：无需修改、补绑定、必要实现（含结构调整）或仍缺具体证据。结论写入所属资料或代码，不另设必填台账；已确认批次可继续，未确认项保留为未完成，不用缩小目标或默认值代替调查。
- 遇到资料、登录或工具缺口，明确它影响哪些判断，在当前工作线完成不依赖该缺口的批次；不因等待就自动切换另一条调查线。同一目标按职责和依赖分配到不同的已授权执行机，仍是继续当前工作，按 [多机任务分工](../york-workstation/references/environment-sync.md#按依赖拆分多机任务) 明确输入、输出和交接。先完成独立可做的步骤，确需用户解除缺口时，只说明受阻阶段、已完成部分、可继续部分及最小解除条件，不默认要求用户回原机器操作。全部必要依赖不可用时如实说明有限阻塞，按用户已明确的优先顺序处理其他获授权目标，不自行取消或假报完成。
- 以用户需要的成果安排收尾。代码任务默认提供正常 IDEA 中可审核的代码及必要测试结果；不追加报告、交接流程、清理证明、部署或线上验收。
- 已授权的动作继续执行；需要新的用户决定时只询问该决定，不从记录中推导新的审批步骤。

较复杂的工作可沿用 `${CODEX_HOME:-$HOME/.codex}/workflows/works/<work_id>/alignment.md` 记录关键决定。该位置和格式只是方便接续的选择，不是执行条件。历史 `resources.json` 等记录不产生独占权，也不要求原任务释放或归档。
