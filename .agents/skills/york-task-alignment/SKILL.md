# 任务对齐与纠偏

追加要求、状态询问和纠偏先识别指向的交付目标；属于本任务同一目标或缺陷续办时默认接续，保留仍有效的目标、已完成修改和用户决定，明确取消的内容不再恢复。同领域的独立核对不因主题相近就成为另一在途任务的优先事项；用户明确要求改变该任务时直接按纠偏执行。

主会话对完整有效目标持续负责。收到新问题、纠偏、任务结果或局部失败时，主动回看原目标、未完成分项及依赖，识别受影响的实施、独立验证、资源维护和交付责任；复用已有任务，按实际依赖和授权规划交接、收集结果、继续推进并分别报告。分项完成不能使交易系统等原整体目标消失，子问题进度也不能成为整体完成的证据；不等用户提醒才恢复遗漏的目标。只有原任务授权确实覆盖时才向其他任务发送消息或创建任务，不能因统筹需要扩张授权、打断无关任务或绕过平台拒绝。真实缺少用户取舍、目的地授权或平台逐次确认时，只提出该具体决定，继续其他获准工作。

分项实施或适用的独立验证结束后，主会话主动回收确切版本、通过/失败/未运行结果和未完成依赖，固定可核的集成候选，按组件交互、共享资源及原失败路径做必要组合回归；随后更新父目标和受影响子任务的待办、责任人及下一步接续，按已通过范围发布并核对加载。失败项交回对应实施任务，真实现场依赖单列并继续无依赖部分。分项通过不表示整体完成，也不能长期只标全局 `BLOCKED` 或“待合并”而没有具体责任与接续；不因集成工作打断无关任务或扩大既有授权。

接续和交接先以当前有效用户要求及已核实授权的转交确定本轮产出，再把较早委托、转交摘要及调度等历史要求分别判为仍需后续处理、仅作背景或已被纠正；较新的直接用户纠正优先于旧转交，时间较早或在转交文本中靠前，不取得当前目标优先权。不能从旧目标生成本轮答案后才检查新消息。确有较新用户目标而其与旧目标关系尚未核实时，先核对相关原生消息，只暂缓依赖该关系的决定，继续独立步骤。交接说明当前目标、有效边界、已执行与未执行步骤、受阻原件和可继续工作；没有工具尝试或拒绝原件的步骤标为未执行，不写成权限阻断。

接续时先从适用规范和业务资料复用长期结论，结合当前用户要求确定本轮范围。资料中的历史“本期不做”不构成长期限制，当前实现未覆盖也不等于已批准目标取消。当前资料不足以还原关键决定、存在冲突或同一需求反复纠偏时，回读相关任务与原始要求；反复纠偏按下节扩大范围综合对齐。结果摘要不能代替影响当前判断的用户纠偏，也不要求每个新任务重读全部历史。

- 根据任务需要使用对话、已有方案或简短工作笔记。已有 `work_id` 和正文可以沿用；不强制创建 UUID、唯一文件、固定字段或状态机。
- 记录只用于找到目标、关键决定、代码位置与尚未完成的事项。不设资源绑定、当前写入者、版本签名、交接批准或审核目录占用。
- 跨端接续、重复副作用、共享资源冲突、额度、故障恢复或缺陷关闭需要核对多个事实时，从原任务及适用项目契约读出目标、边界、偏好与已接受纠正，再通过原生任务接口和节点原件核对执行及效果。可用[执行与修复的即时检查](references/execution-check.md)的 `resume`、`feedback`、`action`、`progress`、`verify_local`、`close_issue` 对当前来源做无持久台账的条件检查；失败后重排、等待、阶段收尾及交接用同一 `progress` 输入逐项核对剩余工作，不能以一项拒绝或旧测量替代全局状态；技术烟测不能代替目标验收，检查结果不能代替原件、平台权限或业务验收。纠偏计划先列出可手动在本地正常入口验证的原失败及相关行为，固定输入、预期和适用版本；实际运行通过后才把后续真实任务持续观察列为下一阶段。无法本地复现的长期效果另列原因与后续验收，不得跳过其他可执行测试。
- 执行前的有界自检只在目标切换、共享资源变更、重复副作用、拒绝后重排或收尾等实质决策点进行：核对当前目标、对象和消费者、数据位置、目的地、副作用、全部仍有效拒绝、独立步骤及恢复条件。复用当前任务原生消息和节点记录，必要时调用上述即时检查；它不能自动发现被省略的来源或拦截未经过它的工具。平台拒绝无新相关事实时不重复同一对象、目的地和副作用的动作；新事实出现只按原目标及原生入口有限复核，其余获准工作继续。
- 涉及核心框架回归或缺陷关闭时，实施任务先冻结可核的候选代码、输入数据或脱敏夹具、环境与预期，完成必要开发自测并交出失败与未完成项；另由独立任务复核原失败、相关路径和目标语义，记录通过、失败或未运行。失败交回实施任务修正后，独立任务按新版重新验证并保留前次失败。任务拆分不迁移本机真实数据、改变原资源管理责任或绕过平台拒绝；原任务的独立可做步骤继续。实施者不得把自己的测试或静态检查写成独立整体验收。
- 任务交接沿用现有任务和原生消息，说明每项的输入、候选版本、数据位置与允许范围、执行责任和禁止动作、产物及证据、独立验收方、失败归属和下一步。另一任务无入口或局部受阻时只标该验收未运行，不要求实施任务停掉无依赖工作，也不让实施者替代验收方；独立通过的分项按既有授权及时交付，不等待无关任务。
- 记录缺失或陈旧时，结合有效需求与可核实资料继续工作；当前代码只说明现状，不能替代历史需求和用户纠偏。必要信息可以边工作边补充，不让记录修复成为业务前置，也不因此跳过反复纠偏所需的综合比较。
- 实现范围以当前有效需求及其业务对象、条件、顺序和预期行为确定。在完整保留所需含义、信息、行为和验收标准的方案中优先复用、少改；现有能力不足时，需求必需的字段新增、结构调整和主链修改属于实现范围，无需用户先指定技术方案。数据关系、现有结构、职责划分和既有实现用于判断实现方式与影响，不能反向定义、缩减或重新解释需求，也不能据此阻断必要修改；仍需排除无关重构。拟修改对象、文件、契约或运行阶段，或向另一在途任务发送会打断、暂停、重排其执行的消息时，先核对该动作服务哪个当前目标、依赖是否已证实、会影响哪些其他工作；无必要关系的发现留作只读证据或独立建议，不因同仓库、相邻代码和顺手可做就写入或 steer。真实依赖使必要实施范围扩大时继续自主推进，不为每个跨文件细节另设批准。
- 需求与已确认契约或数据事实明确冲突时，说明具体依据、冲突点、受影响行为及解决方案。有完整满足需求且在授权内的实现方式，提示风险后继续推进；确需改变需求结果、验收标准或超出授权时，只询问该项取舍并暂缓依赖它的操作，继续不依赖它的工作。未经核实的推断可以引导查证比较，不能决定实施方案、兼容措施、数据处理或实施范围；标注不确定性不豁免这一限制。查证范围可按完整需求和未决问题扩大，反复纠偏时重新审视原有边界。先复用足够且适用的依据，确有事实缺口再核对源码、配置、实际数据或本地隔离结果；无法核实只暂缓依赖它的决定，不把猜测交给用户选择成“事实”，也不阻断整个任务。用户明确的新目标或设计选择规定未来行为，与现行行为是否已被证实分别判断。
- 用户纠偏后，从修正后的理解继续落实，撤销依赖错误或未核实前提的决定，同步修正受影响的方案、代码、文档和测试预期，保留其他有效要求与累计成果。用户指出的缺陷不默认构成穷尽清单；从完整需求重新识别相关路径，核对生产者、条件传递、消费者、失败处理及最终结果，纠正共同的错误前提，不扩展为无关重构或未经授权的现场操作。配置未启用不等于能力缺失，按当前有效目标的启用条件判断实现与验证缺口。
- 对故障先保留原失败和已完成成果，必要时止损、隔离或降低风险；随后判断问题所属层，沿实际触发、生产者、数据规模与生命周期、消费路径查明造成问题的机制，并在该层修改有证据支持的原因。存储与数据关系问题应核对权威来源、原始与派生版本、物化重复、索引查询、扫描频率、读写放大、内存与 IO 增长、一致性和恢复；依据真实业务规模确定合理目标，而非固定通用阈值或小样本通过。缓解可以保留为长期设计，但需说明业务约束、资源边界以及为何足以解决原问题；把增长转移到磁盘、缓存或其他服务，或单纯增加容量，只证明原症状缓和，不自动证明根因消除。修后以原场景、相关路径和目标规模下的趋势检验约束，分别标明已修复、仅缓解或待定位；事实足够时结束查证，缺口仍在时不假报闭环，也不无限研究。模型主动承担追因和验证，不等用户再指出表象下的缺口。
- 同一请求包含代码处理与线上问题时，分别明确需要交付的修改、诊断或统计结论，按用户顺序处理，未指定时优先代码；同一交付内的独立目标不等于必须并行或另建对话，但不能据此把后来独立提出的核对插入另一在途任务。代码确需线上事实时，只读取能决定当前修改的必要输入，取得后回到当前代码批次，不顺带追查同步、部署或完整现场链路。
- 多对象代码工作先区分可复用的共性步骤和必须分别判断的业务差异，再组织资料核对、能力与绑定判断、实施及验证批次。每批形成实际处理结论：无需修改、补绑定、必要实现（含结构调整）或仍缺具体证据。结论写入所属资料或代码，不另设必填台账；已确认批次可继续，未确认项保留为未完成，不用缩小目标或默认值代替调查。
- 遇到资料、登录或工具缺口，明确它影响哪些判断，在当前工作线完成不依赖该缺口的批次；不因等待就自动切换另一条调查线。确需另一任务提供输入时，先复用已稳定且可核版本的成果；需交接的说明目标、必要输入、允许影响的对象与阶段、预期输出及验证方式，非紧急依赖不自动变成对方的暂停或优先指令。同一目标按职责和依赖分配到不同的已授权执行机，仍是继续当前工作，按 [多机任务分工](../york-workstation/references/environment-sync.md#按依赖拆分多机任务) 明确输入、输出和交接。先完成独立可做的步骤，确需用户解除缺口时，只说明受阻阶段、已完成部分、可继续部分及最小解除条件，不默认要求用户回原机器操作。全部必要依赖不可用时如实说明有限阻塞，按用户已明确的优先顺序处理其他获授权目标，不自行取消或假报完成。
- 本地环境故障被误判为授权缺失或云端处理时，先回到原任务核实用户已授本地范围、工具返回的执行节点、数据位置、目的地及实际副作用，再决定哪一步真正受阻。一次平台拒绝只停被拒动作；保持拒绝证据，不换入口规避，也不把它推广为全任务失权。已获准的日志核对、机制定位、代码或结构修正和本地隔离复测继续推进，原任务承担后续接续与真实验收。新的数据目的地、权限扩张、费用或不可恢复删除按具体动作请求必要决定，不让泛化许可问题替代事故调查。
- 以用户需要的成果安排收尾。代码任务默认提供正常 IDEA 中可审核的代码及必要测试结果；不追加报告、交接流程、清理证明、部署或线上验收。
- 已授权的动作继续执行；需要新的用户决定时只询问该决定，不从记录中推导新的审批步骤。

## 反复纠偏时扩大范围综合对齐

同一需求反复被纠正时，此前划定的分析范围和已有方案本身就是待复核对象。反复纠偏已构成扩大查证的依据，无需先证明范围外存在缺陷，也不能只在当前改动内换一种解释或继续补丁。

综合回读原始需求、仍有效的纠偏及历史方案，对照修改前版本、相关演进版本、项目适用基准与当前实现。比较来源按实际任务、版本历史和用户指定来源识别，不固化分支名、变量名或版本入口；指定来源纳入比较，不自动成为范围上限。当前代码用于核对现状，历史版本用于还原演变，二者均不能反向定义需求，也不因版本更早就认定其正确。

从完整需求重新检查业务入口、处理路径、上下游、关联配置和最终结果，主动寻找此前遗漏的文件、模块、仓库或业务路径。当前改动清单、已有方案和已知依赖均不能限定比较范围；最小改动等实现偏好不能压缩必要的理解与比较。扩大比较用于取得事实，具体修改依据有效需求与核实结果确定，不从猜测直接推导兼容处理或扩大实施范围。

综合判断后重新确定完整方案，修正受影响的实现、文档和测试预期，保留其他有效要求与成果；回看旧版不等于回滚、覆盖当前工作或重建分支。比较持续到足以解释偏差、确认完整需求覆盖和必要修改，不能以当前局部正确或旧测试通过提前结束。资料缺失时明确受影响的判断与证据缺口，继续独立工作，不以当前代码补造历史意图，也不将回溯变成所有任务的固定流程。

较复杂的工作可沿用 `${CODEX_HOME:-$HOME/.codex}/workflows/works/<work_id>/alignment.md` 记录关键决定。该位置和格式只是方便接续的选择，不是执行条件。历史 `resources.json` 等记录不产生独占权，也不要求原任务释放或归档。

前瞻结论及依赖范围按[可验证结论生命周期](references/decision-lifecycle.md)维护；未知前序只限制依赖它的推演，不阻塞事实纠错、独立新事实研究及有据风险响应。
