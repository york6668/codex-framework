# 原任务的条件、执行异常与恢复

在原任务或业务记录中分清 dependency、capability、business_failure、user_stop 与真实权限拒绝；复用已有身份、字段及写入机制，不要求统一 schema、另建任务库或登记普通会话。不能从自然语言、字段名或旧索引标签猜测拒绝来源。

普通条件只限制对应步骤及已证依赖消费者。保留原请求/输入、步骤或对象、责任、条件来源与修订及实际缺失证据；同一条件沿原身份更新，不反复登记。业务失败由原责任诊断；能力或输入缺失先核可控原因及正常恢复入口，确需外部返回时才等待准确条件，独立获准工作继续。

用户停止优先于普通条件满足，只能由适用的直接用户恢复解除。平台拒绝按原对象、目的地和副作用保留，原生工具决定实际动作权限；owner 标签、报告或方法文档不授予权限。UNKNOWN 先核原执行、原效果和原结果，不补发、清占用或把超时当未执行。

执行通道或会话暂时失联属于准确能力的恢复条件，不自动升级为网络故障、权限拒绝或整个目标暂停。按[执行连接恢复](../../york-workstation/references/local-network.md#执行连接与原任务恢复)，当前回合先用获准原入口核诊断与原状态，通知/恢复/已有调度实际提供机会时由原责任主动核收及接续；无需用户重复同一要求。新通道可读只解除通道条件，不清除原 UNKNOWN、有效拒绝及用户停止。没有可用触发能力则记录该具体缺口，不能把重试计划当正在运行。

## 执行异常的自行纠偏

工具/审核错误、结果冲突、版本漂移、效果缺失或反复只报状态时，在原任务按具体原因推进，不从错误标签直接推定违规、缺授权或整体不可执行：

1. **还原失败动作。** 对照用户原目标与实际原生请求，核实际提交材料及继承上下文、参数、父子任务、编排宿主与执行节点、对象、目的地、副作用及执行结果。使用任务所需的最小原件；材料未暴露就明确缺项，不能用助手摘要补成已核输入。
2. **定位及区分原因。** 分别核内容安全检查、工具审批、环境分配、进程执行及业务验收。启动进程前的环境错误不证明代码失败或违规；其他聊天可执行不证明原会话绑定恢复。风险标记只证明该请求被拦截，不证明具体违规、误报或已发现漏洞。核实际行为及故障时生效的官方规则，指出适用条款和证据；规范判断与平台准入分别保留。相邻版本差异也须通过原失败验证其因果关系。
3. **修正并复测。** 对已证的调用构造、材料承接、宿主选择、版本加载或实现偏差，在所属层修正，复测原失败步骤及受影响后继。确认违规时修正违规行为，继续可独立完成的合规目标；未解除的原平台拒绝仍适用，不靠换措辞、代理或入口试探安全检查。修复另一个缺陷不代替原失败根因或恢复证明。
4. **继续有区分力的调查。** 原因未明时列出尚未排除的具体解释，以及哪项原生请求、日志、配置、版本或结果能区分它们，沿获准入口实际取证。可自行取得就继续；确实缺少受支持入口或所需外部事实时，保留已排除项、准确缺项、恢复条件及下一入口。`UNKNOWN`、`OPEN`、平台内部不可见或反馈材料准备完成均不代表调查或根治完成；也不为填满清单重复无变化探测。

上述判断复用原请求、问题及结果字段，不要求新表单或自动策略分类器。检查器只核提供的关系，模型负责结合原件判断原因并执行；方法修订不改变平台 trust。

| 实际状态 | 下一步与边界 |
|---|---|
| 尚未获准的新范围 | 按实际合同核新增决定；已有委托持续适用，不重新索取整个目标或管理权限。 |
| 平台正在等待原生确认 | 定位当前宿主真实请求和原生入口，需要本人操作时只交该步骤；不杜撰批准卡片、命令或能力。 |
| 普通技术/业务失败 | 原责任诊断并修正可控原因，定向复验后接续；不因出现 authorization 字样就推定缺少用户委托。 |
| 平台明确拒绝 | 停止准确效果，核原授权与正式恢复机制；不能改写成普通待用户授权。仅符合下述条件才作一次原路径证据复核。 |
| UNKNOWN | 只核原获准可见状态、原操作及效果；缺终态接口保留未决，不超时清零、清占用或补发。 |

执行授权不通过聊天转述，平台拒绝不通过聊天补授权。任务交接传要求、事实与结果，父聊天声明、历史授权摘录、摘要和 `transcript_evidence` 均不充当执行端批准，不能生成授权字段、批准标记或可信信封。转贴原文不证明接收工具取得同等级授权；重复同意、管理归属或缺 owner 字段也不改变拒绝依据。正常已获准步骤继续，不为每个内部动作新建批准记录。

助手继续承担原任务及有界排查，核当前工具合同和实际原生执行/批准/恢复能力；不要求用户在聊天回复“授权/确认”、重发指令、重复解释归属或代发协调消息来解锁。错误提出的聊天授权问题不等于用户暂停，应在原记录撤销其派生等待，保留原拒绝及未知。只有已核实存在且适用的原生步骤或真正新增的用户决定才交用户；缺少能力就说明准确缺口，不另造授权通道或假称后台修复。原生批准仍受平台审核约束，见[文档能力与当前可执行能力](../../york-engineering/references/openai-capability-basis.md#文档能力与当前可执行能力)。

拒绝后不得改名、去掉升级参数、换线程、工具、通道、节点、发送者或权限重放同对象/目的地/副作用，也不能将原动作包装为新决定。仅在实质新相关证据确实改变判断、确认原动作未执行且原路径支持时，才可在原允许入口复核一次，再拒即停；单独禁止的旧动作不获重试许可。只修调用方而准入仍缺时，分别报告已修、被拒、待处理、未知和已核实的恢复条件。

工具失败后重排、等待、阶段收尾或交接前，先核收失败，再选择当前可做的诊断、修复、复测或后继并取得实际返回。核收失败和登记 OPEN 不是本轮完成条件；有界工作以具体问题的可交付结果为边界，不把“做过一次探测”当作必须结束。逐项保留剩余步骤的直接拒绝、已证依赖和独立可执行工作，后一次资源预检不能覆盖先前拒绝；无可做项时说明准确缺项，观察未实际运行不称持续跟踪。

## 核实满足并接续

原责任读取真实返回，核对当前请求与输入修订、具体条件、对象/节点/版本、来源及观察时间，确认它消除了哪一个缺口。报告必须可追溯到实际原件；旧输入、别的对象、仅文件出现或时间过去，均不自动解除当前条件。重新读取不会刷新源事实，新鲜度按本次动作的实际需要判断。

满足的普通条件由原责任在原权威更新并读回，仅解除该条件；其他条件、停止、拒绝、UNKNOWN 和已有成果继续保留。使用已有 CAS 等一致性能力时按准确原修订操作，冲突先重读；不为这一步新增门禁或恢复已归档接口。

写入或回执不明，先核实际记录及原效果；已提交就消费其结果，未核清不重复领域动作。已完成效果仅在原输入与对象仍适用时复用，变化回到原责任判断，不自动重放。条件解除后，在当前真实回合推进获准后继；文档、程序校验或文件更新不提供后台执行机会。

## 已归档 Task Store

旧 `task` 命令和执行链已退出当前安装包。原记录、原结果、历史代码/版本包及拒绝、UNKNOWN 保持原位；按明确来源读取原件，把仍有效义务交现有原生任务和原责任承接，不将旧状态迁入另一份权威表。

历史 external_condition 等未分类字段可能表示等待或取消；未核原来源不能重分类或清除。已受拒的 TaskStore/effects 核收写回不能通过新任务、改路径、其他工具或新条件 ID 重试。历史源码可从原仓已发布版本找回，但可恢复不代表获准执行，也不要求当前包保留整套旧链路。

源码关系校验、实际权限、原责任对条件的判断及最终效果分别取证；历史 pending 或 accepted 标志不能独自决定当前需求是否完成。
