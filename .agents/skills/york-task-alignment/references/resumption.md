# 接续、纠偏与受阻判断

仅在接续信息不足、目标冲突、重复纠偏或局部失败时读取；普通首次工作使用 [工作生命周期](../SKILL.md)。

接续先复用适用规范和业务结论；当前资料不足以还原关键决定、与新要求冲突或同一需求反复纠偏时，再回读相关原生任务和原始要求，不要求每次重读全部历史。资料中的历史“本期不做”不是长期限制。较新的直接用户纠正优先于较早委托和转交摘要，后者分别判为仍待处理、背景或已被替代；不能先从旧目标生成本轮答案再查新消息。影响判断的来源尚不明确时，只暂缓依赖它的决定。

用户纠偏后，撤销依赖错误前提的决定，同步修正方案、代码、文档和测试预期，保留其他有效目标及成果。误将局部问题扩大为全局暂停时，按最新用户范围恢复合法分支；原取消、平台拒绝、在途副作用和真实共享冲突分别保留，不能随纠偏清空。从完整需求核对入口、生产者、条件传递、消费者、失败处理及最终结果；用户指出的缺陷不是穷尽清单。查证与实施边界使用 [工程方法](../../york-engineering/SKILL.md)，故障所属层、原规模复验及资源恢复按全局和 [工作站](../../york-workstation/SKILL.md) 处理。

失败后先保留原失败、版本和有效成果；按当前剩余步骤区分直接拒绝、已证依赖、未执行和结果未知。平台拒绝无新相关事实时，不更换线程、工具、通道或执行节点重试同一对象、目的地和副作用；新事实出现仅在原目标及原生入口作有限复核。局部拒绝不撤销其他既有授权。需要来源、去重、预算、共享冲突或关闭判断时，按 [即时检查](execution-check.md) 选择相应模式，检查只能核对给定关系，不能认证原件、授予权限或发现遗漏步骤。

交接 Timeout 或返回未知先按结果不明处理，不写成拒绝、已接收或已执行；定向回读原动作和目标任务的新输入、版本、在途与副作用，原件不可读即保持该环节未知。同一资源不同入口沿用同一副作用身份、冲突及恢复事实，不能换入口重放未知效果；晚到 healthy、后续命令成功或另一范围通过不能覆盖原超时或未验效果。已有同项在途或结果则复用，不重复派发；真实通道不可用或缺直接消息授权时，该交接保持未发送或未知，交有授权协调方处置，本任务继续无依赖工作，不换通道绕过拒绝；确需由另一已有任务承接时先核对晚到风险、当前文件差异和写入范围，保留原发送方的结果回收责任。取消与硬拒绝停止其对象和效果，不能以替代承接、换措辞或新线程规避。阶段完成后的全目标回看、合法派发、接收及结果回收沿[工作生命周期](../SKILL.md#实施、回收和交付)执行；消息权限缺口交回具备相应授权的协调方，其余本任务可做工作继续。

当前代码、现场排查与环境治理分别保留目标和完成标准，按用户顺序及已证依赖处理，未指定时优先代码；允许并行时继续无依赖分支。环境方案待对齐、Docker 离线或 OOM 不产生对代码及离线验证的全局暂停。必要现场事实只作为相应步骤的有界输入；排查返回交原处理落实，晚到结果先比对当前版本，不修改旁任务或反向覆盖新成果。职责与变更范围统一见[工作生命周期](../SKILL.md#职责与新问题)。多对象工作复用共性准备，按业务差异判断无需修改、补绑定、必要实现或证据缺口，已确认批次继续。跨节点按 [多机任务分工](../../york-workstation/references/environment-sync.md#按依赖拆分多机任务) 指定执行机和交接，不迁移真实数据、运行状态或调度来规避边界。

记录可用已有对话、方案或简短笔记，仅帮助定位目标、决定、代码和待办。缺失或陈旧不产生占用或阻止已有授权内工作；不强制 UUID、资源绑定、签名、目录租约、台账修复或独立交接文件。历史记录也不能补造未知事实。只有确需新用户取舍、数据目的地、权限、费用或不可恢复删除时，提出该具体决定；不让泛化许可问题替代可做的查证和修复。

## 反复纠偏时扩大范围综合对齐

同一需求反复被纠正时，此前划定的分析范围和已有方案本身就是待复核对象。反复纠偏已构成扩大查证的依据，无需先证明范围外存在缺陷，也不能只在当前改动内换一种解释或继续补丁。

综合回读原始需求、仍有效的纠偏及历史方案，对照修改前版本、相关演进版本、项目适用基准与当前实现。比较来源按实际任务、版本历史和用户指定来源识别，不固化分支名、变量名或版本入口；指定来源纳入比较，不自动成为范围上限。当前代码用于核对现状，历史版本用于还原演变，二者均不能反向定义需求，也不因版本更早就认定其正确。

从完整需求重新检查业务入口、处理路径、上下游、关联配置和最终结果，主动寻找此前遗漏的文件、模块、仓库或业务路径。当前改动清单、已有方案和已知依赖均不能限定比较范围；最小改动等实现偏好不能压缩必要的理解与比较。扩大比较用于取得事实，具体修改依据有效需求与核实结果确定，不从猜测直接推导兼容处理或扩大实施范围。

综合判断后重新确定完整方案，修正受影响的实现、文档和测试预期，保留其他有效要求与成果；回看旧版不等于回滚、覆盖当前工作或重建分支。比较持续到足以解释偏差、确认完整需求覆盖和必要修改，不能以当前局部正确或旧测试通过提前结束。资料缺失时明确受影响的判断与证据缺口，继续独立工作，不以当前代码补造历史意图，也不将回溯变成所有任务的固定流程。

较复杂的工作可沿用 `${CODEX_HOME:-$HOME/.codex}/workflows/works/<work_id>/alignment.md` 记录关键决定。该位置和格式只是方便接续的选择，不是执行条件。历史 `resources.json` 等记录不产生独占权，也不要求原任务释放或归档。

前瞻结论及依赖范围按[可验证结论生命周期](decision-lifecycle.md)维护；未知前序只限制依赖它的推演，不阻塞事实纠错、独立新事实研究及有据风险响应。
