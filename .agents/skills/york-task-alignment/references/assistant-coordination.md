# 共识整理、任务追踪、进度核收与后继

在需要协调职责、交接、集成或阶段接续时使用本方法；普通单项操作无需加载整套协调流程。助手在真实可用回合落实[需求到交付](../SKILL.md)，异常按[条件与恢复](task-conditions.md)。核心 GitHub 持有通用方法、契约、模板和工具；用户资源及原系统工作站持有私人共识、需求、实际任务与结果。领域 owner 保留需求、专业判断与核收责任；协调身份不转移领域终责。

项目归属、迁移交付跟进、验收及调度承接由助手在原任务持久入口负责；真实路径、仓库映射、本机配置和具体维护归工作站。核心只保留稳定通用职责与正常安装解析能力，不持有私人项目清单、具体地址或节点迁移细则；记录了分工仍须回收原执行者的实际读取和采用结果。

助手管理任务的责任、用户对具体动作的委托和平台是否准许执行分别核对。用户明确的归属纠正及可用原生界面证据用于核对管理责任，工具缺少 owner 字段只表示该接口未提供，不能据此否定已确认归属、要求用户重复证明或将接续责任退给用户；管理责任本身也不解除具体动作的拒绝。

平台拒绝出现后，立即按[执行异常的自行纠偏](../SKILL.md#执行异常的自行纠偏)核原授权、准确拒绝和正式恢复机制。助手持有的协调问题不改派成“等用户在聊天授权/重新发起”；保留原责任与未完结果，推进独立获准步骤。没有可核实的恢复入口时如实报告平台能力缺口，不以一句“仍缺授权”替代原因判断，也不承诺未实际运行的恢复或跟踪。

## 职责、切片与交接

按当前问题与预期结果识别责任：核心提供通用方法，业务系统持需求、业务语义、规范/执行要求、验收标准和实际效果，本地项目持工程实现、测试、修复及原件；业务侧不收工程原件或管理工程版本表。模型编排将适用要求交选定机器执行并核验，机器不裁量是否采用；职责不形成固定层级、串行管道或新平台，交易保留自身专业语义。

切片以可独立实施、验证和收尾的用户结果为单位，贯穿所需生产消费路径；不按目录、技术层或 Skill 名称机械拆分。规范修订、工程重构、分发安装、消费者采用与领域结果保留各自输入、产出、真实依赖、主写范围和完成条件。优先复用既有责任，当前片完成及时交付，后继未完义务不因拆分消失，也不将所有阶段塞入一个回合。页面效果按[业务交付](../../york-engineering/references/business-workflow.md#以实现为依据的文档与交互交付)承接约定的实际接口、登录、交互和目的地；正式前端代码、未要求页面或发布不自动纳入，已有范围内授权继续复用。

编排前核会改变范围、顺序、兼容、资源处置或验收门槛的判断：来源能支持什么、适用于哪个对象、哪些仍未知。转述、摘要、任务创建和压缩保留出处及证据状态，重复出现或更确定措辞不升级证据。无依据的方案外安排撤回；查证通过仅使选项有依据，不自动扩展实施授权。非强制防护说明理由、成本及退出条件，不能自证风险。

只将确切缺失的输入、能力、共享契约、写入窗口或验收结果传给真实消费者，并说明影响理由。环境故障不扣住无依赖代码与离线验证。OpenAI 能力核验按[官方依据](../../york-engineering/references/openai-capability-basis.md)，官方没有业务细节不构成业务禁止；项目契约仍按工程方法核实。工作站资源使用[角色与处置](../../york-workstation/references/resource-lifecycle.md#资源角色与处置)核用途、重建契约、容量和在途依赖；共享标签不触发固定热接管或保旧流程，安全停旧与新增负载分别判断。

处理责任负责方案、实现、自测、修正和获准交付；只读排查仅交证据、影响及限制，不修改旁任务或其优先级，也不撤销原父目标和兄弟任务的有效实施授权。准备/诊断转实施或限制与旧授权冲突时，核原提出者、请求、对象、副作用、阶段及期限；模型选择的保守办法与“本轮不执行”不升格为永久用户禁令。已证风险只停止获准范围内受影响动作。

交接说明完整当前目标、必要输入/版本、数据位置、允许影响和回传范围、交付证据、实施/集成/适用独验责任及失败归属。争议限制保留原消息或工具引用，区分直接用户原文、委托、模型自限和平台回执；这些来源信息不转译为批准凭据。仅真实重叠写入才协调主写或集成，不设整仓占用、永久文件锁、强制分支/worktree 或逐动作授权库。与最新目标一致的未提交差异主动纳入候选并共同验证，未知内容先保护；新共识替代旧行为时同步修实现及测试，不为兼容长期双轨。仍有效接口、持久数据和消费者按事实保留迁移、回退及退出条件。

## 从来源承接共识

从原用户消息、原需求/规范及已核事实识别当前有效项，分别记录原件引用、来源等级、最小必要摘录、模型解释、适用系统/对象/阶段/版本和未决问题。经可信委托收到的用户原文保留其实际委托来源，不冒称直接读过原会话。摘要或别的任务同意只能定位原件，不能升级为用户确认。区分要求、已观察事实、未来目标与实施建议。

原文纠正产生新共识版本及明确替代关系，旧版本和出处保留；回看基于旧前提形成的依赖、暂停、兼容和验收要求，只撤销失去依据的项。不同对象/阶段不按时间一刀切；跨来源顺序不明则冻结依赖它的决定，继续独立工作。新内容写回对应权威并读回，核活跃消费者实际收到及采用；文件存在、发送 ACK、安装完成分别不能签采用。

目标、范围、验收或授权变化递增需求 `input_revision`；目标内实现路径、参数、分工与记录修补只更新 `plan_revision`。新任务 ID、owner 或节点名称不清除同对象/目的地/副作用的拒绝、在途或 UNKNOWN。

## 受理和返回时盘点

盘点围绕仍有效主线：已核收范围、原在途任务、已到待审结果、可做后继、具体阻断和取消。只刷新影响本轮派发、等待、优先级或关闭的项；稳定适用成果复用，不全量重读历史。按原请求/输入/对象/版本定位原件，记录源观察与本次读取时刻、原生轮次及截断；重读不刷新事实。旧运行快照只能说“截至当时在途，当前待核”。入口 unsupported、空 turns 或读取失败只证明该入口可见性缺口，不改写业务结果。

原件 JSON 较大时可按[原件上下文读取](context-reading.md)先定位字段再取所需正文，复用有界分页和所选内容变化判断。结构目录不等于已读完要求；原目标、有效纠正、失败/拒绝和 UNKNOWN 等实际判断所需内容仍须读取，工具不替代原生消息接续或核收。

依赖说明生产者提供什么、消费者为何必须取得、必要版本/对象及依据。hypothesis/unknown 不能自动升级全局硬阻断；新节点故障只限制真实消费者。用户当前指定顺序和停止要求优先，其次实际必要依赖与主线可交付结果。纯汇总滞后不阻已验交付，用户明确要求的原清单仍由原责任补齐。

同请求未完、失败续修或同效果在途复用原任务，先核原结果，不能重复派发。新问题若是原目标缺陷，交原责任续修；确有独立结果、验收和收尾才另定范围。当前已完成工程及时关闭，不将独立领域义务或新问题无限塞回已完成发布任务。同仓目录不构成整仓占用，按实际重叠修改保护并集成双方有效内容。

承接时明确原请求/需求、当前输入和计划修订、准确共识版本、目标及不含范围、验收、执行者/交付 owner、主写对象、节点/数据位置、原生绑定、真实依赖及停止条件。已有 Task Store 只用其原字段；普通小任务不为本方法新建表单或登记。节点 A 能力不代签 B，节点/owner 字符串不认证身份或授予权限。

## 待办安排与阶段承接

推进安排先总结真实待办：仍有效需求、当前实际问题、已到待核收成果及其缺口。按用户优先级、真实依赖和可并行性安排，每项说明当前事实、下一实际动作、预期交付及验收；已有记录足够就复用，不要求固定表单、时间表或新任务平台。用户确有时限、到期条件或既有调度时保留其约束，不能以时点表代替事项安排，也不以整理完成代替执行。

待办同时涵盖当前阶段收尾、下一阶段承接准备与实际开始。提前明确后继复用什么能力、读取什么成果、由谁执行和核收、依赖哪些真实结果；无依赖项在原授权内开始，有依赖项只等待对应结果，不等整个当前阶段结束才准备或启动。已有持续维护沿原入口继续，不重复创建任务或把再次登记冒称新启动；未完问题不因转交后继而变成通过。

从当前真实需要核对旧成果和资源的用途、可达性、版本及消费者。可用的直接复用；已无法消费的旧成果或安排退出活动依赖，保留原件、原因和追溯关系作可逆归档，必要时在已界定范围重建缺失交付，不无限寻找旧文件或要求用户重设计已明确的目标。归档不完成对应需求，也不授权停止服务、删除仍有用途的回退资源或处置结果未知的在途操作；真实资源生命周期和动作边界仍按原方法判断。

安排之后沿已有原执行入口实施、验证并回收实际结果。选择适用专业方法，分别判断专业结果和具体实施证据；字段齐全、文档增加或列出责任人不代交付。可独立验收的范围及时交付，失败仅限制其真实依赖，其余工作继续，不新增逐步经过父聊天的运行依赖。

## 结果与数据边界

原请求、实际 thread/turn/item 身份和原结果引用关联本次工作；机器核收读取原结果，聊天 final 正常说明，不要求全文与自定义 JSON 一致。可选适配及旧请求恢复见[原结果交接](result-handoff.md)。原生任务和既有调度提供执行机会；旧 task-runtime 已归档退出当前入口，现存义务由原责任按原身份和原结果承接，未决效果不重放。

交接前分别核对本地读取、进入模型上下文、跨聊天和公开发布；只传允许的最小结论及结果引用。文档/JSON 自报字段不提供权限，详见[数据流边界](../../york-workstation/references/environment-sync.md#读取模型上下文交接与发布)。

## 核收和真实接续

需要跨越多次修复/调查才能判断根治的具体问题，按[问题持续处置](issue-continuity.md)把目标、问题事实与有限阶段分开持有。先回收匹配的真实结果，再由模型选择下一证据路径；一个补丁涉及多问题仍分别验收。旧的后继/停止记录只适用于当时的证据，本次新返回或纠正必须重新判断，不能永久消除后继责任。缺少原承载时可用 `coordination` 的 goals 快照及只读 `goal-review`，这不是新的执行器、总任务表或调度。

执行者在原授权内完成实施、自测、修正和有界交付，交事实、原结果及未完义务。原交付 owner 按同请求、输入、对象、版本、实际产物与目标效果实质核收。诊断只关闭排查范围；局部 PASS 只证所测范围；原生 completed 只结束对应轮次；报告生成、传输、收件及用户收到分别核。工程完成及时关闭，剩余采用/领域/集成义务归其原责任，不能因未收尾总表把有效成果退回待实施。

交付完成、独立验收、原执行责任核收及阶段整体结论分别登记其实际范围。已完成且核收的项移出活动待办，保留证据；整个阶段达到原完成条件并核收后归档，不能用局部通过关闭整阶段，也不因后续无关观察未结束而永久保留已完成项。

可立即验证的变更，先沿受支持的真实入口执行并核对实际效果；失败或结果不明先修正再定向复验，不等待自然运行代替功能验证。本项适用的立即验证、必要独验及原责任核收通过后，关闭对应实施待办，推进无依赖的下一项；自然运行及长期效果另列非阻塞观察。观察尚未发生不等于实施未完成，不为此每轮等待、重复验证或重开已完成项。观察发现真实缺陷时，保留原结果，按具体问题进入修复。

只有需求本身必须由真实自然事件证明的能力，才保留对应局部验收和依赖，明确需发生的事件、观察范围、判据及结束条件，其余已通过范围照常退出和接续。立即验证不能冒签自然触发、跨周期效果或长期稳定；这些未证范围也不能泛化为全部实施及后继工作的门槛。

阶段验收、退出确认、后继准入和实际启动分别判断。达到原完成条件并核收后，明确本阶段退出结论，移出活动清单并保留历史；未满足的本阶段义务不因转交后继而完成。再按下一阶段的真实目标、必需输入、可用资源、依赖及验收条件，说明可进入、部分可进入或暂不可进入的范围和依据；只让缺失条件限制其真实依赖，不追加无关观察或新门槛。

准入成立后沿现有合法执行入口启动无依赖事项，保存实际读取承接输入、执行结果和责任核收的证据；准入判断、安排或发送成功不代替实际开始。有依赖项保留具体缺项及其满足后的下一动作，不能把等待写成运行。若后继只是既有持续运行维护，明确进入运行维护及当前可执行范围，复用已经开始的工作，不虚构新建设阶段、重复启动或为此建立中央协调。

核收写原系统记录后回看有效目标，本回合有合法可做项就执行；已有原责任在途则回收进展；确需交接时沿已获消息授权、当前支持的原入口。下一动作实际返回后再次核收、继续或给具体合法停止依据。OPEN、列 owner 或承诺继续不等于后继。没有执行机会时说明真实下一触发条件，不承诺后台推进；既有兜底按用户控制的原范围运行，不新增/修改调度。

普通已知失败由原责任核可控调用、实现和约束传播，保存旧失败，修正后定向验证；不重新泛化索取管理权限。明确拒绝停同效果，UNKNOWN 先核原允许可见状态，不换任务、sender、工具或节点补发。原[执行检查](execution-check.md)只可选消费有限关系，不认证原件、不批准重试，也不是发布、核收或小任务必经门禁。

## 组合验收与有限交付

分项独验、集成与领域验收分别回答对应要求。要求独验时，由独立责任按冻结的代码、数据或脱敏夹具、环境与预期判通过、失败或未运行，失败交原处理修正并复验确切新版；普通任务不强制拆成多个会话。组件独立通过后，原集成责任仍需合入统一候选，按实际交互和原失败路径作组合回归；原目标要求多项目组合时保留适用独立跨线回归，不能拼接不同版本的 PASS。相同内容且范围适用的证据复用，变动与组合风险定向复验。

回收核当前原生请求/输入身份、版本、对象及原产物引用，不能凭报告标题、同义词、类型一致或 check ready 认定本轮完成。原任务 spec 已有 project、assignment、request_identity 等字段时复用其关系，不把字段当执行权限或要求普通任务补登记。连续委托将仍有效旧目标及其出处带入后续上下文；原件在历史里不证明下一执行者已取得。

摘要和交接保留原结果限定、无效对照、未运行和具体拒绝，不能只传版本及 PASS。受控回归故意缺项在验证目的达到并核收后仍作为测试对照，不能复制成真实业务待办；真实未履行义务不因“测试”标签删除。原生结果或格式证据缺失时按[原生补证](execution-check.md#原生补证与结果收讫)处理；已证明的合并或领域效果不为补回执重做，已明确核收的有限结果不作形式循环，旧失败保留。

源码组装、加载可见、实际使用与效果分别判断。原执行责任在各端真实机会落实要求，不等父跨设备逐步读发；共享文件不证明唤醒，版本不同不自动要求全部节点整包升级，缺证也不记为节点可以不采用。定位要求形成、编排、执行及效果中的实际断点，在原授权内修正。晚到排查先核版本及当前内容，不覆盖较新有效成果或令排查方接管。

业务侧核需求效果和剩余问题，本地工程保存源码、版本、测试和日志原件；必要源码可用于核缺陷，但不构成业务版本管理。诊断、资源登记和盘点只关闭已核范围，从剩余未知、整改及反馈关联原目标、责任、下一步和验收，不按每个资源另建任务或台账。规范一致性、自测、独验、发布安装和消费者采用分别交付，不互相倒推。

实际需要 finalization 的组合范围关联当前必需分项、合并/加载证据及适用独立跨线报告，缺少真实功能义务证据保持未完成。原唯一清单及汇总只派生关联和遗漏提示，不作功能验收前置；纯汇总缺失、陈旧或被拒不阻独立交付。用户明确要求的清单仍由原责任完成，不能用 tracking 标签抹去真实功能义务；同库可共享、兼容读取继续，真实冲突只隔离重叠效果及已证消费者。旧占用索引与未解拒绝保持原位，不换任务、项目或入口解除。

## 面向用户的跟进摘要

按已整理待办持续跟进，汇报聚焦问题及安排、预期结果、实际交付与验收、阶段退出结论、下一阶段准入结论及已经开始的实际事项。明确用户查询时据实回答；无实质变化、例行检查或已自行解决的内部重试不单独打扰。影响目标结果、实施路径或阶段条件的变化、实质失败/阻塞，以及确需用户决定的事项及时说明，不把内部噪音堆成进展。

当前进度按最新实际执行和验收证据更新，不为与前次报告一致锁定旧状态。历史冻结证据保留用于追溯和对应版本验收，不改写旧记录，也不代替当前事实；当前状态未核实则明确保留未知。

摘要降噪不减少执行和取证：完整失败、重试、未知及恢复证据留在原记录，原执行责任仍在真实机会内推进、修正和核收。不能以安静汇报停止工作、隐瞒影响结果的失败，或把尚未执行的等待称为持续运行。具体任务、时点、命令和运行事实归当前任务，通用正文不另持一份进度。

## 持久承载及可达边界

三个数据角色是共识来源/修订、任务范围/依赖/归属、进度事实/核收/后继。先逐字段映射原文件及 JSON pointer、唯一写入者和读回入口；已有唯一清单或系统结果足够时直接复用，缺什么才补什么。私人共识可索引 canonical 系统文件，不复制领域状态、原生 runs 或第二总任务表。不同角色可以位于同一现有文件，字段权威分别明确；格式缺项准确报缺口，不编造源时刻、owner、终态或 PASS。

需要简单文件侧车且原系统缺机制时，选用[文件契约](coordination-file-contract.md)。跨文件不承诺事务：实际领域动作/计划已成功而进度失败，先查原对象，再补记录关联，不能重做动作补账；写入 UNKNOWN 同样先读原对象。源更新冲突重读、合并非重叠修改，真实语义冲突由对应 owner 处理。

跨端交接在已支持且已授权的原生入口指出系统、原请求、准确文件/字段范围、版本、只读或写入及允许回传内容。原 owner 在自己的节点读取，返回源身份、文件/修订或事件区间、源观察和本次读取时刻、必要内容及限制；写请求另带准确变更和 expected_revision，由原写入者执行并读回。这是交接内容，不能杜撰平台工具参数或把本机路径当共享磁盘。没有合法入口只报告该对象不可读/回写，沿原责任处理，独立工作继续。

公开核心只保存通用规范、可复用代码、模板与小型合成样本构造逻辑；聊天原文、个人资产、业务数据、配置、凭据、现场证据留原节点。源码/自测、独验、发布、节点安装、正常入口加载、会话读取、实际使用和长期效果分别验收。文件接口存在不代表助手平台自动或强制采用，也不提供唤醒、权限、身份认证或自由文本领域判断。
