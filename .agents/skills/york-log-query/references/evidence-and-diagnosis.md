# 原始证据与异常定位

## 读取与使用

通过当前授权的只读入口读取、搜索并关联诊断所需原始业务日志；不要求先删关键字段或让用户重新提供有效认证才能调查。证据访问、聊天展示与长期保存是不同动作：仅引用必要片段，不把完整认证、支付凭据或运行日志原文复制到 Skill、设计文档、记忆或 Git。内部读取范围不因外部展示要求被提前裁剪；对外载荷的脱敏仍按其真实契约。

优先目标服务配置、安全凭据提供方和既有登录态，凭据在已有受保护通道中使用，不提取浏览器 Cookie 或会话存储。日志平台查询请求可以使用其实际 API；HTTP 方法本身不裁决读写性质。禁止以修改索引、Data View、角色、模板、告警或保存查询对象补齐读取能力。

## 既有对接的修改边界

代码处理先从适用语义、源码、配置和已有样本确定实际缺口；接入来源或变更原因影响判断时再查提交历史。只有修改依赖尚未确认的现行行为时，补取相关配置或请求响应，不把提交年龄、响应字段变动或历史调查流程作为重新核查部署和完整链路的理由。现场归因需要对应实际实例与事件的证据，本地代码结论不能替代。

- 围绕本次变化选择能区分疑点的成功或异常请求、响应及必要的相邻阶段，核对实际接口、运行上下文和代码处理位置。证据足以确定边界时停止扩大调查；不要求每次取得所有分支的日志。
- 区分已观察行为、对应接口的协议依据、用户新增的业务目标和待验证假设。用户目标规定发生条件后如何处理，不自动定义第三方如何表达该条件；不能因同一厂商、错误文案或常量就把错误码与响应结构推广到其他接口。
- 用证据决定最小修改，保留不受目标影响的请求构造、成功判断和副作用。复用响应处理器或增加重试前，核对其实际异常转换与附带写入，不能仅凭方法名判断等价。
- 未观察到但有对应接口依据的条件，可以用构造样本验证新增行为；样本通过不反向证明线上已发生。证据不足时说明受影响的结论和下一证据入口，仅暂缓依赖该前提的修改，继续当前代码批次中有依据的事项；不自动转入另一条线上调查。暂缓不等于取消目标，未完成要求按 [任务对齐](../../york-task-alignment/SKILL.md) 保留；撤回假设实现或改变副作用前，核对是否同时切断其他仍须保留的能力，不能把有共同依赖的修改当成独立完成。

没有既有运行记录的新接入，可以按对应协议和隔离验证推进。取证不重放生产业务请求；原文读取、展示和夹具保存沿用上方边界。

## 依据证据选择定位方法

从已观察现象与适用契约提出候选解释，明确缺少什么事实、它影响哪个决定，再选择能区分疑点的必要证据入口。候选解释可以引导查证比较，不能作为后续实现、兼容、回退或扩大修复范围的依据，即使标为风险也不能先行采用。反复纠偏时按 [综合对齐](../../york-task-alignment/SKILL.md#反复纠偏时扩大范围综合对齐) 扩大比较，既有范围是否遗漏完整需求本身也属于待核对问题。日志、源码、运行状态、存储查询和本地验证按需要组合；已有证据足以回答相应问题时即可结束该项取证，证实候选不成立时撤销依赖它的步骤，不为补齐流程继续扩查。

- 关联证据时，核对对象、时间、时区及实际可用字段，按问题需要关联请求、响应或处理结果；不要求所有链路都有 traceId。
- 在线上诊断中用源码归因到实际实例时，核实相应部署版本及相关配置，需要时按授权同步代码。构建成功或默认分支一致不证明实例运行该版本；尚未确认的源码结论保留为候选，不把部署核查扩展为无关代码修改的前置。
- 上游已有记录而下游缺失时，可沿相关消费路径查找记录变化或丢失的位置。映射覆盖、默认值、提前返回、continue 和分组条件是待核对入口；只有证据确认相应条件与记录变化，才能据此归因或决定修改。入口或“转换开始”日志不证明通过后续处理。
- 本地验证能区分当前疑点时，复用已有工作站和输入；已有资源降低准备成本，不单独构成回放理由。需要准备数据时使用 [本地数据方法](../../york-local-data/SKILL.md)，真实依赖断言见 [通用验证](../../york-engineering/references/dependency-testing.md)。验证范围由待证明的结论决定。

第三方结果应结合当前请求/响应、供应商官方协议或状态证据判断。平台返回、落地页、后台 API 原文、服务日志和数据库结果属于不同阶段，不能相互替代。遇到错误时定位实际产生、捕获、转换、重试与降级路径；同名错误常量不证明请求命中对应路径。

服务调用已发生而 API 原文缺失时，沿实际异步保存及存储实现查失败。无命中先校对时区、来源、字段、筛选和覆盖范围，不直接断言未调用；数据库当前无记录也不单独证明从未写入。

只有能对应事发对象、实际失败或静默丢弃路径及触发条件的证据，才能支持现场归因。本地成功只说明所测条件下路径可行，假设夹具只证明条件行为；本地额外异常需对照现场版本、触发条件和影响分布，不能直接移作现场原因。诊断程序错误或夹具差异只影响相应结论；来源不可用时，围绕当前诊断问题选择确能补齐缺口的其他证据，缺失输入和假设如实说明。仍缺关键证据时，说明已证实边界，并按剩余疑点选择下一入口，不因此把诊断与代码批次交错执行。

日志与版本入口见 [本机操作](local-log-operations.md)。不为获取证据重放生产资金或业务请求，也不把普通日志查询扩展为完整事故调查。
