# 线上数据库只读查询与结果复制

用于线上 MongoDB / StarRocks 记录核验、漏单或落库排查、两端数据差异，以及将任务所需查询结果复制到本地工作站或测试环境。根据当前疑点选择数据库、日志或后台证据，已有证据足够时停止扩查，不要求每次查询两端。

## DataGrip 入口与只读边界

- 线上数据库访问仅使用 DataGrip，复用现有连接，通过当前可用的原生应用操作工具读取和操作界面。线上查询和结果读取使用 DataGrip 自身能力，不增加命令行、脚本、驱动直连或外部 dump 工具，不从连接配置或凭据存储提取密码。DataGrip 不可用时说明受影响的具体判断，复用已有结果推进当前工作线中不依赖该查询的部分，不自动切入另一条调查线。
- 从当前界面确认查询编辑器绑定的数据源、数据库、集合或表及站点归属。本机已有生产 MongoDB 和线上 StarRocks 连接，与测试连接共处于名为“测试环境”的 DataGrip 项目；这是入口线索，使用时仍核对实际连接。项目名、连接名或驱动名称不能单独证明环境和数据库产品，不把连接地址、账号或连接串复制到 Skill。
- 线上账号默认按只有查询权限操作，仅查询数据和读取必要的结构、字段或索引信息。不试写验证权限，不修改线上业务数据、索引、配置或权限，也不用写后回滚验证。连接成功或界面的只读标记不等于已核实服务端权限；权限不足时保留实际错误，不换用高权限账号。只读约束适用于线上源端，查询结果复制到本地或测试目标的写入按下方范围处理。
- 执行前核对本次语句及绑定对象，只执行所需的只读片段，避免运行旧控制台中的整份脚本。MongoDB 使用查找或不含写入阶段的聚合，排除 `$out`、`$merge`；StarRocks 使用查询及必要的元数据读取，不通过建表、写临时表或服务端导出落地中间结果。

## 查询范围与结果解释

- 查询前明确要回答的问题、需要返回的字段或分组结果，以及结果如何影响当前决定。按业务问题选择对象、关联标识、站点、时间窗和必要字段；已有结构与适用样本直接复用，仅结构或类型不明时先取少量样本。
- 同单定位按业务键读取相关状态、时间及必要的相邻字段；统计直接返回按业务维度分组的总数、缺失数或异常数，不先复制全量明细再统计。调试或回放确需原始记录时，才复制能支持相应断言的记录与必要关联；统计范围由本次要求确定，不固定为所有站点或某个天数。
- 优先让结果以可完整读取的紧凑行列返回，避免把大量分段明细嵌套到一个单元格。需要更多数据时按时间或稳定标识分段，合并所需统计并核对边界、重复和截断；保留已成功取得的部分，只补查缺失范围，不自动扩大为整库读取。
- 查询、执行控件或结果读取失败时，先区分查询失败、未执行、复制失败和展示截断，再调整对应方法；没有新依据不反复执行相同查询或试探同一控件。已有结果足够回答问题时结束取数，转入相应结论或修改，不为完善展示继续耗时。
- 区分业务时间、入库时间和更新时间，核对时区及秒、毫秒、日期类型。查询条件结合实际索引或分区范围；结果条数限制不等于扫描范围受限，大范围聚合或排序先缩小范围，必要时在 DataGrip 查看查询计划。
- MongoDB / StarRocks 对照先核对实际业务键、站点、字段映射、金额精度、状态含义及同步链路。不要假定两端行粒度、唯一性、时间口径或可见时点一致；只在当前问题需要时沿生产者、转换、写入、同步和读取路径关联日志与代码。
- 无结果先检查环境、对象、字段类型、时间窗、残留筛选和分页覆盖。单次空结果不证明从未写入；一端有记录也不证明另一端已同步或后台展示正确。分别说明已观察结果、查询覆盖及仍缺证据，不把本地假设当成线上事实。

## 将查询结果复制到本地工作站或测试环境

- 用户允许将任务所需查询结果复制到本地工作站或测试环境，用于分析、调试和验证；目标可为文件、调试数据集或相应数据库表、集合。目标与数据范围明确时自主完成所需复制和目标端写入，无需为此类操作重复确认。只读要求始终保留在线上源端。
- 复制前核对线上来源和实际目标身份、库、表或集合、站点及数据范围；测试环境在本场景可作为写入目标。结合已有结构、键冲突及消费者确定写入方式，保护目标既有数据，不把查询结果复制扩大为整表替换、整库同步或无关清理。只有目标或覆盖范围无法自行确定时，澄清对应缺口。
- 根据数据量和目标选择结果复制、必要的中间文件或现有导入能力，文件中转是可选手段。本地分析或目标导入可使用已有工具、脚本和目标连接，但不能由这些工具重新直连线上取数；不能仅因 dbctl 支持测试源到本地同步，就假定它支持向测试环境写入。
- 区分当前页选中行与完整查询结果；查询限制、执行中断及时间分段均影响完整性。获取所需结果后核对条数、字段、边界样本、重复和截断；写入目标后回读核对目标记录及必要关联，复制成功与业务验证分别说明。
- 保留 ObjectId、日期、长整数、Decimal、金额精度、时区、长编号、空字符串及 NULL 的含义；目标结构不同时先核对字段映射和类型兼容。需要文件中转时，MongoDB 优先 Extended JSON，StarRocks 默认带表头 CSV；不让分析或导入工具把标识自动转成数值，或把金额转成有损浮点数。
- 本地数据准备按需参考 [本地数据方法](../../york-local-data/SKILL.md)。必要结果在当前答复中说明来源、目标、复制范围及实际验证，不要求另建报告或必须交付导出文件。凭据和原始生产数据不写入 Skill、记忆或 Git，聊天仅引用支持结论的必要片段。

操作控件以当前 DataGrip 界面为准。查询、结果获取、目标写入或验证失败分别报告，不将未执行的操作报告为成功；Skill 文档验证、实际连接、服务端权限和业务链验收分别说明。
