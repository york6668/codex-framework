# 本机已有日志操作方法

用于查找已有服务日志、核对后台参数或取得浏览器请求证据。普通查询直接选用相关段落，无需启动完整事故调查。目标环境、连接和页面状态在本次访问时核对；原始证据访问与保存使用 [原始证据与异常定位](evidence-and-diagnosis.md)。

## 从现有入口找到环境

- 从接口、模块名或报错定位仓库，再查目标仓库 `.codex/log-sources/*.json`、相关配置和当前已打开页面。父目录没有日志配置时继续到实际服务仓库；不要因此要求用户重给日志地址。
- `platform2-game-center/.codex/log-sources/kibana-production.json` 是已有入口，包含环境、Kibana space、Data View、时间/消息字段、认证提供方和只读动作。读取当前值，不把地址、账号或字段快照复制到新配置。
- 用当前浏览器工具列出已有页面，以标题、URL 和页面内容选择 Mi CC、Mi Boss、Kibana 或 FinderWeb。复用登录态，使用当前工具返回的接口；旧任务的 tab、节点编号与自动化代码不能直接重放。
- 仅盘点入口时先停在页面清单。选择标签可能自动返回已打开的业务日志；确需判定节点时只提取树、frame URL 和必要上下文，不把附带的旧日志当本次查询结果。
- 同一 FinderWeb 入口可以展示多个主机与环境；后台域名、日志平台域名、来源主机与业务请求目标也可能不同。结合当前选中节点、服务、请求目标和已有环境配置判断。明确缺口才询问，不用页面标题单独裁决环境。

## Kibana：按服务日志与 API 日志分别查

1. 按配置进入相应 space 和 Data View，查看当前时间窗口、时区、查询与残留筛选。先用已知错误、接口或关联标识做有界查询，再按结果调整。普通服务日志使用配置声明的时间和消息字段。
2. 需要第三方请求/响应时，继续查 API 日志来源，不能因服务日志里只有调用摘要就结束。游戏中心已有 `gameapi_centerlog-*`；当前索引规则以 `GameCenterApiLogIndex` 为源码入口，月份取 `Asia/Shanghai`。先核对当前索引/字段，不能把这个模式套到其他服务。
3. API 日志的 `startTime`、`endTime` 当前由 `GameApiLogDocumentMapper` 写为 epoch 毫秒。将用户给出的时区和时间窗换算为实际字段需要的值。服务日志的 `@timestamp` 与 API 日志的数值时间不要混用。
4. 先取少量命中确认字段和范围，再取需要的请求、响应、关联标识与相邻阶段。页数、条数、命中总数和时间覆盖相互核对；大范围结果分批读，保留分页位置，避免一次输出整库日志。

游戏中心 API 文档的当前字段为 `api`（接口 URL）、`bodys`（请求正文）、`headers`、`urls`（URL 参数）、`resps`（响应）。后台 `QueryApiLogController` 的 `/m/gameApi/gameCenterLog` 接收 `url` 条件，实际查 `api.keyword`；先用源码确认用户提供的是平台入口还是第三方接口，不能直接互换。字段与查询实现使用前核验；当前 mapper 不提供共同 `traceId`，需结合站点、场馆、时间和请求内容关联服务日志。

已有安全凭据提供方也可供只读查询工具使用。读取配置中的认证方式并在进程内使用；不要把密码输出、写入命令文本或临时脚本。优先已有登录浏览器；使用查询 API 时先核对当前接口与实际操作，只查询/检查字段，不修改索引或保存对象。HTTP POST 本身不等于业务写入，实际后端操作才决定性质。

查询失败时按实际原因继续：

- `number_format_exception`：先查字段类型并修正时间表示，不盲目扩大时间窗。
- 无命中：清点残留条件、校对时区/月份、消息与结构化字段、服务与 API 日志来源，再逐步扩大窗口；一次空结果不证明业务未发生。
- 服务已有调用但 API 原文缺失：沿 `HttpUtils` 的异步保存、`GameCenterApiLogWriter` 与存储实现查当前服务日志中的保存失败，核验入库链；不直接断言第三方未被调用。
- 登录或网络错误：核验当前登录与 [本地网络](../../york-workstation/references/local-network.md)，围绕同一问题选取已有结果或其他适用入口；无法补齐时说明具体缺口，不因入口受阻转入另一条调查线。
- 搜索成功后，核对具体文档时间、接口与对象；成功 HTTP、代理总结或命中总数都不替代目标记录。

## Mi CC / Mi Boss：参数、游戏日志与分页

- 从当前已认证页面的菜单进入目标功能。Mi CC 已有“游戏日志”“品牌方/场馆”“场馆站点参数配置”等入口；确认选中站点、场馆、币种和时间范围后查询。Mi Boss 按其当前菜单与页面字段查找，不假定两套后台页面或接口完全相同。
- 查单次调用时，关联游戏日志中的请求/响应、当前有效参数与前台结果。只读参数页面不自动证明服务缓存采用该值；需要结合运行时调用或版本证据。
- 用户要求整条线路、整个站点或完整异常清单时，先清除与目标无关的残留场馆/关键词筛选。选择页面支持的合适页容量，记录当前范围与总数，逐页或按时间分段扫描；不能把第一页或旧筛选结果当完整清单。
- 线路或站点范围已足以检索时直接推进，先从结果取得账号、订单等关联线索；单个账号或订单不是这类查询的通用前置。
- 当前 game-center 的 `GameApiLogRequest` 只有站点、场馆、时间、URL 和请求/响应条件，没有独立线路字段。线路先从现有后台或配置解析到实际站点集合，再按所用入口支持的方式查询；不能把线路名称硬填 `siteCode`，也不能默认一条线路只有一个站点。
- 当前 `master/gameapilog/service/Elasticsearch7GameApiLogAdapter.searchBody` 使用 `from=(pageNumber-1)*pageSize`、`size=pageSize`，按 `startTime DESC` 排序；起止时间同时提供才产生时间条件，`url` 匹配 `api.keyword`。实际实例的适配器和 mapping 仍需核对。该实现读取 `hits.total.value` 而未解释 `relation`，页面 total 不能独自证明命中总量精确；大范围查询分段去重，必要时回读原始命中关系和时间边界。
- 分页按页码、边界时间或稳定记录标识去重；只保留本任务需要的命中定位和分类。扫描超时后重新取得当前页面状态，从已确认边界继续，缩小单批范围，不重置为无依据的全量结论。
- 分别归纳明确白名单拒绝、其他访问限制、接口/签名/配置错误及无响应。固定耗时的空响应仍需网络或供应商证据；不要统一称为白名单问题。

验证查询结果时同时说明范围与未覆盖页。查看参数、刷新页面或后台查询成功，只证明对应读取；它们不能证明缓存、第三方落地页或业务链已经恢复。缓存刷新、参数更新和调度按钮是另一个操作，查询方法不要求点击它们。

## FinderWeb：主机、服务和轮转文件

- 复用已有 FinderWeb 登录页，先读取当前主机树，确认实际 `host → workspace → service → file`。已有树可能同时含 `mi-pre-env` 与其他节点；节点名称只是定位线索，结合已有环境资料和请求归属确认。
- 按问题时间选择当前实际存在的轮转日志；同一天可能有多个序号文件。使用页面现有查找/grep 视图，按错误、接口或关联标识取上下文。核对视图所示主机、目录和文件名，而不是只看顶层页地址。
- 无命中时检查是否在错误主机、服务、日期或轮转片段，必要时查相邻文件和上游 gateway。页面内嵌 frame 或多个同名控件时，以当前 frame 和文件上下文限定操作。
- 读取状态就绪只说明文件已读。结论还需命中时间、实际日志内容和请求关联；未查询其他节点/片段时保留范围限制。

## 浏览器请求与版本关联

- 平台 `game/start` 返回、实际第三方落地页、后台游戏日志与服务日志是不同环节。按用户目标关联它们；平台成功响应可能与落地失败或异步日志写入失败同时存在。
- 获取请求证据优先使用当前浏览器提供的开发能力。若当前 tab 声明 `cdp`，先读取其文档：观察动作前取得事件游标，之后按返回游标连续读取；`hasMore` 继续分页，`truncated` 表示缺失，不能称为完整抓取。只获取相关请求与响应，不从页面存储提取登录态。
- 已发生的请求不保证仍在事件缓冲中。缺失时使用已有网络面板或对应服务日志；仅在当前任务允许且请求没有不合适副作用时才复现，不为补证据重放生产业务调用。
- 从现有只读构建信息、版本接口或启动日志查运行版本，与相关 checkout 的 HEAD/源码对齐。构建成功并不证明目标实例运行了该版本；多个实例需关联实际命中实例。未对齐时将本地源码保留为候选解释。
- Jenkins、调度平台或参数页面中只读取当前任务所需的既有结果；部署、构建触发、执行一次与缓存更新不是取日志的前置步骤。
