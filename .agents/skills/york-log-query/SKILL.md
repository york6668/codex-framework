# 日志、后台与数据库查询

从用户给出的接口、线路、站点、异常或时间开始，先探索已有入口；只有无法自行取得且影响结论的缺口才询问。普通查询不要求完整事故调查。

代码处理先复用适用协议、mapping、源码、配置和已有样本；当请求、响应解释、异常恢复、重试或降级的修改确实依赖尚未确认的现行行为时，主动补取能区分该疑点的必要证据。已有依据足以决定修改时直接实施，不因触及响应字段就默认查询双库、日志和部署版本。

线上故障归因与代码处理分别组织，执行顺序见 [任务对齐](../york-task-alignment/SKILL.md)。每次取证明确要回答的问题、最小必要结果及其影响的决定；取得结果后结束该次取证或明确仍缺的证据。候选解释可以引导查证比较，未核实前不能据此决定修复、兼容、回退或实施范围；反复纠偏时按任务对齐方法扩大比较、复核原有范围。配置事实、样本核对、缺失统计和现场归因各自证明相应结论，不因某个入口可用就扩大调查，也不把取数成功当成问题已解决。

- [本机日志操作](references/local-log-operations.md)：服务仓库配置与已登录页面发现，Mi CC 分页，Kibana 服务/API 日志，FinderWeb 主机与轮转文件，以及浏览器请求关联。
- [线上数据库只读查询与结果复制](references/production-database-query.md)：需要核验线上 MongoDB / StarRocks 记录、定位落库差异或复用数据时，仅通过 DataGrip 读取线上查询结果，按需复制到本地工作站或测试环境；按问题选择来源，不要求每次查询两端。
- [原始证据与异常定位](references/evidence-and-diagnosis.md)：既有对接的修改边界、读取与展示边界、异常定位及本地验证的适用范围。
- [三方资料发现与读取](../york-provider-docs/SKILL.md)：需要协议或产品依据解释现场时，发现相关文档；文档规定与本次请求响应各自证明相应事实。

读取查询保持源端只读。日志与后台复用有效登录态与安全凭据提供方，不要求用户重复提供；线上数据库仅复用 DataGrip 现有连接，不提取凭据或改用命令行、脚本直连。允许将任务所需查询结果复制到本地工作站或测试环境，包括按明确目标和范围写入相应数据库，无需为此类复制重复确认；源端读取与目标端写入分别核对，具体方法见数据库参考。不以重放生产业务请求、触发构建、刷新缓存或修改参数作为查询前置。

日志平台域名、来源主机与业务请求目标分别核对。结果必须对应本次筛选、时间和对象；第一页、单次空结果、代理总结或历史命中不代表完整结论。
