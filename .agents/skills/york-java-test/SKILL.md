# Java 本机验证

先确定需求、受影响行为与真实风险所需证据，再选择覆盖充分的最小有效测试，复用适用用例与本机工具。已有测试通过只证明覆盖到的行为，旧实现遗漏的需求和错误测试预期也须修正。同批修改按模块和影响范围合并编译及测试，共用准备与公共路径验证整批复用，各产品差异仍由相应断言覆盖，不为每个对象重复完整构建。已确认批次可以先验证，不必等待所有外部资料齐备；通过后仅因新变化、失败或未决风险扩大或重复验证。

测试预期涉及外部约定时，区分协议要求、项目契约和实现假设；影响成功判定、分页或进度的断言须能回到相应依据。当前实现与自造样本通过不能单独证明协议保证。撤销错误假设时同步修正断言，保留仍有效的业务验收。需要补充依据时使用 [三方资料发现与读取](../york-provider-docs/SKILL.md)，已有适用依据可直接使用。

测试入口覆盖待证明的行为及实际错误路径。验证字段生产与消费衔接时，让真实生产者生成该字段，再经过受影响的转换和消费；手工填入目标值只能验证后续消费者，不能证明生产者已接入。预期使用有依据的独立值，不调用被测算法计算预期。修复可复现故障时，先确认所选断言能捕获原症状，再验证修复；补充已有正确行为的覆盖时，无需制造生产故障或扩大重构。

测试是否随源码长期维护，依据其对项目和业务的必要性：优先保留保护核心行为、接口兼容和实际故障风险的回归。与当前任务无关但仍有业务价值的测试继续维护；年代、文件数、行数和历史通过记录不单独决定去留。按业务职责组织用例，复用准备逻辑、合并重复覆盖，修正当前有效测试的错误预期。已失效的历史测试、一次性核验及无持续用途的调试代码直接删除，不为保留历史文件补兼容、重建旧调用链或另行归档；有效的核心业务回归由当前测试维护。普通回归用小样本覆盖边界，有持续价值的压测和真实依赖验证显式按需启用，不增加每次开发的执行负担。

遵守全局源码与数据边界：具备上述长期价值的测试与小型样本构造逻辑随源码维护，生成的数据文件只写临时目录；需要已有样本时从明确的本地位置读取，不随 Git 或源码包提交。一次性验证程序及其结果留在执行环境，合成、脱敏数据同样适用，不能将整份快照编码到脚本中。整理时保留必要断言与覆盖，不设置文件数量指标或另建清理台账；交付检查见 [提交内容](../york-safe-delivery/references/policy.md#提交内容)。

- Maven/JDK 选择、实际本地仓库、跳过测试、JUnit Console 与结果回读：[Maven 测试入口](references/maven-testing.md)。
- SQL、事务、消息、并发，以及业务回放中的依赖与异步断言：[真实依赖断言](references/dependency-testing.md)。

检查所选生命周期及测试实际连接，避免测试顺带发布制品或调用远程业务。常规入口受阻时使用有真实断言的更小入口，说明原路径和替代路径的覆盖。

回读实际目标、内容版本、通过/失败/跳过数量；编译、服务健康、退出码和零用例都不代替行为通过。临时执行配置恢复后核对最终差异，不回退用户修改。本地结果与环境验收分别报告。
