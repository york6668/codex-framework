# Codex 工作站

Mac mini 是数据存储与执行节点；核心框架、长期规范、Skills、引用及可复用源码由所属 GitHub 项目持有、维护和发布。共享框架归 `york6668/codex-framework`，BTC 专属方法归 `york6668/btc-core-strategy`。节点上的文档和 Skills 是部署副本，工作站按这些方法使用实际数据、工具与服务完成任务。

发现已有配置、工具与服务，优先复用；确认缺少任务所需能力时补齐。安装、替换、回退和数据处理依据实际身份、适用条件与操作结果决定；未确认的缺失、容量或兼容问题只用于确定必要验证，不能先据此新增环境或扩大处理范围。工作站提供 Codex 云端配置和本机资源的共同入口，当前任务维护目标、计划和进度。GitHub 是项目来源，Codex 云端执行环境是可选运行位置，不能将两者统称为“云端”并推导出必须中转。

核心框架定义环境准备、数据同步及生命周期的职责、策略设置、默认行为和预期结果。各台 Mac 或其他执行节点的数据单元负责发现实际环境、选择或补齐工具、保存节点配置、执行并核验结果；数据单元指承担这些职责的具体节点资源与实现，不要求统一程序、目录或配置格式。

工作站异常状态有固定入口：启动或恢复时先用已注入的 `SessionStart` 摘要；没有摘要时只读运行 `codex-framework workstation-entry`，它直接读取节点的 `workstation/observation-sources.json`。清单缺失或不可读即为未知，不用 `rg --files`、`find` 或递归遍历工作站来寻找替代配置。仅对与当前任务相关的具体异常，按清单中的来源路径和运行 ID 定向读取有界原件；单个观察入口失败不打断无依赖工作，保留待处理和恢复点。

环境准备沿项目实际配置识别配置中心和候选环境；存在多个候选且当前任务尚未明确选择时由用户确认，已有选择继续沿用。读取选定环境发布的服务配置与注册信息，追踪动态数据源，保存本地发现结果，再按任务需要准备服务和数据。资源身份、临时入口、认证状态与操作权限分别判断；一次失败仅影响对应操作，具体见 [环境发现与同步](references/environment-sync.md)。环境名、地址、凭据变量和数据范围均从实际来源取得，不把本次选择固化为共享默认。

- 工作站入口优先使用环境安装说明明确的位置；未指定时查看 `${CODEX_HOME:-$HOME/.codex}/workstation/README.md` 和 `$HOME/.codex/workstation/README.md`，也可从框架源码的 `.codex/workstation/README.md` 读取。平台运行时 `CODEX_HOME` 与框架安装位置可能不同，不能仅凭前者缺少文件认定规范未安装。入口已定位后沿用，其中的配置名称、来源、适用范围及本机线索以任务已取得的配置和实际连接核验可用性。
- 配置与认证默认先使用已有的 Codex 云端配置或原生连接。当前任务可直接访问 GitHub 时直接读取目标项目；当前入口无法使用时，再检查本机已有 Git/SSH、认证工具及配置。沿用实际配置名称和类型，不构造未配置的变量、别名或逐仓凭据要求。
- 已知 Codex 云端有配置但当前任务无法取得时，核对环境是否请求已有配置键及是否已提供给任务。需要 Codex 云端执行或核验时，使用当前可用的原生任务发现、读取接口，并按用户授权向对应任务发送请求和回读结果；只返回来源、可用性和操作结果。没有适用执行入口时说明访问缺口，不能仅凭本地缺少变量认定 Codex 云端未配置，也不能用任务列表失败代替 GitHub 连接核验。取得配置后认证失败属于访问验证问题，按实际错误处理，不冒充未配置或自动新建凭据。
- 创建或修改脚本、CI 和部署流程前，核对实际执行环境及目标操作可复用的授权能力。不得假定某个 secret、环境变量或凭据名称存在，并将其写成强制前提再要求用户补配；模板占位不代表已经配置或必须采用该认证方式。
- Codex 原生连接、本机进程、Codex 云端执行环境和 GitHub Actions 分别核验。一个入口成功不代表其他环境自动继承认证，一个入口失败也不代表其他环境没有配置；连接器可以读取源码，不证明任意 shell 子进程可以直接拉取私有依赖。
- 已有流程强制依赖未确认配置时，先检查流程设计，优先改用能满足任务要求的已有授权路径；不以跳过必要验证或静默成功掩盖访问失败。确需新增认证时，说明具体执行环境、所需权限和现有授权无法覆盖的依据，再按实际授权处理；不能把实现自选的变量名升级为用户必须满足的长期要求。
- 普通命令失败先核实当前执行机、目标资源、操作与工具返回；区分沙箱限制、系统文件权限、认证失效、连接故障、平台明确拒绝及能力不支持，不从 `permission denied` 等字样直接推断用户未授权。已授权范围内检查当前任务实际可用且受支持的本机能力，自行使用诊断、环境修复及当前工具的原生审批或执行升级，验证同一目标操作后继续任务；能由模型操作本机完成的事项无需请用户代操作或逐项汇报。工具能力不支持时准确说明受影响能力，使用已有授权且适用的执行机或接口完成可分离步骤，不把能力限制转成重复授权请求。平台明确拒绝后停止该动作，不改安全设置、凭据或敏感 socket 权限来绕过，也不无限重试；新增范围、持续访问或安全设置变更只按实际授权处理。只有已获准的本机能力仍无法完成而确需用户介入，或平台强制逐次确认时，才说明最小具体阻碍。可选 CI 无法访问依赖，不代表整个任务无法完成；其他路径验证通过，也不代表该 CI 已通过。
- 根据实际凭据类型选择使用方式，不凭名称假定内容。只报告配置来源、可用性与必要的验证结果，凭据值留在原有配置渠道，不进入源码、文档、日志或同步内容。
- 对用户已委托或在授权任务中创建的本机资源，按需自主安装、配置、启动、修复、扩容和替换，不限 Docker、数据库或任何服务清单。既有授权持续有效；能通过当前获准的本机能力完成的维护由模型处理和验证，安装机制、工具合同与平台安全边界仍适用。
- 持久工具与服务跨任务保留；数据由模型按业务依赖、复现价值、重建成本、源端可获得性及本地独有修改判断价值。核心数据按用途决定保留、刷新或清理，普通运行数据用途结束后默认直接清理，具体执行 [生命周期策略](references/resource-lifecycle.md#数据价值与生命周期策略)。共享资源变更核对实际消费者；未知资源先辨识，不能因可访问就接管。
- 已有环境满足需要时直接使用，不增加工作站准备步骤。维护随任务需要执行，不自动建立巡检或每任务登记。
- 共享框架在环境准备时按 GitHub 发布版本完整安装；本机任务新建、恢复或清空时按 [框架同步方法](../york-codex-policy-maintenance/references/framework-sync.md) 检查发布版本，补齐缺少内容、兼容更新变化，再读取实际安装的规范，Skills 及引用按需使用。后续仅明确已发布的规范变更、当前任务完成长期规范发布或用户要求时刷新；两种入口均失败则保留最后有效版本、节点数据和未发布修改，标记待用户处理并提示一次，继续无依赖工作。任务间交互仅服务当前执行、配置核验或环境更新，不作为规范加载前置，也不建立实时同步或常驻协调。
- 长期规范或方法修订在所属 GitHub 项目检出中开发，按该项目授权发布后刷新部署副本；节点中的未发布修改保护并明确标识，归回所属项目，不维持独立规范分支。设备配置与发现线索留在节点说明，运行数据、历史记录和凭据不随框架入库。

## 按当前需要加载

- 多机分工、节点授权变化或局部访问受阻：[按依赖拆分多机任务](references/environment-sync.md#按依赖拆分多机任务)，区分任务附着、连接状态与执行权限，并核验产物交接。
- 项目配置中心、多环境选择、服务连接发现与本地保存：[环境发现与同步](references/environment-sync.md)。
- 新资源、共享服务、升级或清理：[资源生命周期](references/resource-lifecycle.md)。
- 工作站故障发现、来源新鲜度、操作后置状态与有界追溯：[异常与可溯源性](references/observability.md)。
- 本机服务的发现、启动、容量与故障处理：[本机服务入口](references/local-services.md)。
- 私有依赖、日志入口的网络要求或连接故障：[本机网络](references/local-network.md)。
- 业务数据选择、导入、同步恢复及上线 SQL 数据修正使用 [本地数据方法](../york-local-data/SKILL.md)。工作站负责本地分析、冲突处置和最终 SQL 验证，再将已确定的变更交付线上；不把这些工作转交线上环境或执行方。复用已有资源，Docker 为可选实现；数据库就绪不代表数据或业务断言通过。
