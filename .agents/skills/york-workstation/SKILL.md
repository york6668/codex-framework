# Codex 工作站

发现已有配置、工具与服务，优先复用；缺少能力时按任务需要补齐。工作站提供云端配置和本机资源的共同入口，当前任务维护目标、计划和进度。

- 工作站入口优先使用环境安装说明明确的位置；未指定时查看 `${CODEX_HOME:-$HOME/.codex}/workstation/README.md` 和 `$HOME/.codex/workstation/README.md`，也可从框架源码的 `.codex/workstation/README.md` 读取。平台运行时 `CODEX_HOME` 与框架安装位置可能不同，不能仅凭前者缺少文件认定规范未安装。入口已定位后沿用，其中的配置名称、来源、适用范围及本机线索以任务已取得的配置和实际连接核验可用性。
- 配置与认证默认先使用已有的 Codex 云端配置。云端配置或原生连接可用时直接复用；当前任务无法使用该入口时，再检查本机已有 Git/SSH、认证工具及配置。沿用实际配置名称和类型，不构造未配置的变量、别名或逐仓凭据要求。
- 已知云端有配置但当前任务无法取得时，核对环境是否请求已有配置键及是否已提供给任务。需要云端执行或核验时，使用当前可用的原生任务发现、读取接口，并按用户授权向对应任务发送请求和回读结果；只返回来源、可用性和操作结果。没有适用执行入口时说明访问缺口，不能仅凭本地缺少变量认定云端未配置。取得配置后认证失败属于访问验证问题，按实际错误处理，不冒充未配置或自动新建凭据。
- 根据实际凭据类型选择使用方式，不凭名称假定内容。只报告配置来源、可用性与必要的验证结果，凭据值留在原有配置渠道，不进入源码、文档、日志或同步内容。
- 对用户已委托或在授权任务中创建的本机资源，按需自主安装、配置、启动、修复、扩容和替换，不限 Docker、数据库或任何服务清单。既有授权持续有效；安装机制与工具合同仍适用。
- 持久资源任务结束后保留。共享资源变更核对实际消费者；未知资源先辨识，不能因可访问就接管。服务管理权与其中数据的处置范围分开判断。
- 已有环境满足需要时直接使用，不增加工作站准备步骤。维护随任务需要执行，不自动建立巡检或每任务登记。
- 共享框架在环境准备时完整安装；本机任务新建、恢复或清空时按 [框架同步方法](../york-codex-policy-maintenance/references/framework-sync.md) 检查版本，有变化再兼容应用。后续明确规范变更或用户要求时刷新；两种入口均失败则保留现用版本、标记待用户处理并提示一次，继续无依赖工作。读取实际安装的规范，Skills 及引用按需使用。任务间交互仅服务当前执行、配置核验或环境更新，不作为规范加载前置，也不建立实时同步或常驻协调。

## 按当前需要加载

- 新资源、共享服务、升级或清理：[资源生命周期](references/resource-lifecycle.md)。
- 现有 Docker / Compose / dbctl 的服务与容量操作：[本机服务入口](references/local-services.md)。
- 私有依赖、日志入口的网络要求或连接故障：[本机网络](references/local-network.md)。
- 业务数据选择、导入及同步恢复使用 [本地数据方法](../york-local-data/SKILL.md)；数据库就绪不代表数据或业务断言通过。
