# 原生用量异常与锁定

仅用于用户已要求保护、且节点明确配置的任务范围。比较今日与正常历史，不设置固定日额度，不把 token 换算为积分。真实账户百分比、积分余额是账户级观测；本地 response_id、缓存/未缓存输入、输出是代理指标，其他机器和云端未覆盖时不能声称账户硬上限。

`codex-framework usage-check` 从 stdin 接受 `{"policy":"<节点实际配置路径>"}`。政策包含 schema=`native-usage-guard-v1`、source_db、state_db、timezone（IANA）、roots（明确原生主线程 ID）、workload、reviewed_days；可用 day_classes 对特殊交易/工作日显式分组。真实路径、ID、历史证据和计量库留在节点。正常日条目为 date、workload、evidence；须先核其任务范围、完整覆盖和正常工作结果，不能自动把最近高耗日或未审阅日纳入基线。没有足够可比历史时保留锁定，不用假样本启动。

默认使用近60日内至少7个经审阅、同工作类型、同工作日/周末类别的历史日。对每个模型/推理等级，分别比较今日截至当前本地时刻的累计量、同一时刻前60分钟的增量；缓存已包含在输入，未缓存输入单独相减，不叠加计费。边界为 `1.5 × max(历史95分位数, 中位数 + 6 × 1.4826 × MAD)`，逐项返回样本、中心、离散度、阈值及触发项。这个保守经验阈值用于识别相对异常，不是概率保证；正常工作方式或模型变化应重新审阅可比基线，不用放大异常阈值掩盖故障。时区和特殊日按实际用户与工作安排配置，不能从机器时区猜测。

SQLite 中增量保存原生响应 ID、时间、模型与计数，不保存正文或凭据；来源只读，完整/失败/在途消耗都计入，末行写到一半时保留下次读。同一事务串行化读取游标、去重、比较和锁定。重复调用、并发进程、重启及跨午夜不会清除已锁状态；时钟倒退、缺源、未知模型计量、缺基线或配置变化都拒绝准入。存储自身不可用时无法保证落盘锁，但调用仍失败关闭，不能声称已持久化。

锁定后受保护入口不得开始新的业务准备、研究、续接或报告模型工作；已完成回执可以只读回收。原生工具可能已在入口运行前唤醒模型，本地程序也不能拦截宿主内部每次响应、终止已发出的请求或阻止未接入的其他端。因此这是**可观测准入边界的异常熔断**，不是实际账户每一 token/积分的硬制动。该限制必须随验收说明；不为绕过限制另建调度器、模型 API 或持续后台 worker。

解除只由用户明确要求后，通过同一命令提交 action=`release`、原 lock_id 和真实复核 evidence；重新采样必须正常，未补齐基线、计量仍未知或仍异常都不能解除。日期变化不自动解锁，解除用量锁也不恢复用户暂停的调度。历史锁与解除依据保留。安全恢复可先修复数据源或修订经证实的可比工作基线，再作人工解除；不支持静默忽略或按新任务名重开。

`action=history` 只提供近60日的观测日期、响应数与 `usage_fingerprint`，每项都标为 UNREVIEWED，不证明正常或完整。正常日条目还必须带该 fingerprint；后来补写、变化或缺失的历史不能静默改变已审基线。完整覆盖仍须依来源与工作实际核验，一条记录不证明完整一天。时区夏令时切换日与选中基线不可按同钟点直接比较时拒绝准入，不能静默把重复/缺失小时当可比。无有效正常日时保留缺基线锁，先寻找并核验已有正常材料，不为建立基线启动额外模型工作。

并发事务防止丢锁和重复计数，但日志落盘前可能已有多个请求同时在途；检查不是请求额度预留，也不承诺最大超额。实际根线程更换或工作方式变化须显式重审范围和基线；不自动挑选旧同名任务。计量库只保留数字与定位字段，真实节点路径、线程ID和正常日证据不得进入框架源码。

用量报告可独立生成，不再把一个已失踪的历史缺陷文件作为统计入口。原问题是否已修复仍由其原验收负责。运行端只读取本轮简短检测结果；历史全日志只在具体诊断时读取。父任务交付一个有界工作包，子任务返回一次实际结果；无新证据不等待、催办或互相轮询。
