# 本机服务操作入口

从工作站入口、项目需求、已有工具说明及服务运行状态定位实际资源。优先复用；缺少能力时由当前节点安装、配置或补齐实现。服务种类、版本、端口、容量与管理命令以本机配置和工具能力为准，旧路径或某个 `dbctl` 缺失不阻断任务，也不把一次安装的组件清单变成框架默认。

## 已有 Docker 与 Compose

先用 `command -v docker`、`docker context show` 和所选 context 的 endpoint 核对实际执行位置，再读取相关 Compose 项目标签、容器、端口和挂载。区分本机 daemon、远程 daemon、named volume 与宿主机业务目录；同名容器和端口不能证明属于本机授权范围。优先显式选择已核实的 context，避免改变其他任务使用的共享默认。

读取实际工具的 README、帮助和必要源码，确认当前操作支持的服务及副作用；不要将完整容器环境变量或认证配置输出到聊天。已有 `dbctl` 时可参考 [可选 dbctl 实现](../../york-local-data/references/dbctl-operations.md)，普通 Docker/Compose 或其他本机实现同样适用。

| 需要 | 执行与预期结果 |
|---|---|
| 状态、日志、容量 | 使用当前工具或原生命令读取相关服务状态、必要日志、主机与卷占用；已有运行报告只是历史快照。 |
| 启动服务 | 复用已有配置、数据与持久卷，必要时初始化本机服务并核对就绪和真实客户端功能；已经满足需求时不重复启动。 |
| 重启、停止或替换 | 核对共享消费者及命令实际影响范围。有的封装会重新启动其他服务，按当前实现选择局部操作。 |
| 工具自测 | 先辨明是否写入、恢复或清理本地夹具；不能把含写入的测试当成只读健康探测。 |
| 同步数据 | 从具体任务确定范围，按 [本地数据方法](../../york-local-data/SKILL.md) 执行；服务启动与数据同步分别触发。 |

节点已有客户端、虚拟环境和依赖可直接复用，不为统一路径或命令重复安装。环境准备与业务配置分工依据 [环境发现与同步](environment-sync.md)，应用最终连接也须指向已确认的目标。

## 容量与故障

启动失败从相关日志定位端口占用、兼容性、配置、卷或空间问题；辨识占用者，避免关闭无关进程。容量由实际主机、服务统计及节点有效策略判断，执行 [生命周期策略](resource-lifecycle.md#数据价值与生命周期策略)。同步工具的预算不一定限制业务应用直接写入；删除记录也不保证卷立即缩小。

重建容器不等于删除命名卷。恢复时保留必要核心数据和配置，失败只影响依赖它的操作；不能通过删规则、换目标或删除运行中的锁绕过真实容量与并发约束。完成修复后核对实际客户端及所需功能，容器健康、同步完成与业务验证分别判断。
