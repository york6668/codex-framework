# 本机服务操作入口

从工作站入口、项目需求、已有工具说明及服务运行状态定位实际资源。优先复用；缺少能力时由当前节点安装、配置或补齐实现。服务种类、版本、端口、容量与管理命令以本机配置和工具能力为准，旧路径或某个 `dbctl` 缺失不阻断任务，也不把一次安装的组件清单变成框架默认。

## 内部维护入口

先按[认证与操作能力](environment-sync.md#入口、认证与操作能力)区分工作站受管维护身份和外部业务/测试身份，以及现成认证复用、新凭据和权限变更。本机 MySQL 等内部资源不因 DataGrip 无本机连接就必须新建 GUI 数据源或让用户提供 root 密码；沿已知非敏感引用寻找当前允许的原生客户端、既有会话或不透明提供方。发现与登录分开，不读取秘密或重试失败认证。外部业务数据库仍遵守其入口限制；本机客户端不改变目标归属。

## 已有 Docker 与 Compose

先用 `command -v docker`、`docker context show` 和所选 context 的 endpoint 核对实际执行位置，再读取相关 Compose 项目标签、容器、端口和挂载。区分本机 daemon、远程 daemon、named volume 与宿主机业务目录；同名容器和端口不能证明属于本机授权范围。优先显式选择已核实的 context，避免改变其他任务使用的共享默认。

先按[资源角色与处置](resource-lifecycle.md#资源角色与处置)核对用途、重建契约、准确挂载及在途依赖；本地 MySQL、StarRocks 或持久卷不自动意味着生产重要数据。可重建模型资源按已授权的安全停旧重建或迁移核验，真实需要保留的数据/连续性另有具体依据。Compose 项目、网络和“开发”用途只帮助定位实际实例，不决定管理负责人或是否允许跨任务共享。按[资源生命周期](resource-lifecycle.md#发现与归属)先分清管理归属与消费者，再核对数据/权限隔离、容量及恢复；不同项目可复用同一服务实例，不能仅因标签拆分或仅因可连接就合并数据。

Docker 只读调用遇到 `docker.sock permission denied` 时，核实所选 context 的 endpoint、socket 所属机器及当前命令的执行沙箱；在已委托范围内使用当前工具正式支持的执行升级或正常环境修复，再以同一目标的只读调用验证。该报错本身不证明需要用户代跑命令，也不授权修改 socket 权限、Docker 安全设置或绕过平台明确拒绝。若正式途径被拒绝，仅停止受影响调用，继续不依赖它的工作。

读取实际工具的 README、帮助和必要源码，确认当前操作支持的服务及副作用；不要将完整容器环境变量或认证配置输出到聊天。同名命令不证明不同节点行为相同，工具专用参数和故障回归由其项目或本地入口维护，不在共享 Skill 保留第二份操作说明。

| 需要 | 执行与预期结果 |
|---|---|
| 状态、日志、容量 | 使用当前工具或原生命令读取相关服务状态、必要日志、主机与卷占用；已有运行报告只是历史快照。 |
| 启动服务 | 复用已有配置、数据与持久卷，必要时初始化本机服务并核对就绪和真实客户端功能；已经满足需求时不重复启动。 |
| 重启、停止或替换 | 核对共享消费者及命令实际影响范围。必要停机和停旧重建按角色执行；有的封装会重新启动其他服务，释放资源时选择不会附带启动负载的操作。 |
| 工具自测 | 先辨明是否写入、恢复或清理本地夹具；不能把含写入的测试当成只读健康探测。 |
| 同步数据 | 从具体任务确定范围，按 [本地数据方法](../../york-local-data/SKILL.md) 执行；服务启动与数据同步分别触发。 |

节点已有客户端、虚拟环境和依赖可直接复用，不为统一路径或命令重复安装。环境准备与业务配置分工依据 [环境发现与同步](environment-sync.md)，应用最终连接也须指向已确认的目标。

## 容量与故障

启动失败从相关日志定位端口占用、兼容性、配置、卷或空间问题；辨识占用者，避免关闭无关进程。容量由实际主机、服务统计及节点有效策略判断，执行 [生命周期策略](resource-lifecycle.md#数据价值与生命周期策略)。同步工具的预算不一定限制业务应用直接写入；删除记录也不保证卷立即缩小。

重建容器不等于删除命名卷，移除卷也不代表已处理 bind mount。可重建资源保留所需配置、来源和实际有用内容；需保留的状态才走相应数据恢复，平台删除确认仍适用。容量复测包含用户正常浏览器/IDE基线，临时关软件只算缓解。失败只影响依赖它的操作；不能通过删规则、换目标或删除运行中的锁绕过真实容量与并发约束。释放资源与启动、重建分别判断：已核实安全的停旧不等待新增负载的容量门槛，启动和重建仍核实际峰值。只等待受影响消费者的具体安全点，不因宿主 WARN 无限等全局稳定。完成对应动作后核对实际退出或客户端所需功能，容器健康、同步完成与业务验证分别判断；复用有效结果，只补测受变化影响的部分。
