# 项目环境发现与同步

核心框架定义发现、选择、保存、同步和核验的职责与预期结果；具体数据单元按节点能力实现。按当前任务需要进入相关环节，已有可靠结果直接复用，不把这份方法变成每次任务的固定检查流水。

## 识别项目与环境

从项目依赖、配置文件、启动参数、profile、环境覆盖和代码消费链识别配置中心、服务发现机制及实际数据来源。配置可能位于本机未跟踪文件或外部提供方；仅搜索 Git 已跟踪文件不足以证明不存在。只读取当前识别所需内容，凭据值不回显。

- 单一且无冲突的候选环境，在核对其配置来源及与当前任务目标的对应关系后可以继续执行；仅“只找到一个”不证明它就是目标环境。存在多个候选且当前任务尚未明确选择时列明来源和用途，由用户选择。默认 profile、文件名、地址可达或历史缓存不能替代用户在多环境下的选择。
- 当前任务已有明确选择时沿用，不反复询问。项目、配置覆盖或实际源环境发生实质变化，导致原选择不再适用时，重新确认受影响的选择；普通地址刷新不自动撤销有效选择。
- 配置中心及环境名称由项目识别，不预设某种产品、固定环境值或强制变量。无法识别时说明具体缺口，继续不依赖该信息的工作。

## 发现已发布的服务连接

使用当前可用配置或认证入口读取选定环境发布的配置及注册信息。“发布”指配置中心向获准客户端提供，不要求服务暴露在公网，也不将可访问视为其他环境的操作授权。

服务注册地址与数据库、缓存、消息服务等依赖配置分别检索；保留所属应用和配置来源，不将同名库或服务的不同地址随意合并。配置中心可能只提供首段连接：继续沿配置引用、主控接口或运行期下发链确认站点、租户及读写角色最终使用的数据源。项目声明、注册健康和实际客户端可用性分别核验，避免为验证权限启动会注册、初始化或写源库的业务应用。

Consul 场景按实际 prefix、context、profile 分隔符和 data key 读取 [KV API](https://developer.hashicorp.com/consul/api-docs/kv)，结合服务目录和 [Health API](https://developer.hashicorp.com/consul/api-docs/health) 查地址与状态。KV key 中的环境后缀不一定等于项目 profile，不能凭名称改写。ACL 过滤、未解析引用、不可达实例及动态加载缺口分别保留为未完成项，不把空结果当作完整清单。

## 入口、认证与操作能力

核对 OpenAI 产品能力时，先用 [官方依据与能力核验](../../york-engineering/references/openai-capability-basis.md) 的完整官方导航，再比较实际编排宿主、执行节点、安装版本及原生接口；示例、索引和其他产品的支持不能代签当前可用。权限 profile、连接状态、连接器授权及具体资源操作许可分别判断。研究范围扩大不授权迁移环境、引入费用/凭据或改变无关任务，资源身份及认证继续按以下分流。

分别识别资源的稳定身份、所属执行节点、访问入口、认证状态、具体操作权限与最近核验结果。浏览器登录态、标签页、签名下载地址和会话句柄是可失效的临时入口，不作为持久脚本或自动任务的唯一依赖。优先复用能完成目标操作的原生连接、受支持接口或 CLI 及其认证续期方式；这不意味着 CLI 或接口永不失效。

按下表形成当前动作的判断，不设每次必填表或另行审批。认证与账号身份不决定数据保留价值或生产连续性；维护方式先按[资源角色与处置](resource-lifecycle.md#资源角色与处置)核对用途、重建契约和依赖，再按本节判断授权与入口。资源归属与身份用途来自用户委托、创建事实及已核实配置；账号名（包括 `root`）、客户端位于本机或调用者自称已认证均不产生授权。操作按实际读写、目的地和持久影响判断，不能把“内部”当作一揽子放行条件。

| 事实组合 | 下一步与验收边界 |
|---|---|
| 已委托工作站资源、已有维护身份、现成获准认证路径，动作在原范围内且无平台硬拒绝 | 模型沿已有授权执行并核验所需结果，不重复申请身份用途许可或索取密码。优先复用已有且权限足够的较小身份，不自动选择 root，也不为此新建账号。只读元数据仍限制到所需对象和结果；高权限身份不使写入、停库或迁移获准。 |
| 外部业务或测试身份，或用途、归属尚未核实 | 沿该资源的现有环境、身份用途、只读及 DataGrip 等限制。先有界核对未知事实；本机维护权不扩张到业务行、他人身份或远端权限。内部与外部均需核实原授权，但不为已授权步骤重新索权。 |
| GUI 未声明本机连接、客户端未带认证、超时或普通命令错误 | 只证明该入口或调用不足；沿已知非敏感引用核对原生会话、客户端选项来源、login-path 或受管提供方的存在、目标绑定与允许使用方式。未检查、主动排除和不存在分别记录，不能据此宣布全局无凭据、强制 DataGrip 或要求用户输入密码。 |
| 普通认证失败（如 1045） | 保留确切入口、目标、错误与认证是否提交，不重试登录、不猜口令、不重置或换身份试探；仍可做不触发认证、明确允许的已有路径发现。发现另一入口不自动授权再次认证，按原失败与当前限制决定恢复条件。认证失败与平台硬拒绝分别判断。 |
| 新账号/GRANT、变更认证或口令、持久化凭据、开放端口/远程登录/自动续期 | 按实际新增的权限、目的地与持续访问核对原授权；未覆盖才提出具体新增项。普通临时会话及原提供方在原范围内的正常续期不等于这些变更，不能仅因写会话状态就新增索权；内部身份也不自动覆盖实际扩张。 |
| 秘密、平台确认或硬拒绝 | 使用提供方在原渠道内消费秘密，不读取或输出秘密正文。原任务禁止秘密读取时，只能使用其明确允许的既有不透明能力，不让 helper、脚本或另一线程代读；秘密复制、传输须另核目的地及授权。平台强制逐次确认交原生入口；明确拒绝停止同对象、目的地与副作用，不换工具、身份、线程或改信任记录绕过。 |

认证路径发现只读取允许的非敏感名称、用途、绑定及状态，不读取客户端选项正文、容器环境、凭据文件、保险库、密钥或进程环境来提取秘密；路径存在也不证明可用或权限足够。选择能完成目标且当前明确允许的最小能力，成功后分别核对目标身份、结果覆盖与权限可见性，空元数据不直接判空库。

确实缺少可自主使用的获准路径时，记录实际执行节点、目标和操作、已检查入口的非敏感结果、尚未检查项及原因、受阻步骤与继续条件。只有确认需本人原生认证或平台确认时，交给用户该最小步骤，不再申请整个工作站管理权，不把新凭据配置当成认证复用。其余获准工作继续；本机资源恢复、认证可用、规范测试通过分别验收。

一个浏览器未登录不证明其他认证通道失效；任务列表可读不证明环境可编辑或发布，空任务列表也不证明环境不存在。`.local` 等网络发现名依赖当前网络，解析失败不证明节点或业务服务停止。不同节点的同名绝对路径分别核验，不把另一节点的本地路径当成当前主机通道。

入口或命令失败时先核实执行机、对象、操作及实际错误。在已授权范围内检查当前任务可用且受支持的本机操作能力，必要时使用诊断、环境修复和当前工具的原生审批或执行升级，再验证原操作；命令接口失败本身不是平台拒绝或授权缺失，也不意味着须交由用户操作。入口失效时按已有配置发现适用替代通道，核对同一目标身份及所需操作；未知失败原因保持未知，不能因猜测未配置、服务停止或权限丢失就决定重配、迁移或替换。已核验的平台拒绝须停止该动作，不能通过替代通道绕过；接口不支持目标能力时按能力边界分工，不重复请求同一授权。仅暂停真正依赖该入口的操作，继续其余工作；不要把一次失败写成永久“等待用户补登录或地址”。已核验缺口保留执行位置、操作范围和时点，在实际使用、环境变化或原有计划核验时复查，不新增轮询或凭据要求。

故障回归场景按结果判断：Docker 只读命令在普通沙箱内报 socket 权限错误，应核实目标 daemon 与正式执行途径，获准执行后复验并继续；工具明确拒绝同一动作，应停止该动作且不改 socket 权限或换通道规避；已委托的工作站维护能由获准本机能力完成时，应自行处理和验证，不再询问同一许可；原生自动化接口若仅支持 local thread，应说明该接口的任务类型边界，按对象交给适用的已授权执行机，不解释成用户未授权；跨机任务以数据、能力和操作权限决定分工，不要求任一节点包办。这些文字可用于静态审查决定，实际缺陷仍须在修正后的采用版本上用原场景或安全隔离的等价场景复测。

## 按依赖拆分多机任务

所有设计与任务发起以适用核心框架支持的模型编排为基础，按职责、数据位置、实际能力、依赖和授权安排机器执行。机器仅提供数据与工具，不是独立决策或选择是否采用要求的主体；需求、业务规范、工程及结果责任留在原职责，编排负责要求送达、执行和效果。按当前任务适用条款核实落实，缺失则修正具体链路，不把所有机器升级整套规范作为默认步骤。职责层次只是说明，不强制管道或中央服务；当前只用Codex套餐内原生模型/任务及获准正常工具/CLI，不设计独立模型API、Key、计费、外部模型worker或fallback。

协调入口名称、助手所在云端和目标执行器是三件事。工具实际返回的执行节点可证明代码在哪里运行，不能证明内容仅留本机。结果文件即使只写本机，命令输出、摘录、截图、提示和跨聊天消息仍可能进入模型上下文。不能仅凭 `cloud_threads` 名称断言备份已上传，也不能凭“本机执行、没有 Git 推送”断言未发生内容传输。逐项核实节点、内容、目的地、授权及实际副作用；缺项保留未知。用户工作站与助手云端不共享工作空间或本地文件。

### 读取、模型上下文、交接与发布

| 动作 | 核对与最小输出 |
|---|---|
| 原节点本地读取/处理 | 沿已授权对象在原节点处理；不回显秘密或整份受保护正文。需要比较时先本地计算差额、计数或允许公开的字段。 |
| 工具输出进入模型上下文 | stdout、工具结果和截图分别视为内容披露；调用前限制字段、范围和长度。输出上限只是截断措施，不是内容授权。不能先打印全文再在回答中删去。 |
| 跨聊天交接 | 只传接收方任务所需且获准的身份、版本、状态、最小结论和原结果引用。路径不是读取许可；接收方仍核实际可达性及平台权限。受保护正文留原节点核验。 |
| Git/页面/其他公开发布 | 按目标仓库当前可见性和内容用途单独审查。读取或跨聊天许可不自动授权发布；公开源码不证明节点数据也可公开。 |

这些边界依据 [OpenAI 本地工作安全说明](https://learn.chatgpt.com/docs/enterprise/chatgpt-work-local-security)。权限由实际平台和工具执行，Markdown、JSON 自报字段和校验通过都不充当授权凭证。历史是否披露只能依据实际输出/发送原件核对；缺原件或来源截断保持 UNKNOWN，不用当前修复倒推历史安全。

验证输出链路时，在临时目录生成随机标记，分别放入允许输出与节点专用字段，通过正常入口核对前者可读、后者不出现在工具输出及交接投影；不用真实敏感正文作外传测试。此验证只覆盖受测读取和投影，不代签所有工具或历史处理。

- 本地 Docker、磁盘或内存不足先用已获准入口读取有界日志和运行证据，核实进程、数据结构、代码分配与查询、并发和资源生命周期；可在本机修正并复测的工作继续做。不能未经取证就迁真实备份、生产依赖、权限或负载至云端、公司节点或其他项目，也不能随意停止其他项目服务。合成 CI 只验证其代码和夹具，不足以关闭本机 OOM 或真实恢复事故；无日志异常也不能代替容量及退出事实。
- 若跨环境方案确有必要，先说明为何本地修复不足、将移动什么数据与权限、谁承担运行成本、目的地和已有授权是否覆盖。数据传输、扩大权限或新增费用不是本地维护授权的内部步骤；用户已明确某对象仅本地处理时维持其本地边界。不可恢复删除须在执行前明确对象、后果及针对该动作的确认。
- 平台明确拒绝针对其目标操作生效：停止相同对象、目的地与副作用，不能改通道、工具、线程、权限或直接在本机执行来绕过。若出现能改变原拒绝判断的新相关事实，只按原目标和原生入口复核一次；再拒即停。拒绝不撤销其他本地授权，也不阻止独立的日志核对、代码修正和隔离复测；原任务继续负责未闭环事项，报告具体阻断而不请求泛化授权。

- 在现有任务描述/结果中说明本端范围、必要输入、预期结果和原责任。工程项目自行保存源码版本、测试和原件；业务侧只保留相应需求、规范落实、实际效果/剩余问题及必要负责项目引用，不要求搬运工程记录。确需获准传递的工件才核相应版本与字节，不增加每步签名、台账或批准。
- attached、connected、接口支持与动作授权分别核实。机器在线、任务列表可读或账户相同不证明父聊天可跨设备执行、读会话或突破拒绝；原编排责任在对应环境安排获准工具并回收结果。普通能力错误在原范围有界核实，真实拒绝不能借 SSH、替代线程/通道或另一设备重试；未落实应定位该执行链路缺口，不归为机器选择拒绝业务要求。
- 动态选择限于适合该步骤且已授权的执行环境；它不改变已选业务环境，不授权迁移生产状态、调度或凭据。切换 attached 不会自动迁移既有任务、文件或业务；已有任务的执行位置和生产节点身份仍按实际任务及节点配置核实。本机有同仓代码或路径，不能证明它就是原生产节点。
- 某节点或入口不可用时，只暂停依赖其数据、状态或权限的步骤，继续其他已授权步骤。比如原生产节点无法执行时，已有充分输入的开发机可继续修复、隔离测试及获准的 Git 发布，正式采用和真实业务验收保留待办；不得复制生产状态来假装解除依赖，也不能把测试通过当作正式采用。
- 跨端先复用获准载体和既有内容，例如个人框架已发布 commit/tree；新增共享明确具体数据、目的仓库或 bucket/key、访问范围，并实证各端各自读取。仅共享允许的业务要求/结果或框架技术说明，不默认上传源码/tests/logs、公司索引、交易原件、机器配置/运行记录或凭据，个人资源不能成为拒绝资料的替代通道。文件/同名路径不自动共享，存在文件不证明目标端有触发/消费者；本端读取只证本次，另一端未验保持未接入，不凭字段或协议签跨端成功。
- 收到用户纠偏、授权或环境更新时，重新核实受影响步骤的节点身份、输入版本、所需能力与实际权限；保留仍有效的授权和成果，只调整受影响的分工。不能把旧失败永久化，也不能把新出现的在线状态当作授权恢复，不为复核新增轮询或要求用户重复提供已有信息。
- 已授权且能通过当前受支持的本机能力完成的事项由模型自行处理并验证，无需逐项向用户报告。先推进独立可做工作；已获准本机能力仍无法完成而确需用户操作，或平台强制逐次确认时，才说明受阻阶段、已完成部分及最小解除条件。若全部必要依赖均不可用，明确当前无可执行的剩余步骤及原因，保留成果等待所需条件，不笼统取消目标，也不以重试、无关工作或未验证结果假装进展。

## 保存与复用本地信息

沿节点已有工作站目录或实际工具配置保存足够复用的信息：项目与配置来源、选定环境及选择依据、服务用途与地址、发现或成功核验时间、有效期、核验范围和未解决缺口。保存格式由节点选择，复用已有文件，不要求新台账或完整配置中心镜像。

只保存必要的非敏感连接信息及凭据来源引用；URL 中的认证、密码、令牌和无关配置不进入发现清单、日志或框架仓库。节点为获准操作确需保存凭据时沿用原有受限配置渠道。框架发布只分发规范，不携带某台节点的实际选择、连接、数据或运行状态。

配置与连接缓存默认有效期为 24 小时，具体失效、覆盖和失败行为见 [生命周期策略](resource-lifecycle.md#数据价值与生命周期策略)。有效缓存能回答本次问题时直接复用；重新打开文件或连接成功不延长原配置的发现有效期。

## 按任务准备与验收

根据业务目标判断本机能力和数据是否足够；依赖、服务缺失时由节点按 [本机服务入口](local-services.md) 补齐，数据缺口按 [本地数据方法](../../york-local-data/SKILL.md) 选择对象和范围。服务启动不自动触发全量同步，旧工具缺失时由节点选择或补齐实现。

环境准备以所需依赖和真实客户端能力为依据；配置有效性以选定环境、来源、时效及实际消费链为依据；同步完成以选定对象、数量、结构、时间边界及必要样本为依据；业务验收以本次断言为依据。分别说明已完成、部分完成、截断和失败，不用其中一项成功替代其他结果。
