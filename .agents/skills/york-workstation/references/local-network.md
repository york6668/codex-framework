# 按当前环境核验本地网络

本参考用于实际依赖或日志入口的专用网络要求及网络故障，不是所有 Maven、Docker 或生产查询的固定前置。

## 执行连接与原任务恢复

设备联网、目标应用路径、执行通道、原会话和原操作结果是分别取证的事实。用户能联网聊天、节点绿点、连接异常、VPN 开关或旧任务状态，都不能互相代证；没有具体路径证据时只描述已观察到的执行通道或会话异常，不推断整机断网或 VPN 根因。用户要求容错时，不把确认 VPN 作为恢复及独立工作的前置。

| 观察层 | 最小核对与不能推定的结论 |
|---|---|
| 设备联网 | 当前设备的实际连通证据；不能推出特定进程、代理路径或执行通道可用。 |
| 应用路径 | 目标请求的代理、路由及错误；一个目标失败不表示整机或其他目标断网。 |
| 执行通道 | 当前受支持入口返回的连接身份、可用性及权限；在线不授予任务访问，显示名相同也不证明节点相同。 |
| 原会话 | 用原节点和任务身份核查原 session/operation；重连后旧句柄失效或查无会话，不证明原进程退出或效果未发生。 |
| 原操作 | 核原输入/版本、逻辑效果、提交与结果；回执丢失、超时及空列表保持 UNKNOWN，不当作失败或未执行。 |

在当前真实回合遇到连接错误，先保留原任务、操作/会话引用、输入版本、效果身份、错误时间及有效产物；这些运行事实留原记录，不进入共享源码。识别当前工具是否提供原连接恢复、重新取得句柄、原操作查询或终态结果读取，沿已授权且受支持的原入口有界恢复。重新取得读取通道不等于重新提交业务操作，不以改 VPN、代理、网络、安全设置或迁走真实数据作为默认修复。

恢复机会由当前回合、平台实际送达的重连/结果通知、原任务恢复或用户已有调度提供。原责任每次先核原状态、消费已到结果、重算实际依赖，再推进下一合法动作；同一回合可先完成独立工作，再按实际工具超时与退避约束复核一次。通知只是核收的触发，重复/迟到通知不重做已有效果，也不按数组顺序选成功。没有受支持的通知或后续执行机会时，准确报告缺哪个宿主能力和恢复条件；不得说“后台持续重连”，不得新建常驻轮询、第二调度或要求用户反复催促。需要新增调度时由原任务沿用户已有的调度授权单独处理，不能用文档或文件投影冒充注册成功。

- 提交前已明确终结且证明未执行：重新核当前能力、输入及授权，原任务才可按原逻辑效果再次执行。连接失败、找不到会话、队列暂未开始不是这一证明。
- 原进程仍运行：观察原操作；回执丢失但已完成：取原结果并按原义务核收；已失败：核部分效果和原因，沿原恢复政策修正后再决定。不能重复研究、下单、发送或写入来“试连接”。
- 仍为 UNKNOWN：继续原获准状态/效果读取，保留确切未知；只限制该效果及已证依赖，其他开发、诊断和允许离线验证继续。预算耗尽或原结果入口不可用时留有据等待，不将时间经过转成失败或清除在途状态。
- 节点在线但无任务访问、平台拒绝或用户停止：分别保留其真实边界。恢复连接、用户要求继续其他工作和一次新预检都不能解除它们；拒绝按任务方法的正式恢复规则处理。

原生执行连接与空闲唤醒由实际宿主持有；共享框架的 Hook、`check` 和交接库不实现它们。可选的[断线结果检查](../../york-task-alignment/references/execution-check.md#断线后的原操作核收)只约束已提供输入，实际调用方仍须接入并验证。合成断线、临时进程管道和云端回归分别报告其范围，不能代签原工作站自动重连、原任务恢复或部署采用。

## 识别真实目标

- 配置与认证先按 [工作站方法](../SKILL.md) 复用已有 Codex 云端配置或原生连接，当前入口不可用时再检查本机已有配置；从选定的 Maven settings/repository、日志入口或现有连接配置解析实际目标及网络要求。使用原有凭据提供方，不回显 URL 内认证、token 或敏感配置。
- 查询当前操作系统、网络工具和已配置服务；不把历史服务名、旧 utun 编号或上次检查结果当作当前事实。
- macOS 可用 `scutil --nc list` 找到相关既有 VPN，再以 `scutil --nc status "<实际服务名>"` 读取状态和动态 InterfaceName；服务名不是网卡名。
- WireGuard 等已有连接从当前设备的服务清单或网络管理工具发现；不同设备可能使用不同服务名，不能把旧记录的 Connected 或接口编号作为当前状态。所需既有连接的操作仍按下节处理，无需重新创建 VPN 配置。
- 需要确认目标流量经过专用隧道时，以当前动态接口、接口可用性及 `route -n get <当前目标地址>` 的结果核对。Connected 仅表示连接状态，不证明目标路由或应用访问成功。

## 处理与复核

- 当前授权允许所需网络连接且存在明确对应的已配置 VPN 时，可连接该服务并在合理超时内复核状态、路由及目标操作。不要自动创建或替换网络配置，也不切换无关 VPN。
- 实际 Maven 解析或日志查询是功能性证据；通常无需再建立固定 TCP/HTTP 探测流水。应用失败时区分 DNS、路由、认证、仓库响应和依赖问题。
- Codex 可在当前任务内复用近期结果；网络错误、休眠/恢复、接口或路由变化、执行位置变化及用户报告异常时重新核验，不以“检查过一次”阻止动态纠偏。
- 仅限制依赖故障网络的操作，继续本地可用工作。报告所需目标的最小标识、连接/路由结果、时间和实际请求结论；敏感地址无需完整回显。
- 不自动关闭或恢复用户 VPN；用户要求改变连接状态时遵循该请求。此流程不扩大 Git、配置或远程业务操作权限。
