# 本地调试数据

从本次业务断言选择数据；已有本地数据满足需要时直接使用。源端只读、本地导入和业务验证分别判断。

- 线上 MongoDB / StarRocks 数据复用使用 [DataGrip 只读查询与结果复制](../york-log-query/references/production-database-query.md)：仅通过 DataGrip 现有连接读取线上查询结果，可按任务需要复制到本地工作站或测试环境，包括写入相应目标表或集合。核对目标、覆盖范围及消费者；不把生产连接接入下方 dbctl 或其他直连脚本。dbctl 的现有测试源到本地同步能力不代表它支持向测试环境导入，复制目标按实际工具能力处理。
- 已有工具优先从当前设备工作站入口和业务仓库定位；`$HOME/docker/mi-local` 是可核验的发现线索，不要求各设备采用同一路径。数据依赖、同步范围、副作用、容量与恢复方式见 [dbctl 操作方法](references/dbctl-operations.md)。
- 连接名称不证明方向。核对源和本地目标身份，以及应用最终连接；涉及站点动态数据源时沿实际加载链追踪，不能只看示例 JDBC 或 YAML。
- 使用当前配置、凭据提供方或已认证会话；只读取所需字段，不回显凭据。源端仅查询或导出，不用业务请求、写后回滚或清理验证权限。
- 本地覆盖、重建和清理只处理当前授权对象；共享数据先核对消费者，其他任务数据原样保留。连接或范围不明只暂停对应写入。
- 核验所选对象的结构、实际数量、时间或快照边界、限制与必要样本，再验证目标行为。导入成功、容器健康和环境验收互不替代。

服务缺失、启动故障或需处理共享资源时，按需使用 [工作站](../york-workstation/SKILL.md)。普通日志、后台和线上数据库读取直接使用 [日志、后台与数据库查询](../york-log-query/SKILL.md)，无需走同步流程。
