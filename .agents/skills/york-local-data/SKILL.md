# 本地数据准备与 SQL 修正

从本次业务断言、已核实的数据关系和修正目标选择数据；已有本地数据满足需要时直接使用。疑似关联影响可以引导查证比较，不能预先决定修数方式或扩大同步范围；反复纠偏时按 [综合对齐](../york-task-alignment/SKILL.md#反复纠偏时扩大范围综合对齐) 重新检查完整需求与比较范围。实际处理路径及已有数据仍不足以判断时，按需复制所需记录和关联到本地隔离验证，再决定处理。核心框架定义范围选择、时效、保留、清理及恢复的预期，当前数据单元选择或补齐具体实现。源端只读、本地导入和业务验证分别判断。

遵守全局源码与数据边界：复制、同步、合成和脱敏得到的数据均保存在明确的本地数据位置或测试临时目录，不纳入 Git、源码导出或共享框架。仓库只维护数据准备程序、构造逻辑与契约。停止跟踪已有数据时保留仍需使用的本地副本，交付检查见 [提交内容](../york-safe-delivery/references/policy.md#提交内容)。

- 线上 MongoDB / StarRocks 数据复用使用 [DataGrip 只读查询与结果复制](../york-log-query/references/production-database-query.md)：仅通过 DataGrip 现有连接读取线上查询结果，可按任务需要复制到本地工作站或测试环境，包括写入相应目标表或集合。核对目标、覆盖范围及消费者；不把生产连接接入 dbctl 或其他直连脚本。读取与目标写入能力分别核对。
- 配置中心、候选环境与服务连接按 [环境发现与同步](../york-workstation/references/environment-sync.md) 识别并保存本地信息。多环境时沿用当前任务明确选择，尚未选择才请用户确认；不把默认 profile 或缓存当作选择依据。
- 已有工具从当前设备工作站入口和业务仓库定位；能力缺失时由节点按需求补齐，不要求固定路径或 `dbctl`。数据选择、副作用、容量、核验和恢复见 [按需同步方法](references/data-sync.md)；确有相应工具时才使用 [可选 dbctl 实现](references/dbctl-operations.md)。
- 国际化及其他上线 SQL 数据修正，按 [本地分析与最终 SQL 交付](references/data-sync.md#上线-sql-的本地分析与交付) 在本地完成记录及关联核对、冲突处置、目标值计算与验证。交付前确定实际变更，不能只验证分析脚本，再让线上数据库或执行方完成分析、筛选和组装。
- 连接名称不证明方向。核对源和本地目标身份，以及应用最终连接；涉及站点动态数据源时沿实际加载链追踪，不能只看示例 JDBC 或 YAML。
- 按[认证与操作能力](../york-workstation/references/environment-sync.md#入口、认证与操作能力)区分内部维护与外部业务/测试身份；使用当前允许的既有配置渠道、不透明凭据提供方或已认证会话，凭据由原渠道消费，不读取或输出秘密正文。缺连接先有界发现，失败认证不重试；新增认证配置、权限和持续访问按实际效果分别核对。只读取所需非敏感字段。数据库取样源端仅查询或导出，不用业务请求、写后回滚或清理验证其读取权限；已授权测试业务流程的预期副作用另按 [业务复测](../york-engineering/references/business-workflow.md) 判断，不将取样边界扩大为测试环境一律禁写。
- 本地覆盖、重建和清理按[资源角色与处置](../york-workstation/references/resource-lifecycle.md#资源角色与处置)处理当前授权对象。用户明确可重建的模型数据不默认走生产热接管；模型先核实最小重建来源、准确目标及在途依赖，再按原范围停旧重建或迁移。其他任务仍需的数据/状态按其真实用途及授权保护，不由共享标签推定永久保留全部实例。个人文件和外部业务源不继承本机重建许可；连接或范围不明只暂停对应写入。
- 数据价值、保留与清理由模型按 [生命周期策略](../york-workstation/references/resource-lifecycle.md#数据价值与生命周期策略) 判断：核心数据按用途和恢复能力处置，普通运行数据用途结束后默认清理。业务数据时效由本次需求决定，配置缓存默认 24 小时不能替代业务时间范围。
- 核验所选对象的结构、实际数量、时间或快照边界、限制与必要样本，再验证目标行为。导入成功、容器健康和环境验收互不替代。

服务缺失、启动故障或需处理共享资源时，按需使用 [工作站](../york-workstation/SKILL.md)。普通日志、后台和线上数据库读取直接使用 [日志、后台与数据库查询](../york-log-query/SKILL.md)，无需走同步流程。
