# 按任务准备与同步本地数据

框架规定应达到的结果，节点选择现有导出导入工具、客户端或适合当前对象的实现。旧工具缺失只说明需要补齐能力，不要求找回某套历史源码才能开始；工具的历史默认也不成为业务范围。

## 选择对象与确认实际连接

从业务断言和实际读写链确定源环境、站点或租户、库表或集合、关联对象以及时间或快照边界。已有本地结构与数据满足需要时直接复用；只补当前缺口，不预设全库、全站点、最近若干天或固定行数。范围不能由任务推导且会改变结果时只澄清该项，独立工作继续。

从 [环境发现](../../york-workstation/references/environment-sync.md) 取得已选择环境及有效连接。核对源端与本地目标身份不同，应用最终连接没有被 profile、环境覆盖或动态站点数据源引回源端。动态加载涉及主控或其他服务时继续查真实消费链，示例 JDBC 和 YAML 不足以证明最终目标。初始化、调度、消费者与回调同样可能产生写入，不通过启动业务请求验证源端只读性。

测试源仅查询或导出，生产来源沿 Skill 中已有的只读渠道。凭据使用已有提供方和必要引用，不复制到数据清单或日志。服务与依赖不足时使用 [工作站](../../york-workstation/SKILL.md) 准备，服务管理授权不自动扩展为其他数据的覆盖授权。

## 准备、执行与容量

- 明确哪些对象需要结构、基础或关联记录、完整窗口或可说明限制的样本。相关字段、类型、索引及约束影响验证时同步保留；样本不代表完整窗口或跨对象一致性。
- 导入前识别实际工具的替换、追加或更新行为及当前消费者；只处理已授权对象。仍有用途的核心数据与独有修改先保护，普通运行产物按生命周期处理；避免默认清空整个库、Redis DB 或共享卷。
- 由节点根据主机资源、已有数据、预计导入量、索引与恢复开销确定预算。空间不足先清理可丢弃运行数据，仍不足则保留明确缺口；需要改变所需覆盖范围时不能静默取样或截断。
- 导入按对象组织可重试的执行。数据库结构不兼容、关联缺失、缓存 TTL 语义或动态源尚未确认时，处理影响本次断言的差异；不能只凭客户端协议相同认定 MySQL 与分析库等存储行为相同。

生命周期及配置缓存有效期执行 [资源策略](../../york-workstation/references/resource-lifecycle.md#数据价值与生命周期策略)。数据新鲜度由业务时间目标决定，运行时间不等于数据截止时间；若源端会变化，说明取得数据的窗口或一致性限制。

## 核验与恢复

按本次选择核验结构、实际数量、必要样本、时间或快照边界、过滤与限制，再运行目标业务断言。完整、仅结构、抽样、截断、失败分别反映实际结果；源端前后变化与本地导入损坏分别判断，不承诺工具未提供的跨表或跨服务原子快照。

节点保存足够支持重用和恢复的实际结果：源环境、目标与选择范围、固定数据窗口、完成或失败对象、实际数量及限制。复用现有工具状态或本地说明，不要求统一 run-id、报告文件或台账。

失败时保留有效本地数据和必要恢复材料；仅对失败对象重试或续传，先查明结果未知的写入是否已经完成。续传保留原范围和窗口，源、范围或语义变化时重新安排受影响对象；不删除其他运行使用的锁或手改状态冒充成功。修复后复核相关对象，其他已验证对象无需全量重做。

用途结束后由模型复核价值：必要核心数据继续保留或按恢复能力处置；不再需要的临时导出、中间文件、运行日志及恢复产物默认清理。持久服务可以继续存在，不因清理数据自动卸载服务。
