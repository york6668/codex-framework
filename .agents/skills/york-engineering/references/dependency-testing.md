# 真实依赖、隔离与异步断言

## 选择组件

- 按需要证明的存储、事务、并发、消息、检索、文件或协议行为选择必要组件。实际匹配、SQL、约束或异步行为仍有决定性疑点时，在隔离环境验证该条件的真实路径，不能先按猜测修改生产处理再用匹配该猜测的夹具证明必要性。已有契约、源码或适用结果足够时无需追加容器或回放；复用已有测试、容器或夹具，Compose、Testcontainers、容器内工具等由当前环境和验证成本决定。
- 版本、运行时、Docker API、镜像平台与工具兼容性从当前仓库和运行结果取得，不将一次项目版本固化为全局默认。
- 需要准备或维护组件时使用 [工作站](../../york-workstation/SKILL.md) 的资源方法；已有组件可用时直接测试。配置实际指向远程时按远程边界处理。

## 选择业务回放时

需要用原始或构造输入验证业务路径时，可以采用回放；是否采用、输入规模和执行边界取决于待验证的问题及准备成本。

- 证明既有第三方行为时，优先复用对应接口和运行上下文的可用真实样本；修改边界先按 [既有对接取证](../../york-log-query/references/evidence-and-diagnosis.md#既有对接的修改边界) 确认。构造样本用于验证有明确依据的新增行为和边界，注明输入来源及所证结论；真实样本缺失不阻断独立测试或按协议验证新接入。
- 不把同一个自造成功或错误响应套到不同接口并据测试通过确认协议。分别保留各接口用于断言的结构和类型；仓库保存测试程序和可复用样本构造逻辑，样本在临时目录生成或从明确的本地位置读取。测试数据文件即使合成或脱敏也不纳入 Git 或源码导出，不将整份数据换名或编码后嵌入源码。测试数量不能代替样本代表性，本地通过不证明第三方具有该行为或已完成环境验收。
- 撤换无效样本或测试时，回读其对应的有效业务要求。可以修正错误断言或选择更小的执行入口，不能随实现减少验收；尚缺依据或未覆盖的要求按 [任务对齐](../../york-task-alignment/SKILL.md) 保留，不把剩余测试通过当作原目标完成。

- 按待证明的结论保留真实依赖，可以替换外部输入和范围外副作用；支撑结论的查询、转换或写入不能预设为成功。依赖的隔离方式也属于行为前提：例如生产中独立的 Mapper 工厂应分别加载，不能合并到同一工厂后声称验证了跨工厂可用性。局部替代说明所测范围，不要求每次执行整条业务链。
- 观察点选择能区分当前疑点的值、分支、数量或查询结果，避免观察代码修改业务输入或额外查询改变原执行条件。
- 验证异步持久化时，等待相关任务正常或异常完成，再回读实际目标数据库，核对记录、关键字段和必要数量。超时记为未证实完成，此时回读只是当时状态。提交任务、入口返回或固定等待时长不能代替完成证据。
- 批量边界、已有数据或重复处理与当前疑点有关时，再选择相应输入验证。诊断程序或夹具失败只修正影响所选结论的条件，并核验受影响结果；已通过的路径仅在新变化、失败或未决疑点需要时重跑。

## 执行断言

- 先确认测试应用连接本地目标，检查环境变量、配置回退、启动初始化、调度、消费者和回调是否可能写回源端；相关方法见 [本地数据方法](../../york-local-data/SKILL.md)。
- 服务就绪后执行目标业务断言，覆盖必要的成功、失败及状态变化；事务回滚、幂等或消息投递用实际数据状态验证，端口可达和健康检查不够。
- SQL 或存储语义变化应在隔离数据上执行受影响语句并核对查询/写入结果；编译、Mapper 加载或 SQL 字符串断言不能证明数据库执行行为。用户要求所有语句时逐条核验全部受影响语句。
- 本地夹具不依赖测试环境可用；确需源数据时使用本地数据方法。按需要重置或重建本地数据，保留复现输入、版本和必要诊断。
- 网络可用性以实际执行位置为准，宿主机成功不证明容器成功。私有依赖网络问题按 [本地网络核验](../../york-workstation/references/local-network.md) 定位，不扩展成所有镜像下载的 VPN 门禁。

## 结果

- 记录命令、内容版本、组件或镜像/平台身份、业务断言与实际数量，以及资源保留/清理情况；未使用镜像时不强填相关字段。
- 下载失败、不兼容、未就绪、超时或零测试执行只证明对应前置或路径失败。继续独立验证，容器退出码不代替测试计数。
- 本地结果只覆盖所测数据、版本和配置；测试环境部署与验收单独说明。
