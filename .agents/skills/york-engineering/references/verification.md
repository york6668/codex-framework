# 可证伪验证与结果边界

按当前待证明的行为选择下述方法，普通小修改无需全部执行。业务前端采集、动态值关联、测试对象准备与清理，使用 [业务复测方法](business-workflow.md)；实际请求、状态和领域预期缺失时，不能用 trace、mock 或进程成功替代。

先确定需求、受影响行为与真实风险所需证据，再选择覆盖充分的最小有效验证和本机工具。输入与预期从当前有效要求独立确定，不因旧用例存在或曾通过而沿用；已有结果只证明当时覆盖到的条件行为。同批修改按模块和影响范围合并编译及测试，共用准备与公共路径验证整批复用，各产品差异仍由相应断言覆盖，不为每个对象重复完整构建。已确认批次可以先验证，不必等待所有外部资料齐备；通过后仅因新变化、失败或具体未决问题扩大或重复验证。待验证假设可以决定需要区分什么问题，不能预先决定实现；说明追加测试或比较能补足哪项证据，已有证据充分时停止扩大验证。

测试预期涉及外部约定时，区分协议要求、项目契约和待验证假设；影响成功判定、分页或进度的断言须能回到相应依据。当前实现与自造样本通过不能单独证明协议保证，也不能证明所构造的触发条件实际成立或相应兼容改造必需。用户目标或已确认契约规定的新行为可以用构造样本验证，不要求线上已经发生；据此只报告条件行为。撤销错误假设时同步修正依赖它的实施决定和断言，保留仍有效的业务验收。需要补充依据时使用 [三方资料发现与读取](../../york-provider-docs/SKILL.md)，已有适用依据可直接使用。

OpenAI 相关预期按 [官方依据与能力核验](openai-capability-basis.md) 取得：示例不是产品白名单，其他产品/宿主支持不能代签，过期或无来源不签当前可用，需求修订不扩散无关任务。回归分别覆盖导航入口、现有程序的范围/时效/能力标签关系，以及按新方法作实际场景判断；只检查词句或链接可达不证明模型完成能力核验。`check` 不能从相同标签认证产品、宿主或官方来源，真实可用仍须原生入口和适用依据。

测试入口覆盖待证明的行为及实际错误路径。验证字段生产与消费衔接时，让真实生产者生成该字段，再经过受影响的转换和消费；手工填入目标值只能验证后续消费者，不能证明生产者已接入。预期使用有依据的独立值，不调用被测算法计算预期。修复可复现故障时，先确认所选断言能捕获原症状，再验证修复；补充已有正确行为的覆盖时，无需制造生产故障或扩大重构。

## 正式代码与测试隔离

测试可以调用正式实现，正式实现不得导入测试代码或依赖夹具、回放文件、本地验证器及测试专用配置。测试入口、断言、mock、固定时钟、模拟身份、故障注入和样本构造仅放在仓库外或明确忽略的临时位置，按项目构建方式临时接入测试作用域；不随源码提交，正式产物不打包或加载。合法的生产依赖注入保持正常默认行为，测试仅替换自己的实例，不能通过改写业务成功条件、持久字段含义或公共服务行为满足测试。

隔离同时核对依赖方向、编译及打包内容、运行时扫描和配置来源。目录命名、SQL 放置方式或单测通过不代表已经隔离；发现混用先停止受影响执行，在所属层移除测试专用能力，再以相同输入核对正式路径。不能把必需的生产幂等、事务或异常处理标成测试代码后删除；其必要性须有有效需求和实际调用链依据，验证范围覆盖其生产影响。

数据探索、组合调试和回归案例均属于临时验证材料；任务、框架、个人工具及合成输入不改变这一边界。测试可以使用正常授权的隔离业务副作用，不能把真实资金、权限或生产配置当夹具。

## 证据与验收依据

方案前可行性、实施自测和正式回归分别说明证据范围。用户要求修正后先确认新方案再回归时，开发自测可以验证修复，但正式通过标准由确认后的方案确定；按该方案固定输入、独立预期、实现版本及环境，输出通过、失败或未运行。确认前不得用旧 PASS、自测结果或页面演示签署新方案通过，也不将这项约定扩展为普通任务的统一审批。

测试案例验证的是给定输入、版本和条件下的观察，不能生成业务事实、协议保证或长期契约，也不能证明某字段、接口、兼容措施或旧流程必须存在。预期须有独立的有效需求或事实依据；旧断言与当前要求冲突时重新确定本次临时验证，不为旧案例补兼容、恢复已撤销的实现或降低业务要求。

测试案例及其程序、断言、mock、夹具和样本构造逻辑不纳入 Git 或源码包；不能按“长期价值”“保护核心行为”或“文件已跟踪”自行豁免。临时构建接入在提交前恢复，代码推送成功时删除本任务案例或确认其留在明确忽略的临时位置；原失败及验证结果留在原执行记录，不靠保留测试源码将其变成契约。已有受跟踪文件的实际清理按获准范围处理，忽略不等于停止跟踪；见 [提交内容](../../york-safe-delivery/references/policy.md#提交内容)。

对于代码缺陷，保留原失败输入、实际输出、预期依据和版本；在安全隔离条件下确认反馈能区分原症状，再修复并以原输入复验。无法重现时可先静态取证及进行有据修正，但明确未证实的因果和原场景缺口，不让复现困难阻断独立工作。需要真实 SQL、事务或异步完成语义时，按需读 [真实依赖断言](dependency-testing.md)；Java 执行入口另读 Java Skill。

行为、边界和升级风险决定验证面：接口变化经过实际序列化或调用边界；持久对象演进从旧对象进入新读写及恢复路径；组件变化走真实生产者到消费者的组合。外部副作用可隔离，但不能预设支撑结论的查询、转换或写入成功。普通局部改动不自动增加全链路或容器；但决定涉及现有数据时，必须先验证适用真实数据，不能用改动小、构造样本或单测通过豁免。只读记录核对、金额回放、真实事务/落库和资金结果分别支撑对应结论，不能相互替代。

回读实际执行内容、版本、通过/失败/跳过及零用例，编译、健康检查和退出码不替代断言。修后原场景未运行、失败、只证实缓解或结果未知时保留对应缺口。目标规模、并发和资源恢复只在受影响时验证；小样本不能冒充原规模。保留失败记录，不以重试成功、后续 not_run 或一般测试清除它。

多个有效在途成果须由原集成责任合入同一候选，再按实际交互和原失败路径作组合回归；各项独立通过不等于合并结果通过。原验证与候选字节相同且范围适用时复用证据，变动及组合风险定向复测，不重跑无关全量。职责与结果回收见[需求到交付](../../york-task-alignment/SKILL.md#实施回收和交付)。

实施自测、适用独验、组合回归、发布/安装和真实采用按当前范围分别判断，不要求每次规范修改包办全部阶段。规范一致性不代代码重构或模型执行；模型采用须有真实当前输入、方法选择、工具/效果及后继。核心正式独验按适用受检范围，普通任务不强制独立实例。版本和实际结果由原任务及执行环境承接，测试案例仍按临时文件处理；业务侧接对应需求效果和剩余问题，不以测试数、静态链接或推送证明需求满足。
## 故障定位与目标规模

已识别缺陷的受影响执行先停止，保留原失败、输入、版本与有效成果；先判明故障属于代码、数据关系、存储结构、访问算法、资源或瞬时服务的哪一层，依据实际业务规模和约束确定修复目标，再沿触发、生产者、读写路径及生命周期查明机制。症状保护与服务恢复可以先做并保留，但不自动消除原因；转存状态、增加资源、换入口或重试成功不能代替在问题所属层修复。跨层改动只沿已证依赖展开，不因“最大力度”调用更高模型或无限重构。数据问题按适用场景核对规模、扫描和查询复杂度、重复率、内存与 IO 增长、延迟、一致性及恢复，说明合理目标的业务依据，不编造统一阈值。根因未明时保留缺口，继续有依据的工作，不无期限扩查。无相关修复及隔离验证不得换模型、会话、节点或子任务重复尝试，尤其不得反复启动高等级模型。通用故障恢复按选定安装目录的 `model-defect-recovery.md`执行；项目专用调用政策仍归其已确认的权威来源，具体来源映射由工作站承载。预留不代替业务审阅或授权；不影响无关的正确工作。
