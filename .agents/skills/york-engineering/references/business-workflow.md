# 业务需求承接与项目复测

业务任务以有效需求和聊天共识为起点，按“共识 → 可行性验证 → 方案对齐 → 正式实现 → 实现验证 → 文档与交互交付”推进；设计、实现或纠偏的决定涉及现有数据时，先完成对应真实数据验证，再安排依赖该结论的下一步。任务需求、设计规范和任务文档贯穿全过程；已有确认及仍适用的证据按范围复用。明确的小修不因此重做完整方案。持续指这项已触发任务内的接续，不默认安装后台扫描、定时任务或额外模型循环。

## 从核心编排到本地项目

核心框架提供目标理解、接续、纠偏和协作等通用能力。业务系统持有需求、业务语义、规范/执行要求、验收方法、交付标准和实际效果，将适用核心能力转成业务要求，交本地项目并核落实。本地项目自行设计、实现、测试、修复和保存源码/工程原件，反馈对应需求完成情况与剩余问题。本方法提供可行性验证及工程复测方法，不替代业务系统或具体项目；执行遗漏不能一概归因于缺少规范，不建立强制三层平台、会话或台账。

- **业务规范**：业务侧先明确用户问题、对象与规则、实际流程、期望效果、当前满足程度和下一动作；承接最新纠正及适用的对象关联、异常自修和 UNKNOWN 防重要求。沿实际入口、存储及消费查证字段、身份、状态和接口含义；规则未决先核既有来源，不靠更多测试补造规则，当前实现不能缩减新需求。
- **执行要求**：业务实现从真实入口贯穿持久化、转换和有效消费者。验证职责准备适用真实数据及独立预期，必要的写入验证使用本测试的隔离副本；环境核对、授权内修正及失败复测由本地项目承接。证据缺口只限制依赖它的步骤，页面可打开或接口成功不替代业务正确。
- **交付标准**：以任务需求、业务规范、设计规范和实际效果判定满足及剩余问题，本地项目保存并按原仓规则交付可审核源码、测试及工程原件。需要页面效果时，从已实践的实现构建范围内交互和统一入口；正式前端开发、会员端页面及远端发布按有效需求确定，不从“页面交付”推导为默认义务。代码推送、tests PASS 或 completed 不代替业务结果。

公司业务源码、接口说明及有持续回归价值的测试源码由公司 GitLab 持有，本地检出用于实施与测试；不迁入核心框架或本方法。运行数据、回放材料、日志和实际配置保留在本地执行环境，凭据沿原渠道管理。获准公开交付只导出说明文档、页面运行资源和效果图；具体边界沿[交付方法](../../york-safe-delivery/references/policy.md#提交内容)，环境发现沿[工作站方法](../../york-workstation/SKILL.md)。

普通业务或环境问题先在所属项目修正并回归，项目保留事实和适用条件；验证有效且可复用的方法再反馈框架正文与入口。公司接口、存储配置、业务源码和测试数据不随方法复制，单次成功不构成通用保障。

## 共识、可行性与方案

先合并原始需求、有效共识和最新纠正，明确范围、规则、未决项及验收预期。已有页面、历史方案和当前代码用于查证现状，不能覆盖用户目标。被纠正的内容从活动方案、文档、页面入口及相关测试预期中退出，保留其原失败证据，不以聊天中回复“已理解”代替落实。

涉及现有数据的设计、实现、兼容、修数和恢复决定，必须先以获准环境的真实记录或适用本地副本验证，再进入依赖该结论的方案、修改或后续编排。该要求同时覆盖方案生成、实施中的新发现和纠偏，不因改动小或已有部分测试通过而省略。源码、表定义及契约帮助解释真实记录，不能单独证明实际数据分布、关联或运行结果。推测只用于提出待查问题；标注“可能”“待验证”不允许相关决定先行。

按本次决定核对环境与对象、实际结构和约束、记录关联及纳入/排除范围、数据规模与时间边界，再验证所需金额、状态、读写或恢复结果。已有证据在对象、版本、范围和时效仍适用时复用；发生相关变化则重验受影响部分。取不到数据、仅有构造样本或结果未知时保留缺口，继续取证及不依赖它的工作，不作有条件可行的实施承诺。源端只读；需要执行写入、事务、并发或故障注入时，复制必要真实记录到本测试隔离对象。本机受阻不隐含允许迁往其他节点。环境和数据方法见 [工作站](../../york-workstation/SKILL.md) 与 [本地数据](../../york-local-data/SKILL.md)。

可行性验证可以使用测试区的探索实现，但不得为其加入正式业务入口、模拟认证、硬编码账号或测试分支。新规则尚无历史数据时，真实记录与构造的规则参数分别标明；构造参数验证未来行为，不冒称线上配置。预期来自共识及独立计算或权威记录，不用被测算法自证。证据说明输入范围、实际运行结果及未覆盖部分；数据或环境不足时将受影响内容保留为待验证方案，不宣布可行。

方案外的推测只用于选择有界查证，不直接成为改动、执行依赖或前置条件。已经据此增加的安排先撤回，保留待验证问题；相关验证通过后只作为可选方案，仍按原目标、实际影响和授权决定是否纳入。该规则适用于全部系统与组件，不能只纠正用户举出的一个例子。

在共识和可行性结果上给出方案，交代表结构、接口、关键代码职责、失败恢复、页面要求及验收边界。算法回放通过只支撑计算模型，不能推导实际落库或资金链通过。用户要求先对齐方案时在该边界等待确认，其他已授权且不依赖确认的工作继续；不把此约定扩大为所有任务的审批前置。

## 正式实现与验证

正式代码只承载有生产需求及真实消费路径的行为。测试调用正式代码，正式代码不依赖测试代码、夹具、回放数据或本地验证器；测试依赖、测试配置和测试资源隔离在测试源码集及构建作用域，正式产物不能包含测试入口或模拟认证。依赖注入等可测试设计须保持正常运行契约，不为测试增加业务特判。目录分开、Mapper 改用 XML 或测试通过都不能单独证明隔离，具体见 [验证边界](verification.md#正式代码与测试隔离)。

涉及钱包、权限、调度、公共服务时，沿实际生产者与消费者核对每项改动的需求、作用范围及失败行为，再修改所属层。测试环境缺少依赖应在测试准备或适用替身中解决，不能通过改变正式成功条件、跳过校验或扩大公共接口来让测试通过。替身覆盖的边界单独说明，不能据其签署真实链路通过。

开发自测、正式回归、适用独立验收分别报告。用户要求“修正后提交新方案，确认后按新方案回归”时，可先完成修正和必要开发自测；新方案列明具体场景、独立预期、范围和未验项，确认后才据此判正式回归通过、失败或未运行。未确认的新方案、旧通过结果及不同版本的分项结果不代替这次回归依据。

## 先按实际能力设计

业务设计从有效需求、业务规则、现有契约和实际执行能力形成可达结果。只在确实依赖 OpenAI 产品/运行能力时按下段核官方和当前宿主，不能把官方资料核对变成所有业务需求或工程工作的前置。已核适用依据可复用；相关能力/接口改变时只查受影响范围。业务含义和预期来自用户及业务规范，不因官方没有某项业务细节而判其不能做。

涉及 OpenAI 的流程与环境，先按 [官方依据与能力核验](openai-capability-basis.md) 从完整官方文档体系定位适用能力，优先核对现成入口及其当前宿主、版本与授权。Agent 编排和 Agents API 是可选参考，不是流程设计的唯一模型或候选清单；SDK、app-server、exec/resume、ChatGPT 原生任务及其他相关产品按需要进入比较。原协调仍回收完整目标；文件或会话保存不证明空闲后有触发器、接收者或自动执行机会。官方存在、当前宿主支持和本次实际可用分别验证，不为采用说明擅自部署 API 应用、购买能力或新增调度。

沿用已经选择的测试环境与资源归属；配置缓存过期时自动刷新本次涉及的实际事实，不重新询问已有归属或管理授权。配置存在、profile 名称和摘要刷新不能证明最终租户数据源、服务、浏览器站点或测试身份可用。已有认证沿允许的不透明入口消费；缺入口负责有界发现，实际缺口只限制依赖它的动作，不能扩大成整个资源系统故障。

测试环境交付所需的配置核对、问题定位、授权范围内的修正和回归由模型承接；只将必须由用户完成的登录交还用户。收到登录完成后继续验证实际业务调用，不把账号归属、接口权限关联、缓存生效等可自行排查的工作改成交给用户处理。具体问题在所属业务或交易项目修正并回归，验证有效后更新其现有方法；不跨项目照搬配置，也不把一次测试结论提升为通用保障。遇到超出既有授权或平台强制确认的动作，只针对该具体动作处理，其他获准步骤继续。

浏览器 DOM、截图和点击不等于完整 HTTP 观察能力。[Playwright 网络接口](https://playwright.dev/docs/network)要求在动作前订阅或等待响应，并按本次实际请求与操作关联；只有当前执行器确实支持才能使用。当前工具子集未暴露的网络 API，不能用隐藏注入、CDP、私有浏览器/会话存储或换线程来补齐被拒能力。缺少相关能力可继续项目已有测试入口和隔离工程验证，真实业务端到端明确未运行。

## 采集、断言与对象生命周期

选定流程前明确当前任务、环境、租户或业务对象、源码与契约版本、允许的步骤及预期效果。测试环境正常订单或状态更新等预期副作用可以发生；不能把“真实业务流程”误解为实资生产交易，也不能预设所有测试必须零写入。源数据库取样的只读限制继续适用于取样入口，不扩展成禁止已授权测试前端行为。

复用项目测试入口，按需要提供动作前准备、一次执行、只读核对和清理能力。采集本次操作对应的必要请求/响应、前后业务状态、可见结果及版本，原始允许观察先于断言保存。按业务断言选择字段，认证头、Cookie、口令、令牌及不需要的身份信息在采集端排除，不先保存秘密再事后脱敏。白名单与已知模式检查不能证明任意字段值无秘密；只保存经任务和业务语义允许的最小投影，数据与失败材料留在节点，不进入 Git 或源码导出。

动态 ID、时间和随机值只按明确契约处理：记录值从哪次响应或状态提取、被哪一步使用，并核对对象关系。不能按邻近时间、同 URL、HTTP 200 或整体忽略动态字段来关联。预期独立于被测算法；金额、状态、数量、归属和因果关系的错误必须可证伪。共享物理引擎允许，业务和交易仍使用各自契约，交易历史快照不能接受业务任务。

初始化和清理只处理本测试明确拥有的对象，保留无关对象。准备部分失败、动作已生效但返回丢失、清理失败或取消后晚到结果，先从原操作与权威状态对账；不换 run、账号、线程或入口盲重放，不假定所有服务提供幂等键。取消不因晚到消息复活。恢复查询可以证明当前状态，不能补出遗失的网络原件或消除原失败。清理退出码 0 仍需实际后置状态。

## 修正、回放与交付

流程、源码或契约相关变化后保存旧失败与旧版本，复测原输入和受影响路径。区分产品错误、采集缺口、预期错误与环境故障，在其所属层修正；不能为了通过修改有效业务契约。较新证据只在相同内容与范围内承接，不能拼接不同版本的通过。结果未知先核对，局部阻塞不停止独立获准工作；真实拒绝继续保留。

[Mock/HAR 回放](https://playwright.dev/docs/mock)可以用录制响应代替服务调用，只证明该隔离范围，不能证明真实存储、效果或清理。历史证据回看也不等于新执行。源码单测、实际测试工具集成、真实测试站点端到端、发布安装与模型真实采用分别验收；截图、trace、进程成功或核心检查 ready 都不替代领域断言。

项目可用现有 `perform → Exchange → Oracle` 等接口交付最小适配器，不要求通用采集平台或固定记录表。处理者保留原输入、独立预期、实际失败与版本，自测后将确切成果交适用的独立验证；原协调核对主题、实际接收与结果，合并组合复测，并继续未完目标。缺失或截断原生记录保留具体缺口，不读取私有会话数据库补齐。未部署的空闲触发能力明确未运行，不能用 OPEN、owner 或承诺继续冒充接续。

需要辅助检查时使用[既有即时检查](../../york-task-alignment/references/execution-check.md)的可选业务工件适配。它检查提供的来源与选定字段关系，不发现遗漏任务、不认证调用者原件，也不判业务语义。模型与独立验证仍须沿实际生产者到消费者核实完整目标。

## 以实现为依据的文档与交互交付

本节按明确需求提供文档和交互效果，帮助团队依任务需求、设计规范和任务文档推进实施与验收。业务系统持有业务规范和用户结果；本地项目维护与共识及实现一致的文档、接口、页面、构建/测试及获准上传能力，节点保留实际配置和运行材料。核心提供通用方法，原任务回收完整目标及剩余义务，不把工程原件交业务管理。

顺序为业务共识与可行性依据、正式代码实践及验证、接口与持久事实、交互效果。现有页面可用于了解入口和操作习惯，不能以自造页面或浏览器计算模型确定后端业务规则。编辑、存储和展示模型可以不同，沿稳定业务标识核对同一对象；范围只包含有效需求中的页面和操作。正式前端仓库缺席不阻断后端和交付效果，也不授权重建完整前端。

交互优先接实际已验证接口；使用输出样例时，由当前正式代码经测试入口生成，并明确证明范围。前端仅负责输入、展示和交互，不复制一套资金、档位或状态转换算法。业务验证未完成的部分标明待验证，不能用页面保存成功、静态结果或演示领取冒充真实业务完成。测试驱动器与生成结果按源码和运行数据边界隔离，交付页面不能成为正式后端的依赖。

在上述明确需求范围内，交付包含三个相互衔接的结果：

1. **文档说明**：以任务需求、设计规范和任务文档为正文，说明已确认规则、范围、操作、字段与接口、异常以及验收依据。已有项目文档作为内容来源，构建浏览页时保留全文、目录、表格、代码块和章节链接；公开示例使用虚构身份，实际数据不得随页面导出。
2. **页面效果**：仅提供范围内的可操作效果，反映当前实现的输入、输出及异常；明确真实接口、实现生成样例及尚未验证的部分。效果确认不授权资金交易或修改范围外业务。用户明确排除的页面和操作从入口及实现移除。
3. **统一入口**：接收人只从一个入口就能找到完整说明及全部效果；文档相关章节链接对应效果，各效果页能返回说明及总入口。不得要求接收人额外索取仓库路径或本地文件才能理解交付。

按入口核对导航、全文、锚点、表格、代码示例及资源，再核对范围内操作与同一业务对象的接口和持久结果。要求后台与会员端贯通时才验收两端接续；截图、页面可打开和生成样例分别只证明对应展示范围。

远端发布仅在明确要求及授权下进行。完成本地效果确认后，以同一份页面构建上传到已确认目的地并远端复验；已有确认覆盖的内容复用，改变后的内容重新核对。未要求发布时交付本地可审核结果，不为统一入口追加发布或认证工作。

本地调试代理、模拟认证和数据回放各自只证明隔离范围。远端交付前检查页面入口、脚本、样式、图片、动态资源、刷新和跳转是否适配部署目录，并核对正式 API、HTTPS、跨域和正常登录的实际能力。静态存储不能运行本地代理，也不能继承其他网站的浏览器登录态；不把认证信息打包到页面，不用绕过认证或降低安全设置补齐联调。

从项目已有工具和配置来源选择最小上传方式，完整上传公开页面资源并保留相对路径；上传目录仅包含需要交付的内容。源码、任务产物和运行配置按[交付边界](../../york-safe-delivery/references/policy.md#提交内容)分别处理，环境与认证沿[工作站方法](../../york-workstation/SKILL.md)发现。存储供应商、桶、前缀及业务接口属于项目或本次任务，不能直接提升为框架统一默认。

上传方式、目标或资源类型尚未验证或发生相关变化时，先用有代表性的小页面验证上传和访问能力；已有适用证据直接复用。完整产物仍从远端入口复验资源及真实接口接续。本地确认与远端验证使用同一份页面构建；环境差异由明确的运行配置承载。用户负责发布后端时，未发布只限制相应远端业务步骤，其他获准工作继续。HTTP 成功、跨域预检或资源上传不证明认证和业务通过。
