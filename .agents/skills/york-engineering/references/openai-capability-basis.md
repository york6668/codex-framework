# OpenAI 官方依据与能力核验

OpenAI 的 Agent 工作流只是整体设计的一类参考。涉及其产品、模型、任务、工具、环境或运行机制时，从完整官方文档体系按需求导航，找到适用产品与版本的正文，再核对当前宿主及已授权入口。不能把先前讨论的示例、某个 API、SDK 或局部目录当成研究边界；也不要求逐页穷尽、照搬所有功能或为查资料另建平台。

## 从索引到本次设计

优先复用仍适用的已核依据与现成能力。需要补证时，从 [OpenAI 总导航](https://developers.openai.com/llms.txt)、[ChatGPT 与 Codex 索引](https://learn.chatgpt.com/docs/llms.txt) 和 [API 索引](https://developers.openai.com/api/llms.txt) 定位相关产品族、指南、参考、限制与更新，再读取影响决定的正文。索引、搜索摘要、示例和宣传介绍用于发现，不能单独证明当前接口合同或本机可用。官方目录结构变化时沿官方导航核对，不把这些起点固化为唯一来源域名或产品白名单。

按问题保留可扩展的覆盖说明：相关能力、产品/宿主、具体出处与版本、已读正文或仅定位索引、当前原生入口/安装版本及核验结果、授权/资格/费用/预览条件、尚缺事实与受影响决定。形式沿用当前任务资料，不要求新表单。说明本次覆盖和遗漏，不以“已读完整体系”替代相关性选择，也不把未读页面概括为没有能力。

下列仅为发现方向，可以按需求增加、合并或排除，不是准入清单：

- 模型与多模态、状态/会话/记忆、文件与检索、工具/连接器/MCP、交互和运行生命周期。
- Codex、ChatGPT 及其他官方产品的任务、环境、SDK、接口、自动化和协作入口。
- 认证与权限、安全、评测与观测、错误/恢复、部署、成本及限额。

例如持续任务应检查已有的 [Codex exec/resume](https://learn.chatgpt.com/docs/non-interactive-mode)、[Codex SDK](https://learn.chatgpt.com/docs/codex-sdk)、[app-server](https://learn.chatgpt.com/docs/app-server)、[Goals](https://learn.chatgpt.com/docs/long-running-work)、[dots 任务与记忆](https://learn.chatgpt.com/docs/dots/tasks-and-memory) 或[原生任务](https://learn.chatgpt.com/docs/automations)，而非先决定自建持久调度。它们是待核候选，不因被列出就证明已安装、支持当前任务或获得执行授权。Agent 编排、Agents API 以及后续出现的其他产品按同样方法选择，不高于或排除其他候选。

## 文档能力与当前可执行能力

将当前宿主已核可用、官方其他产品具有、预览/资格/授权依赖、需本机验证、已证不适用分别判断；这些维度可以同时存在，例如官方预览能力仍缺本机资格证据。先核复用条件再比较最小自建方案，不把当前工具未暴露解释为官方产品永远不支持，也不把官方存在解释为本宿主可调用。

- 比较实际产品、编排宿主、执行节点、版本、协议/返回结构、身份与访问范围，再验证所需操作。CLI、SDK、app-server、托管 API、ChatGPT Work Cloud、dots 和本地任务互不代签；同名方法、共享模型和本地执行位置不证明同一生命周期或返回合同。
- [Hooks](https://learn.chatgpt.com/docs/hooks) 分别说明本地工作流与云编排支持。不能把本地 command hook 套给带本机执行能力的 Work Cloud；相关云端能力有自己的管理与接入条件。也不能由某云宿主不支持就否定所有 Codex 本地 Hook。实际事件、连接、失败行为及安装采用仍需核验。
- [权限 profile](https://learn.chatgpt.com/docs/permissions) 不替代连接器、工具、云端或目标资源的授权。认证、原任务范围与平台拒绝继续按工作站方法处理；查文档不授权新增费用、凭据、持续访问、后台任务、平台或数据目的地。
- 区分文档规定、当前工具合同、已安装能力、启用条件、实际生效及目标验收。依据缺失、只读索引、已失效或过期、版本不明及原件截断时，不签“当前可用”；有已证相关变化时复核受影响依据。仍有效且适用的既有证据可复用，不增加统一文档 TTL 或每动作全站重查。

## 进入规划、回归和接续

把核实结果用于切片、环境选择、依赖及恢复设计，必要的执行 ID 查询、原状态读取和接续能力先验证受支持入口。文件持久化、会话恢复、回执绑定、调度触发、执行机会和领域效果分别验收；文档定义或接口名不能冒充这些机制已经运行。需求修订只重算受影响设计及依赖，不暂停、接管或改动无关任务；既有有效成果和未解除拒绝继续保留。

修正本方法时固定具体反例与独立预期，至少区分：示例外相关能力可继续发现；别产品/宿主能力不能代签；过期或无来源不能签可用；局部需求修订不扩散无关任务。使用正常入口的程序关系检查、实际原生样本与独立模型场景判断各证其范围。静态导航测试只验证入口可达，能力标签集合或 `check ready` 只比较提供的关系；都不证明模型完成官方导航、宿主能力真实、自动唤醒或持续执行。
