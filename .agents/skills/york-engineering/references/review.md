# 需求与实现两轴审查

固定本次比较内容及其版本，包含相关未提交与已整合的在途成果；期间内容变化时核对差异，并对受影响结论复查。固定比较点帮助复核，不要求为普通修改创建提交、整树签名或冻结审批。

从当前有效需求和实际差异确定审查范围，包含本任务相关的未提交内容；需求可以来自对话、已有契约或设计文档，不要求先创建 spec 或指定提交。上下文已能确定的范围直接使用，只有影响结论的歧义才询问。

- 需求角度：核对遗漏、部分实现、与要求不符的行为，以及缺少需求依据的额外改动；为复用、少改，或根据现有数据关系、结构和职责划分而缩减、重新解释需求、降低验收标准或阻断必要修改，均属于需求实现缺陷。验收依据保持为用户当前有效要求，不能跟随简化后的实现下调；纠偏后保留仍有效的累计目标。每项问题说明对应要求、触发条件与实际影响。
- 实现角度：用数据关系、职责归属及消费事实核对必要改动、兼容性和可验证性。仅在完整满足需求且保留所需含义、信息和行为的方案中比较复用程度和改动范围；必要的字段新增、结构及职责调整不能仅因既有边界或改动较多被否定，仍需排除无关重构。新增抽象应减少调用方必须了解的步骤、条件或重复逻辑；若移除一层只会减少转发，而不会把必要复杂度推回调用方，应重新判断该层的价值。层数、命名风格或代码气味只提供线索，不单独证明需要重构。

两个角度分别判断，测试通过不替代需求覆盖，满足需求也不证明兼容性。反馈按实际影响组织，区分可证实缺陷、待验证问题与设计建议。未核实推断可以引导查证比较，不能以风险提示的形式直接决定补丁、兼容或实施范围；标注为“可能”仍须遵守这一边界。反复纠偏时按 [综合对齐](../../york-task-alignment/SKILL.md#反复纠偏时扩大范围综合对齐) 扩大比较、重查需求覆盖，不能以现有 diff 或已知依赖限定审查范围。审查兼容、回退、校验及特殊处理时，核对其需求依据、实际触发条件与受影响行为；依据不成立则撤销依赖它的决定并修正相应实现与测试预期，保留有效需求。明确冲突说明依据、受影响行为及解决方案，按 [任务对齐](../../york-task-alignment/SKILL.md) 提示风险并推进，不把风险提示变成统一审批前置。不要求固定报告、独立代理或检查无关代码。涉及跨仓契约时按需使用 [跨仓契约变更](../../york-cross-repo-change/SKILL.md)，测试方法见 [通用验证](verification.md)。审查不增加 Git 交付授权，也不自动实施范围外的设计建议。
